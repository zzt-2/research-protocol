## 1. 端到端数据流推演

### 1.1 星座配置 → 节点位置

- **输入**：Walker Delta 参数（P=24 面, S=66 星/面, h=550km, i=53°）+ TLE 历元
- **处理**：SGP4 轨道传播 → ECI 坐标 → ECEF → 大地坐标 (lat, lon, alt)
- **输出**：位置矩阵 X ∈ R^{N×3}，N=1584；每步更新

| 参数 | 值 | 来源 |
|------|-----|------|
| P × S | 24 × 66 = 1584 星 | [L04: Starlink Phase I v2] |
| 轨道高度 h | 550 km | [L04/L07] |
| 轨道倾角 i | 53° | [L04/L07] |
| 轨道力学 | SGP4（TLE 输入） | [L01: Starlink TLE UTC 2025-07-16] |

### 1.2 节点位置 → 候选 ISL + 链路属性

- **输入**：X ∈ R^{N×3}，连接约束参数
- **处理**：
  1. 计算卫星对间距离 d_{ij}
  2. 地球遮挡判定（LoS 检查）
  3. FOR 角约束检查（θ ≤ 60°）
  4. 距离约束（d_{ij} ≤ z_max = 3000km）
  5. 对通过约束的对，计算 Gaussian beam SNR + Rayleigh jitter 中断概率
  6. 中断概率 P_out > ε = 10⁻³ 的链路标记为不可用
  7. 可用链路计算 Shannon 容量 R_{ij} = B · log₂(1 + SNR_{ij})
- **输出**：候选边集 E_cand = {(i,j) | 连接可行}，每条边含 {d_{ij}, R_{ij}, P_out_{ij}}

**候选边规模估计**：每颗卫星可见 ~15-20 颗邻居，总候选边 |E_cand| ≈ 12000-16000（无向）。

### 1.3 流量生成

- **输入**：地面网关位置（100 GS，GHS-POP 分布），卫星位置 X，活跃 ISL 拓扑
- **处理**：
  1. 100 个 GS 按 GHS-POP 人口密度分布（陆地区域 ~10× 海洋区域）
  2. 每个 GS 找当前可见卫星（仰角 > min_elevation）
  3. GS 对间流量需求 ∝ population_A × population_B（重力模型）
  4. GS→卫星映射：流量需求转嫁到卫星对
  5. 需求加 Poisson 随机扰动（非均匀 Poisson，陆地区域突发性强）
- **输出**：流量需求集 F = {(s_src, s_dst, demand_rate)}，|F| 动态变化

| 参数 | 值 | 来源 |
|------|-----|------|
| N_GS | 100 | [L01: 实验设置] |
| 分布 | GHS-POP（人口加权） | [L01: GHS-POP] |
| 流量模型 | 非均匀 Poisson | [L01: 实验设置] |

### 1.4 状态构造

- **输入**：E_cand 属性，流量需求 F，上一步拓扑状态（活跃 ISL、setup 中 ISL）
- **处理**：组装图结构状态 G_t = (V_feat, E_feat, Adj)
- **输出**：
  - **节点特征** V_feat ∈ R^{N×6}：

    | 维度 | 含义 | 范围 | 归一化 |
    |------|------|------|--------|
    | supply_rate | 发出流量需求 (Gbps) | [0, ~50] | 除以 max_supply → [0,1] |
    | demand_rate | 接收流量需求 (Gbps) | [0, ~50] | 除以 max_demand → [0,1] |
    | latitude | 纬度 (rad) | [-π/2, π/2] | / (π/2) → [-1,1] |
    | longitude | 经度 (rad) | [-π, π] | / π → [-1,1] |
    | n_active | 活跃 ISL 数 | {0,1,2} | / 2 → [0,1] |
    | n_in_setup | setup 中 ISL 数 | {0,1,2} | / 2 → [0,1] |

  - **边特征** E_feat ∈ R^{|E_cand|×7}：

    | 维度 | 含义 | 范围 | 归一化 |
    |------|------|------|--------|
    | capacity | 链路容量 (Gbps) | [0, ~100] | 除以 max_capacity → [0,1] |
    | distance | 星间距离 (km) | [0, 3000] | / 3000 → [0,1] |
    | is_active | 是否活跃 | {0,1} | — |
    | in_setup | 是否在 setup 中 | {0,1} | — |
    | setup_remaining | 剩余 setup 时间 (s) | [0, 30] | / 30 → [0,1] |
    | active_duration | 已持续活跃时间 (s) | [0, ~∞) | log(1+t)/log(1+T_max) → [0,1] |
    | outage_prob | 中断概率 | [0, 1] | — |

  - **邻接** Adj：二值稀疏矩阵 ∈ {0,1}^{N×N}（仅候选边）

### 1.5 模型输入

- **输入**：图状态 G_t
- **处理**：
  1. 节点嵌入 NEF：V_feat (R^6) → R^{64}，线性 + ReLU [L02]
  2. 边嵌入 EEF：E_feat (R^7) → R^{64}，线性 + ReLU [L02]
  3. GATv2 × L 消息传递：4-head, 64-dim, LeakyReLU [L02]
     - 注意力计算使用边嵌入作为偏置
     - 节点更新：h_i^{(l+1)} = AGG({α_{ij} W h_j | j ∈ N(i)})
  4. 边解码器 ROF：concat(h_i, h_j, e_{ij}) (R^{192}) → R^{64} → R^{64} → R^1 → sigmoid [L02]
- **输出**：边级分数 s_{ij} ∈ [0, 1]，每条候选边一个

| 参数 | 值 | 来源 |
|------|-----|------|
| GNN 架构 | GATv2 | [L02: §III-A.2] |
| 层数 L | 2 | [设计选择: L02 用 ≥2 层，平衡感受野与计算] |
| 注意力头数 | 4 | [L02: 4-head] |
| 隐层维度 | 64 | [L02: 64-dim] |
| 边解码器 | 3 层 MLP + sigmoid | [L02: ROF 64→64→64→1] |

### 1.6 模型输出 → 动作映射

- **输入**：边级分数 s_{ij} ∈ [0, 1]
- **处理**：
  1. 从 s_{ij} 采样 Bernoulli 动作 a_{ij} ∈ {0, 1}（训练时）
  2. 或取阈值 a_{ij} = 1{s_{ij} > 0.5}（推理时）
  3. **LCT 约束后处理**：每颗卫星最多 2 条活跃 ISL
     - 对每颗卫星，按 s_{ij} 降序排列候选边
     - 取 top-2 建立/保持，其余拆除
  4. **双向同意**：边 (i,j) 仅当两端均选择时才激活
     - 由于 GNN 共享参数且边分数对称，两端分数相同
     - 后处理在全局执行，天然满足双向同意
  5. **Setup 处理**：
     - 新激活边（上步 inactive → 本步 active）进入 setup 状态
     - Setup 时长从 Uniform(2, 30)s 采样 [L04]
     - Setup 完成前链路不可用于路由
     - Setup 中的链路后续步骤自动变为 active
  6. **拆除处理**：上步 active → 本步 inactive，立即失效
- **输出**：动作矩阵 A_t ∈ {0,1}^{|E_cand|}，满足 LCT 约束

**动作空间语义**（逐链路三态）：

| 当前状态 | 动作 0 (不激活) | 动作 1 (激活) |
|---------|---------------|-------------|
| inactive | 保持关闭 | **establish**（进入 setup） |
| in_setup | **teardown**（取消 setup） | 保持 setup |
| active | **teardown**（立即失效） | **maintain**（保持活跃） |

### 1.7 奖励计算

- **输入**：路由结果（各流量实际送达量）、ISL 状态转换、setup delay
- **处理**：

  **Step A：路由求解**
  1. 在活跃 ISL 拓扑上跑 Dijkstra（边权 = 传播延迟 d_{ij}/c + 节点延迟 1ms/hop）[L04]
  2. 对每条流量需求，找最短路径
  3. 链路过载时按比例缩减：若某 ISL 上总需求 > 容量，所有经过该 ISL 的流量等比缩减
  4. 迭代至无过载链路

  **Step B：奖励计算**

  r_t = w₁ · R_tput - w₂ · C_switch - w₃ · C_setup

  各项定义：

  | 项 | 公式 | 范围 | 含义 |
  |----|------|------|------|
  | R_tput | Σ q^{s,s'} / Σ d^{s,s'} | [0, 1] | 归一化吞吐量（已送达/总需求） |
  | C_switch | n_changed / max(n_active_prev, 1) | [0, 1] | 切换比率（状态变化的边数/上步活跃边数） |
  | C_setup | Σ d_setup_e / max(n_new · d_max, 1) | [0, 1] | 归一化 setup 成本 |

  其中：n_changed = 状态变化的候选边数，n_new = 本步新建链路数，d_setup_e = 每条新建链路的 setup 时长，d_max = 30s

- **输出**：标量奖励 r_t

#### 量级分析

| 权重 | 值 | 加权范围 | 占总范围比 |
|------|-----|---------|-----------|
| w₁ (throughput) | 1.0 | [0, 1.0] | 66.7% |
| w₂ (switch) | 0.3 | [0, 0.3] | 20.0% |
| w₃ (setup) | 0.2 | [0, 0.2] | 13.3% |

总奖励范围：**[-0.5, 1.0]**。无单一项 > 95% ✓

#### 策略区分度估计

| 策略 | R_tput | C_switch | C_setup | r_total |
|------|--------|----------|---------|---------|
| 最优 GNN（预估） | 0.85 | 0.05 | 0.02 | **0.83** |
| 贪心（永不切换） | 0.60 | 0.00 | 0.00 | **0.60** |
| 随机 | 0.40 | 0.30 | 0.15 | **0.28** |

最优 > 贪心 (+38%) > 随机 (+114%)，区分度充分 ✓

> **注意**：以上为预估值，MDP 试运行（Part A-checkpoint）将用实际仿真器验证。

### 1.8 评估指标

- **输入**：积累的路由/拓扑数据
- **处理**：

| 指标 | 定义 | 计算 | 来源 |
|------|------|------|------|
| M1: 吞吐量比 | Σq / Σd | 1.7 路由结果 | [L01, L09] |
| M2: 平均端到端延迟 | Σ(path_delay × q) / Σq | Dijkstra 路径延迟加权和 | [L03, L04] |
| M3: 链路切换率 | Σ_t n_changed(t) / (T × max(Σ n_active, 1)) | 全 episode 累计 | [L04, L07] |
| M4: 阻塞率 | 1 - Σq / Σd = 1 - M1 | 同 M1 | [L09] |
| M5: 公平性指数 | 1 - std(q_i/d_i) / mean(q_i/d_i) | 各流量交付比的变异系数 | [L09] |

- **输出**：{M1, M2, M3, M4, M5} per episode

## 4. 奖励函数设计

### 4.1 结构

r_t = w₁ · R_tput - w₂ · C_switch - w₃ · C_setup

- **R_tput（吞吐量收益）**：归一化已送达流量，主优化目标
- **C_switch（切换成本）**：惩罚频繁切换，激励拓扑稳定性
- **C_setup（建链成本）**：惩罚新建链路的 setup delay 机会成本

### 4.2 归一化策略

所有项归一化到 [0, 1]，通过权重控制相对重要性：

| 项 | 归一化方式 | 依据 |
|----|-----------|------|
| R_tput | Σq / Σd（交付比） | [L09: 奖励归一化思想] |
| C_switch | n_changed / n_active_prev（变化率） | [L07: 精英保留策略隐含稳定性激励] |
| C_setup | Σ d_setup / (n_new · 30s)（归一化 setup 总量） | [L04: setup delay 2~30s] |

### 4.3 权重选择

| 权重 | 值 | 理由 |
|------|-----|------|
| w₁ | 1.0 | 吞吐量是主指标，权重最高 |
| w₂ | 0.3 | 切换成本次之，防止频繁抖动 |
| w₃ | 0.2 | setup 成本最低但非零，建模建链代价 |

### 4.4 反模式检查

| 陷阱 | 本设计是否命中 | 说明 |
|------|--------------|------|
| 量级失衡 | ✗ | 三项均在 [0, 1]，最大加权贡献 1.0 / (1.0+0.3+0.2) = 66.7% < 95% |
| 自适应奖励振荡 | ✗ | 固定权重，不引入自适应机制 [L004 教训] |
| 遗漏奖励项 | ✗ | 对照 L09（负载优化）、L04（setup delay）、L07（稳定性）逐一确认 |
| DRL 退化为贪心 | 需 MDP 试运行验证 | 若 R_tput 独占 > 95%，需调整权重 |

### 4.5 与竞品奖励对比

| 论文 | 奖励结构 | 归一化 | 本项目差异 |
|------|---------|--------|-----------|
| L09 Wang TCOM | 局部负载减少 - β·1(ISL存在) | 负载 s_uv ∈ [0,1] | 本项目增加 setup 成本和切换惩罚 |

### 5.2 变化维度

| 维度 | 变化方式 | GNN 处理 |
|------|---------|---------|
| 节点数 N | 变化 | GATv2 天然支持变长输入 |
| 候选边数 | E_cand | 边级输出逐边独立 |
| 节点特征维度 | **固定** (6) | NEF 权重共享 |
| 边特征维度 | **固定** (7) | EEF 权重共享 |

### 5.3 B2 (FC) 的泛化局限

B2 的 FC 网络输入维度 Lin=810 [L09] 与星座规模绑定：
- OneWeb 720 → Lin=810
- Starlink 1584 → Lin 需重新计算（neighborhood 矩阵维度变化）
- FC 无法直接跨规模，需重新训练

这是 GNN 的结构性优势 [L02 跨规模实验验证]。

**CS 压缩适配**：
- 原始：s_i ∈ R^{(2a+1)×(2b+1)} → CS 投影 → s̃_i ∈ R^{Lin=810}
- 适配：根据 Starlink 24×66 的 orbital geometry 重新确定 a, b

#### 奖励函数

单卫星局部奖励 [L09 §III-A]：

r_i^t = 0.5 · [Σ_{j∈N(i)} Σ_{(u,v)∈P_{ij}} (s_{uv}^t - s_{uv}^{t+1}) · η - β · 𝟙(|N(i)| > 0)]

- η: 负载改善系数
- β: 动态 ISL 存在惩罚
- s_{uv}: 归一化链路负载 ∈ [0,1]

| 经验共享 | 全局共享经验池 | [L09 §IV-B] |

- 与核心方法相同路由模块（Dijkstra + 比例分配）

2-3 周（DQN + CS 压缩 + 奖励分解 + neighborhood 适配）。
