## 1. 章节叙事大纲 (A+B 框架)

### 1.1 Introduction 叙事线

**问题背景 (2段)**
- LEO 星座规模快速增长（Starlink 4000+, OneWeb 648→规划数千），路由成为瓶颈
- ISL 因轨道力学、硬件故障、天气等因素频繁中断（经验值 5-15%），静态路由（ECMP/SP）无法自适应

**问题定义 (1段)**
- 核心矛盾：路由决策需要在"全局负载感知"和"实时响应"之间取得平衡
  - 全局 TE（如 TELGEN）需要离线求解每个快照，无法应对突发故障
  - 分布式逐跳（如 GRLR）信息局部，无法避免拥塞热点
  - 域间路由（如 DTAR）粒度太粗，域内仍用 SP/ECMP

**研究空白 (1段)**
- 现有 GNN+LEO 路由工作的三个不足：
  1. 无故障弹性验证：多数在无故障/低故障场景测试，未系统验证 0-15% 故障率下的鲁棒性
  2. 无在线逐流决策：per-path 流量分割依赖预计算路径集，per-hop 逐跳无法做多路分流
  3. 无跨规模部署：每星座单独训练，无法零样本部署到不同规模

**本文贡献 (1段)**
- 三级贡献递进：
  1. **故障弹性路由**（主）：GNN per-flow K-path 框架在 0-15% 故障率和 5× 流量突发下全面优于 ECMP（GNN/ECMP=0.77-0.88）
  2. **在线逐流决策**（次）：每条流到达时独立路由，单次前向传播（1-2ms CPU），故障响应比 ECMP 重算快 7.7×
  3. **跨规模零样本部署**（辅）：66 星训练 → 48-720 星部署，GNN/ECMP ≤ 1.014，同架构 MLP 跨规模崩溃

### 1.2 System Model 叙事

**星座模型**
- 4-regular grid 拓扑（Walker delta F=0 连通模式），边权重归一化（4 ISL/星）
- 训练规模：P=6, S=11 (66 星)；泛化测试：48/288/720 星
- 选择理由：Walker delta 是最广泛使用的 LEO 星座拓扑（DTAR/GMR/PRIMAL 均使用）

**流量模型**
- 非均匀热点流量：25% 重型流 + 热点目的地
- 突发因子：surge_factor ∈ {1, 5}（默认 1.0，鲁棒性测试 5.0）
- 每 episode 40 条流，逐流顺序路由

**故障模型**
- 链路故障率 ∈ {0%, 5%, 8%, 10%, 15%}
- 每条链路独立以 p_fail 概率中断
- 故障在 episode 开始时确定，路由过程中固定

**问题形式化**
- 目标：min MLU = max_e (load_e / capacity_e)
- 约束：流完整性（每条流必须从源到目的），链路容量
- 决策：per-flow，从 K 条候选路径中选择一条

### 1.3 Method 叙事

**架构概览（1段 + 图）**
- GAT encoder（L=2 层，H=4 头，d=64）→ 全局链路/节点嵌入
- PathScoringHead：对每条流的 K=4 候选路径，用路径上边嵌入的均值做评分
- PPO 训练，Welford 奖励归一化，增量奖励 r = -(MLU_after - MLU_before)

**设计理由（2段）**
- 为什么 per-flow K-path 而非 per-edge weight：
  - K-path 天然保证路径可达性（候选路径由 BFS 预计算）
  - 离散选择比连续分割更稳定（避免 GMR 的 per-path splitting 不收敛问题）
  - 与 ECMP 的 K 候选路径范式一致，对比公平
- 为什么 GAT 而非 GCN/MPNN：
  - 注意力机制可学习故障链路的权重降低（GCN 等权聚合无法做到）
  - 边特征直接参与消息传递（故障状态、当前负载）
  - DTAR/GRLR 均验证 GAT 在 LEO 路由中优于 GCN

**在线决策流程（1段）**
- 每条流到达 → GNN 一次编码（跨流共享）→ PathScoringHead 独立评分 → 选最高分路径
- 关键：编码一次，评分 F 次（O(L·E·d²) + O(F·K·d)）
- 故障发生时无需重算路径集（候选路径由拓扑确定），只需重新编码

**跨规模泛化机制（1段）**
- GNN 参数与节点/边数无关（shared weights across all nodes/edges）
- 66 星训练的模型（28,546 参数）直接部署到 48-720 星
- Walker delta 族内约束：同 F=0, 4-regular 拓扑结构
- 不声称"结构泛化"（不同拓扑族需重新训练）

**实验设计（表）**

| 实验 | 目的 | 规模 | 条件 |
|------|------|------|------|
| E01 | 核心优势 | 66 | 8% fault, surge=1 |
| E02 | 无故障基线 | 66 | 0% fault |

**核心结果（E01，3 seeds × 800ep）**
- GNN/ECMP = 0.778 ± 0.012（改善 22.2%, p < 0.0001, Cohen's d = -0.86）
- GNN/MLP = 0.808（改善 19.2%）
- 关键：即使在无故障条件下（E02），GNN/ECMP = 0.845，GNN 仍赢

**故障弹性（E03 + E08）**
- surge=5× 突发下 GNN/ECMP = 0.767（改善 23.3%）
- 故障率 0-15% 全赢 ECMP：0%=0.845, 5%=0.855, 8%=0.797, 10%=0.881, 15%=0.837
- GNN 在中等故障率（8%）下优势最大

**跨规模泛化（E04-E06 + MLP 对照）**
- GNN/ECMP：48 节点=0.801, 288 节点=1.014, 720 节点=0.932
- MLP 跨规模崩溃：E04 MLP/ECMP=1.021, E05 MLP/ECMP=1.118
- GNN/MLP：48 节点=0.785, 288 节点=0.907, 720 节点=0.946
- 结论：message passing 是跨规模泛化的关键

**架构鲁棒性（E10-E11）**
- 层数 L∈{1,2,3}：GNN/ECMP 差异 < 3%（0.773-0.783，3 seeds）
- 头数 H∈{2,4,8}：差异 < 1.5%（0.771-0.782，3 seeds）
- 架构对超参不敏感，即插即用

**复杂度分析**
- 参数量：GNN 28,546（固定，不随规模变化），MLP 10,309
- 推理延迟：GNN 1.2-2.0ms（CPU），MLP 0.09-0.11ms
- 故障响应：GNN 比 ECMP 全路径重算快 7.7×（288 节点）
- 结论：在线部署可行

### 1.5 Conclusion 叙事

**三句话总结**
1. 提出 GNN per-flow K-path 路由框架，在 Walker delta LEO 星座中实现故障弹性、在线逐流、跨规模部署
2. 在 0-15% 故障率和 5× 突发下全面优于 ECMP（最高 23%），且无需重训练即可泛化至 10.9× 规模
3. GNN message passing 的全局聚合能力是故障弹性和跨规模泛化的关键，MLP 消融证实

**未来工作**
- 非 Walker delta 拓扑族的泛化（极地轨道等）
- 多目标路由（MLU + 时延 + 能耗）
- 分布式部署（去中心化 GNN 推理）

## 2. DTAR 讨论 (Related Work)

### 定位

DTAR (Zhou 2026, arXiv:2604.12382) 不作为 baseline 直接对比，而是在 Related Work 详细讨论粒度差异。理由：

1. **问题建模不同**：DTAR 解决域间路由（inter-domain），本研究解决全网逐流路由（intra-domain per-flow）。两者不在同一问题空间。
2. **粒度差异**：DTAR 的路由单元是"域"（18 域，288 星），域内仍用最短路径；本研究的路由单元是"流"，直接在全网层面做负载均衡。
3. **强行对比的风险**：DTAR 的域划分 + 域间路由是两阶段方案，直接对比路由阶段不公平（DTAR 的域划分已经做了负载均衡的粗粒度优化），对比整体又混淆了域划分和路由的贡献。

### Related Work 讨论文本

> **域间路由方法**。DTAR [Zhou 2026] 提出两阶段框架：离线 NSGA-II 域划分（双目标：最大化域间流量比、最小化负载偏差）+ 在线 GAT+PPO 域间路由。DTAR 验证了 GNN 在 LEO 域间路由中的有效性，但域内路由仍依赖最短路径，无法实现全网范围的负载均衡。本研究采用的逐流 K-path 路由直接在全网层面决策，避免了域划分引入的粒度损失，更适合链路故障频繁的场景——故障可能发生在任意链路上，域内链路故障无法被域间路由响应。
>
> DTAR 的 action masking（基于物理可达性和跳数约束）和 GAT+LayerNorm+Residual 架构是值得借鉴的设计。本文的 PathScoringHead 通过路径可达性预筛实现了类似的效果：只有 BFS 可达的路径才进入候选集。

### 对比维度表

| 维度 | DTAR | 本文 |
|------|------|------|
| 路由粒度 | 域间（18 域） | 全网逐流 |
| 域内路由 | 最短路径 | N/A（无域划分） |
| 故障处理 | action masking | BFS 候选路径 + GNN 编码 |
| 规模 | 288 星 | 48-720 星（泛化） |
| GNN 架构 | GAT (2L, 4H, d=64) | GAT (2L, 4H, d=64) |
| 训练方式 | PPO | PPO |
| 在线/离线 | 在线 | 在线 |

## 3. TELGEN 对比表

### 定位

TELGEN (Zhou 2025, IEEE/ACM ToN) 是最直接的竞品。不回避对比，但强调问题设置的差异而非方法优劣。

### 方法特性对比表

| 维度 | TELGEN [Zhou 2025] | 本文 |
|------|-------------------|------|
| **问题类型** | 流量工程 (TE) | 拥塞感知路由 |
| **决策粒度** | per-path 流量分割 | per-flow 路径选择 |
| **优化方式** | 离线监督学习 | 在线 DRL (PPO) |
| **训练标签** | IPM 最优解 | 增量 MLU 奖励 |
| **网络类型** | 通用（ER/Waxman/ASN） | LEO 星座（Walker delta） |
| **时变拓扑** | 静态快照 | 在线适应（故障+突发） |
| **泛化方式** | 跨拓扑族（ER→Waxman） | Walker delta 族内 |
| **泛化倍数** | 20× (100→2000 节点) | 10.9× (66→720 节点) |
| **泛化 gap** | < 3% optimality gap | GNN/ECMP ≤ 1.014 |
| **故障处理** | 无（静态快照） | 0-15% 链路故障 |
| **推理延迟** | 1.52ms (GPU) | 1.2-2.0ms (CPU) |
| **部署模式** | 集中式 SDN | 集中式（可分布式扩展） |
| **参数量** | ~500K (双循环 GCN) | 28,546 (GAT) |
| **训练时间** | 4h (A100) | 22min (RTX 4070) |

### Related Work 讨论文本

> **GNN 规模泛化**。TELGEN [Zhou 2025] 将 TE LP 问题转化为二部图上的 GNN 消息传递，实现了 20× 跨拓扑泛化（optimality gap < 3%），代表了 GNN 规模泛化在 TE 领域的 SOTA。然而，TELGEN 采用静态快照+离线监督学习的范式：(1) 每个拓扑快照需要预计算 IPM 最优解作为标签，在链路频繁故障的 LEO 场景中不现实；(2) 无在线适应能力，无法响应突发流量或实时故障；(3) per-path 流量分割依赖预定义路径集，路径集在拓扑变化时可能失效。本文采用在线 DRL 框架，每条流到达时独立路由，故障信息通过 GNN 边特征实时传播，无需离线预计算或重新训练。

### 差异化论证逻辑

```
TELGEN 的优势（不回避）：
├── 更大的泛化倍数（20× vs 10.9×）
├── 更低的泛化 gap（<3% vs ≤10%）
├── 更强的理论保证（对齐 IPM 迭代）
└── 跨拓扑族泛化（ER→Waxman）

本文的差异化（不 claims 方法更优）：
├── 在线 vs 离线：故障和突发时无需重算
├── 逐流 vs 全局：每条流独立路由，天然支持增量部署
├── 轻量 vs 重量：28K 参数 vs 500K，CPU 推理可行
└── LEO 特化 vs 通用：面向卫星场景设计，故障是核心考量

核心论证：不是"比 TELGEN 更好"，而是"解决 TELGEN 未覆盖的在线故障弹性场景"
```

## 4. Baseline 讨论文本

### ECMP

> **等价多路径路由 (ECMP)**。ECMP [Chiesa 2017] 是最广泛使用的负载均衡方法，在等价最短路径间均匀分配流量。ECMP 的优势在于简单和无状态，但其被动等分策略无法感知链路负载差异。当链路故障打破等价路径（例如原本 3 条等价路径变为 2 条），ECMP 不会将流量从拥塞路径转移到空闲路径，导致 MLU 升高。本文的实验表明，在 8% 故障率下 ECMP 的 MLU 比 GNN 高 22%（E01, GNN/ECMP=0.778）。

### MLP (消融对照)

> **MLP 消融对照**。为验证 GNN message passing 的贡献，设计了与 GNN 共享 PPO 训练框架但用 MLP 替代 GAT encoder 的对照。MLP 将全局特征（链路负载统计、故障率等）拼接为固定维度向量，无法感知拓扑结构。训练在 66 星（800ep），泛化测试在 48-720 星。结果表明：MLP 在训练规模与 GNN 差距较小（GNN/MLP=0.808），但跨规模泛化崩溃——在 48 星 MLP 不如 ECMP（MLP/ECMP=1.021），在 288 星差距更大（1.118）。这证实 GNN 的共享权重机制是跨规模泛化的关键。

### SP (Dijkstra)

> **最短路径 (SP)**。SP 选择跳数最少的单一路径，是最基本的路由方法。SP 在无故障场景下接近最优，但无负载均衡能力。在 66 星场景中 SP 的 MLU 比 ECMP 高 20%（SP MLU=2.37 vs ECMP MLU=1.97），证实多路径的必要性。
