## 操作

**必须读 content.md，不允许只读搜索元数据。**

### 步骤 0：源文件 title 自检（精读前强制，abort 协议）

> **背景**：下载流水线偶尔抓错页面（firecrawl 误抓 MDPI 导航页、PDF 转换抓到封面 banner），导致 metadata 标题与 content.md 实际内容完全无关（典型案例：DOI 10.3390/photonics10080914 metadata 说是"OPLL 卫星论文"，content.md 实际是"石墨烯纳米二聚体"）。对着一篇错配论文精读 = 浪费一轮 Worker + 产出污染 literature_notes。

打开 content.md，取第一个非导航 H1/H2 标题（跳过 `Journals`/`Information`/`Introduction`/`Abstract` 等 nav 词，方法见 `tools/litdownload/title_verify.py`），与派遣标题做词重叠比对：

- **重叠 ≥ 0.4**（去停用词后 token Jaccard）→ 继续 step 1，正常精读
- **重叠 < 0.4** → **ABORT，不产 L01 笔记**。回报：`[paper_id] TITLE-MISMATCH: 派遣《{派遣标题}》实际 content.md 是《{真标题}》(overlap={x.xx})`，记入 read-log，由 Master 决定补下载或换源
- **提取不到标题**（arxiv_latex 类 / content.md 损坏 / 极短）→ 标注 `title-unverifiable`，按派遣标题继续精读但需人工抽检 content.md 前 20 行确认主题一致

快捷判断：可先查 metadata.json 的 `title_check` 字段（下载流水线已自动算好）——若为 `mismatch` 直接 abort，无需 Worker 重算；若为 `unverifiable` 或字段缺失才走上面的手工提取。

对每篇已下载的论文，读其 `content.md` 的 method + experiment 部分（introduction 和 related work 可跳过，这些信息已从搜索元数据获得），按以下结构提取（模板见 `templates.md`）：

```
### [L01] {论文标题}
- DOI/来源：{实际 DOI / arXiv ID / "无 DOI（来源：{数据源名}）"}
- 源文件路径：papers/{type}/{id}/content.md **[MUST]**（type ∈ arxiv|doi|manual，{id} 取 papers/{type}/{id}/ 目录名字面值）
- **发表状态**：{正式发表 | 预印本 | 已录用待刊 | 未知}
- **发表渠道**：{**引用目标**，不是下载来源。正式发表的期刊/会议名 + 等级，如 "IEEE JSAC (SCI Q1)"。即使只下到 arXiv PDF，若已确认被 IEEE 接收，仍标 IEEE。仅无正式版本的纯预印本才填 "arXiv preprint"}
- 年份/会议：{年份 + 出版 venue}
- 核心贡献：{从 content.md 提取，≥2 句，包含方法层面细节}
- 方法概述：{从 method 部分提取，2-3 句}
- 实验设置：{从 experiment 部分提取的关键配置}
- 使用的 Baseline 方法：
  - {方法名}: {简述，标注论文内是自实现还是引用}
  - （如论文无对比实验，标注"无对比实验"）
- 关键结论：{从 result/conclusion 提取}
- 与本研究关系：{直接相关 / 方法可借鉴 / 对比 baseline 候选 / 仅供参考}
- 实现关键细节：{从 method 提取影响复现的工程细节：奖励归一化方式/具体数值、观测空间归一化、动作空间处理。[MUST] 包含具体数值，不允许"标准处理"}
- 开源代码：{有（链接）/ 无 / MATLAB / 仅伪代码}
- 验证状态：{已通过学术搜索工具验证}
```

### 预印本发表状态验证（[SHOULD]）

当精读论文标记为"预印本"时，应主动检查该论文是否已有正式发表版本：

1. 用 Semantic Scholar API（或 `tools/search --citations {arxiv_id}`）查询该论文当前状态
2. 若已有正式 DOI 或 venue → 更新"发表状态"为"正式发表"，更新"发表渠道"为正式 venue
3. 记录到 `decision_log.md`：`[AUTO] L{序号} 预印本已确认为 {venue} 正式发表`
4. 若仍为预印本 → 保持原状，在素材提取阶段（`paper-materials-workflow.md` Step 5）复查

### 结构化提取（[MUST]）

自由文本的"实现关键细节"不可跨对话复用。以下 7 个子表必须在精读时以结构化形式提取：

1. **状态空间**：维度名 | 范围/取值 | 归一化方法
2. **动作空间**：类型（离散/连续/混合）| 维度 | 合法动作约束
3. **奖励函数**：完整公式（内联 LaTeX，不允许散文描述）| 归一化方式 | 各项权重值
4. **建模假设**：假设内容 | 论文位置（章节/公式）| 对仿真器的影响
5. **网络架构**：层类型 | 维度 | 激活函数 | 归一化 | 优化器设置
6. **适配性分析**：在本研究问题场景下的适配点（1-2条）| 不适配点（1-2条）| 改进方向（1条，为自身方法设计提供依据）
7. **问题提取**（[MUST]，为问题清单产出供料）：该论文解决的研究问题，按 `stages/glossary.md` 定义拆成 M/C/A 三要素 | 问题是否过四判据（逐条标 ✅/❌ + 理由）| 论文的"失效假设 A"在哪（章节/公式定位）| 这个问题的方法产出形态是什么

> 为什么这样要求：精读时如果只留自由文本描述，跨对话恢复时仿真器构建者无法获得足够的 MDP 定义。奖励公式丢失归一化细节是最常见的返工原因。

> **为什么第 7 项是 MUST**：若精读完只产出"空白/局限清单"而不产出"问题清单"，下一步就会拿空白当问题直接进 MVE，反复撞物理天花板把方向做死。每篇精读必须明确回答"这论文到底解决了什么 M-C-A 矛盾、方法形态长什么样"，否则 GW Step 3 没有可进 Step 4a 的问题候选。

领域专属的额外提取要求见领域定制文件（通信领域见 `domain-comms.md`）。

### 写作架构提取（对 2-3 篇标杆论文执行，非全部论文）

**选文标准**：选择 2-3 篇与当前方向最接近、发表在目标期刊/会议上的论文。

> 本步骤关注"竞品怎么写"（结构、图表、叙述模式），与 `paper-materials-workflow.md` 的素材提取（"我要写什么"）不重复。在精读时顺便完成，不需要单独开一步。

#### A. 章节结构
- 各级标题列表（到三级）
- 核心章节的页数/段落分布
- 是否有独立的 System Model / Problem Formulation / Algorithm Design 章节

#### B. 关键参数展示方式
- 参数是用表格集中展示还是散落在正文中
- 参数符号定义的位置（单独的 Notation 节？脚注？行内？）
- 是否有参数敏感度分析

#### C. 图表模式
- 核心图表类型和数量（系统模型图、算法框图、架构图、实验曲线、对比表格）
- 图表的典型 caption 风格
- 是否有 3D 可视化/热力图/收敛曲线

#### D. 实验组织
- Baseline 选择和数量（3-5 个？是否包含传统方法？）
- 消融实验的组织方式
- 评价指标的选择和数量
- 是否有复杂度分析/收敛性分析

#### E. 叙述模式
- Introduction 的论证结构（背景 → 问题 → 空白 → 贡献）
- 贡献列表的条目数和粒度
- Related Work 的组织方式（按方法/按问题/按时间）
- 章首段写法（开门见山 / 回顾上章 / 导航预告）
- 章末段写法（收束结论 / 承上启下 / 空洞）

#### F. 经典段落摘录
- 摘录 2-3 段值得仿写的原文段落（Introduction 开头、过渡段、结论段优先）
- 每段标注仿写要点（如"用具体数字引入问题"、"从宏观到微观"、"对比结构"）
- 记录展开模式（演绎 / 归纳 / 对比 / 问题-解决）

#### G. 公式使用
- 变量引入格式：是否有"其中"定义段，是否注明物理意义/单位/取值范围
- 推导链条的叙事模式：公式之间是否有文字衔接（"将 X 代入 Y 得到"）还是连续堆叠
- 公式编号方式：连续编号 / 按章节编号 / 无编号
- 推导深度：完整推导 vs 仅给结果引用

#### H. 参考文献模式
- 各节引用密度（引言/方法/实验/结论，每节约几条）
- 引用整合方式：逐篇罗列 vs 归类整合；引述式 vs 括注式
- **竞品共同引用的基础文献**：列出多篇竞品论文共同引用但本 GW 未覆盖的文献 → 直接喂入 Step 3.5 定向补充检索

提取结果写入 `literature_notes.md` 的"写作架构参考"节（模板见 `templates.md`）。

### 实验完备性提取（对 3-5 篇核心竞品论文执行）

> 目的：从竞品论文中提取实验完备性维度，为 Contract 阶段的"实验对标检查"提供基线。
> 选文标准：在精读论文中选择 3-5 篇实验设计最完整的论文（非全部论文）。
> 与写作架构提取的区别：写作架构关注"怎么写"，本节关注"实验是否充分、声称是否有证据支撑"。
> 模板见 `templates.md` "实验完备性提取模板"。

[MUST] 逐篇提取以下维度（控制在 ≤20 行/篇）：

1. **声称清单 + scope**：intro/conclusion 中编号的 main claims，标注 bounded vs universal
2. **统计规范性**：seeds 数、error bar 类型、统计检验、运行次数
3. **Baseline 矩阵**：数量、类型、来源声明、公平调参声明
4. **消融设计**：对象（逐模块/整块/参数扫描）、方式（删除/替换/零化）
5. **通信特有维度**：信道模型类型+参数来源、拓扑多样性、复杂度报告
6. **VVUQ 三层评分**：Verification/Validation/Uncertainty 各 1-3 分

**对标汇总**（精读完成后撰写）：
- 将 3-5 篇论文的统计规范性、baseline 合规性、消融设计评分取平均，作为 Contract 阶段对标基准
- 识别领域实验惯例（如"多数论文用 3 seeds"）和盲点（如"无一篇做统计检验"）
- 汇总写入 `literature_notes.md` 的"实验完备性对标汇总"节

### 综合分析（精读完成后撰写）

1. **现有方法分类**：按技术路线分类，每类 2-3 句（包含具体方法名，不是泛泛而谈）
2. **已知局限**：现有方法的共同不足（从论文的 conclusion/future work 部分提取）
3. **2-3 年趋势**：该方向的发展趋势（从精读论文的发表年份和方法演进中推断）
4. **研究背景概述**：领域发展脉络（时间线形式）+ 核心技术挑战 + 本研究定位。多子问题时按子方向分别概述。此节直接支撑论文绪论 1.1 节。

> **注意"已知局限"是新颖性原料不是问题**：第 2 项"已知局限"按 `stages/glossary.md` 是空白（领域级），不能直接当研究起点。必须经第 5 项"问题清单"转译成 M-C-A 矛盾才算问题。
5. **研究问题清单**（[MUST]）：把每篇精读的"问题提取"（结构化提取第 7 项）汇总成跨论文的问题清单，逐条过 `stages/glossary.md` 四判据。这是 Contract Step 1 假设的唯一合法引用来源（每个假设引用一个 Q#）。未过四判据的条目标 ❌ 并说明缺哪条，不进 Contract。问题清单的表格格式见 `templates.md` literature_notes 模板"综合分析-研究问题清单"。

### 浅读流程（可选）

当候选论文数量超过精读范围时（如大论文场景），可将部分论文标记为"浅读"：

1. 标记标准：搜索结果中相关性为"建议读"且非核心方法的论文
2. 操作：从搜索结果的 abstract 和元数据中提取，不要求读 content.md
3. 产出：在 literature_notes.md 中使用浅读条目模板（见 templates.md）
4. 浅读论文不计入精读数量门槛（≥5 篇精读的门槛仅计算精读论文）

精读和浅读的关系：
- 精读（读 content.md）→ 用于核心对比、Baseline 选择、方法细节提取
- 浅读（读 abstract）→ 用于 Related Work 覆盖面、引用定位
- 不需要为小论文（<30 篇引用）启用浅读流程

## 质量门槛

- ≥5 篇论文完成精读提取
- **标题一致**：步骤 0 abort 的论文（title-mismatch）不计入 ≥5 篇下限，必须补派替代论文；abort 原因记入 read-log
- 每篇的"使用的 Baseline 方法"不为空（无对比实验的除外）
- 每篇的"核心贡献"≥2 句，不是搜索摘要的复制粘贴
- 综合分析各小节都有实质内容（方法分类/已知局限/趋势/背景）
- **研究问题清单非空** [MUST]：综合分析"研究问题清单"至少含 1 条过 `stages/glossary.md` 四判据的 Q#。一条都没有 = Step 3 未产出可进 Step 4a 的问题候选，禁止离开 Step 3（处置见 `stages/glossary.md`"候选全被筛掉时"；清单格式见 `templates.md` literature_notes 模板）
- **路径合规**：`literature_notes.md` 在 `projects/{name}/` 下，不在根目录
- **源文件路径** [MUST]：每条精读条目 `源文件路径` 不为空，格式 `papers/{type}/{id}/content.md`；精读产出全局 `papers/_read_notes/{paper_id}.md` 并在对应项目（或探索期专题）的 `read-log.md` 追加一条（字段：paper_id | 源文件路径 | 笔记路径 | 首读日期 | 重读次数 | 用于方向 | alt_ids(可选)）

## 不达标时

- 精读 <5 篇 → 回 gw-acquire.md 补下载
- Baseline 提取为空 → 检查是否漏读了 experiment 部分
- 综合分析泛泛而谈 → 用更多论文的具体内容支撑
- 结构化提取缺少完整公式 → 回论文对应章节重新提取，不允许用散文替代公式
