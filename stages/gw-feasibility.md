# 方向可行性预判（gw-feasibility）

> 在投入仿真器搭建和 baseline 复现前，验证研究方向是否可行。
> 核心原则：新颖性 ≠ 可行性。"没人做过"不等于"值得做"。
> 分两段执行：4a 在精读后评估方向根基 + 初步可行性（含 MVE），4b 在 Baseline 选定后评估仿真条件和资源风险。

## Step 4a：方向根基 + 初步可行性验证（精读后、Baseline 选定前）

> 维度 A0 是纯分析性预检，在 MVE 之前拦截"方法不匹配问题"的死胡同。
> 维度 A' 是竞争维度分解，确保创新声称建在 ML 有空间的维度上。
> 维度 A/B 依赖文献信息，维度 D 依赖快速实验。
> 执行顺序：A0 → A' → A/B → D。A0 不通过则直接 Kill 或 Pivot，不进 MVE。

### 维度 A0：问题-方法适配性预检

> 核心逻辑：MVE 只能验证"能不能跑通"，不能验证"应不应该用这个方法"。
> 过去踩坑的根本原因：在问题结构不需要 ML 的方向上做 MVE，MVE 通过了（因为总比随机好），但方向本身是死胡同。
> A0 在编码前、用纯分析手段回答"这个问题到底需不需要 ML"。

[MUST] 逐项回答，任何一项给出"不需要/没有"结论即触发致命信号：

1. **性能间隙**：当前最好的非 ML 方法离理论上界或实际需求差多少？
   - 差距 ≥ 15% → 有空间，继续
   - 差距 5-15% → 空间有限，需论证 ML 的额外成本是否值得
   - 差距 < 5% 或无理论差距 → **致命**：ML 无改进空间
   - 如果没有人算过上界 → 在 literature_notes 中用最简单的松弛/下界自行估计
   - [FR-02] 性能间隙数字必须标注来源类型：**[实证]**（直接消融/对比数据）/ **[外推]**（从 A 场景推断 B 场景，须列出外推假设）/ **[论证]**（结构性分析，须列出推导步骤）。无来源标注的数字不被接受。[外推] 类型不得作为 Go 的核心论据

2. **问题结构适配**：问题是否具有 ML 才擅长处理的特性（至少满足一项）？
   - 状态空间大，精确优化不可行
   - 环境动态复杂（时变、随机、非平稳）
   - 需要跨场景泛化（不能针对每个实例重新优化）
   - 决策具有延迟奖励/长期依赖
   - 以上都不满足 → **致命**：简单方法就够了

3. **跨域成功先例**：在相邻领域（不要求完全相同的问题），是否有 ≥ 2 篇论文用同类 ML 方法成功？
   - ≥ 2 篇成功先例 → 方法-问题匹配有经验支撑
   - 1 篇 → 弱支撑，需额外论证为什么你的情况不同
   - 0 篇 → **致命**：你是第一个吃螃蟹的，大概率方法不匹配
   - 注意：先例必须是"同类方法在结构相似问题上成功"，不是"随便一个 ML 方法在随便一个问题上成功"

4. **MDP 非平凡性**：写下 S/A/R/P 的具体定义，检查：
   - 最优策略是否平凡（如贪心就能解）→ **致命**
   - 状态空间是否太小（< 1000 个状态）→ 警告，ML 可能杀鸡用牛刀
   - 奖励信号是否稀疏到无法学习 → **致命**

5. **负面证据搜索**：主动搜索是否有人试过类似方法并失败？
   - 搜索关键词组合：方法名 + 问题领域 + "limitation/challenge/failure/unsuccessful"
   - 如果找到失败报告 → 必须解释本研究条件为什么不同，否则 → **致命**
   - 如果完全找不到 → 可能是真空白，但也可能是没人觉得值得试 → 需结合第 3 条判断

6. **先验覆盖检查** [FR-01]：是否存在非 ML 的简单规则/启发式在主要优化指标上已达理论最优的 ≥90%？
   - 列出目标问题的所有优化指标（主指标 + 次指标）
   - 对每个指标，检查文献中是否有简单方法达到 ≥90% 最优 → 标记为"已覆盖"
   - 如果无法判断 → 必须在 MVE 中加入该简单方法作为 baseline
   - 审查 ML 方法的创新声称是否建立在"已覆盖"指标上
   - 主指标被简单策略覆盖 ≥95%，且无明确的次指标维度可竞争 → **致命**
   - 主指标已覆盖但次指标未覆盖 → 不致命，但必须在维度 A' 中明确竞争维度

**致命信号**：6 项中有任何 1 项触发致命 → 方向根基有问题，不进 MVE。

**A0 与后续维度的关系**：
- A0 通过 → 继续维度 A'（竞争维度分解），再到维度 A
- A0 失败 → 直接 Kill 或 Pivot，不浪费 MVE 时间
- A0 是 A'/A/B/D 的前置门槛，不是替代

### 维度 A'：竞争维度分解 [FR-05]

> 多目标优化问题必须按指标维度分解后再做可行性论证，防止创新声称建在简单策略最强的维度上。

[MUST] 执行：

1. 将目标问题拆解为独立的优化维度（≥2 个，如连通性/延迟/拥塞/负载均衡）
2. 对每个维度评估：
   - 先验覆盖度：简单策略在该维度的表现（高/中/低）
   - ML 改善空间：文献证据显示的改善潜力（≥10% / 5-10% / <5%）
   - 方法增量：所提方法在该维度相对增强基线的预期优势
3. 创新声称只能建立在"先验覆盖度低 + ML 改善空间 ≥5%"的维度上
4. 输出"竞争维度矩阵"到 feasibility_report.md

**致命信号**：所有维度的先验覆盖度都高 → 联合 FR-01 判断，很可能 Kill。

### 维度 A：结构优势论证

[MUST] 回答：

1. 核心方法相比最简 baseline（非 DL，如贪心/启发式/传统优化）的结构性优势在哪？
2. 不是"特征不同所以需要复杂模型"，而是"在什么具体条件下，简单方法会导致信息损失？损失多少？"
3. 引用 `literature_notes.md` 中的具体论文证据支撑
4. [FR-03] 对比对象必须是竞品方法的增强版本（+该领域已发表的合理特征工程），而非裸方法。如果增强后差距 <5%，结构优势声称不成立，需重新定位（如"自动学习 vs 手工设计特征"而非"能做到做不到"）
5. [FR-08] 方法论选择（如 GNN+RL）必须与该领域 top-3 成功论文的学习范式做对齐检查。偏离范式须显式论证：(a) 为什么需要偏离？(b) 偏离后为什么仍可行？无法回答 → 默认跟随成功论文范式

**致命信号**：答不出结构性优势，只有"用 DL 替代传统方法"而没有解释为什么 DL 适合这个问题。增强基线对比后差距消失且未重新定位。偏离成功论文范式但无论证。

### 维度 B：新颖性-可行性解耦

[MUST] 区分并分别论证：

1. **新颖性**：没人做过（`literature_notes.md` 已确认）— 这是事实判断，已有
2. **可行性**：做了会更好 — 这是预测，需要独立论据
3. **空白原因**：为什么前人没做？
   - 没人想到 → 可行性较高，但需确认不是"想到后发现不好"
   - 试过效果不好 → 需解释本研究条件为什么不同
   - 技术限制刚解除 → 论据较强
4. **空白零假设检查** [MUST]：列出至少 3 个空白存在的结构性/技术性原因（不只是"没人想到"），逐一反驳。如果 ≥1 个原因暗示方法在结构上可能不适用（如"约束被环境吸收使模型冗余"、"简单方法已是强吸引子"），升级为致命信号。
   - 先例：nfv-sfc-vne 发现 GNN×VNE×SFC=0 篇，实际原因是 SFC 约束被 action masking 吸收，模型级 SFC encoding 是冗余信息

**致命信号**：仅靠"没人做过"论证，无法回答"为什么做了会更好"。

### 维度 D：最小可行实验（MVE）

> "没人做过"不等于"能做"。维度 B 的可行性是文献层面的预测；维度 D 是实证验证。MVE 在 Baseline 选定前执行，避免在不可行方向上浪费复现资源。

[MUST] 设计并执行最小可行实验：

1. **假设**：一句话描述 MVE 要验证的核心假设
2. **最小实例**：能测试该假设的最小问题规模
3. **[FR-04] 实例保真度检查**：简化实例必须保留与核心假设相关的结构属性。如果简化移除了使所提方法具备优势的结构特征（如轨道面结构、图拓扑属性、时序依赖等），验证结论不可外推，必须更换实例
4. **pass/fail 标准**：预定义什么结果算通过
5. **时间预算**：≤1 天（可用临时脚本，不需正式仿真环境）
6. **执行方式**：在子 agent 中执行（见 CLAUDE.md "上下文管理规则"），主对话只接收结果数字和分析
7. **[FR-11] MVE 架构摘要**：MVE 结果必须包含以下架构信息，作为 feasibility_report.md §D 的一部分。缺少架构摘要 → Step 4a 不算完成。
8. **[FR-14] MVE 先验对照要求**：MVE 必须包含至少一个简单确定性先验 baseline（如 Fixed/Heuristic/Greedy），pass 标准必须包含 "DRL > 最强简单先验" 的条件。仅 "DRL >> Random" 不充分——Random 在很多场景下本身就是稻草人（先验策略可能已经 3-10× Random）。MVE 结果中必须记录：先验 baseline 名称、先验得分、DRL 得分、DRL/先验 比值。
9. **[FR-15] MVE 贡献目标基线对照**：MVE 必须包含 Contract 假设中指定的具体 baseline（贡献声称要超越的对手）作为比较对象。pass 标准必须包含"提出方法 > 目标 baseline"。如果目标 baseline 在 MVE 阶段未实现，需用最接近的可用 baseline 近似并记录差距。仅通过 "方法 > 弱 baseline" 不等于验证了贡献声称。
   - 先例：nfv-sfc-vne 的 MVE 测试了 GNN>MLP（弱对比），但贡献声称是 MatchingGAT>DualGAT+（强对比），Execute 阶段才发现声称未经验证

```markdown
### MVE 架构摘要
- 动作空间: {离散K-path / 连续per-edge / 连续per-node / 离散选择 / ...}
- 决策粒度: {per-flow / per-link / per-node / 全局}
- 对比范式: {模型如何与baseline对比，如"逐流K选1 vs baseline round-robin" / "全局权重 vs ECMP多路径分流" / ...}
- 奖励语义: {增量delta / 绝对值 / episode-level}
- 先验对照: {最强简单先验名称 + 得分 + DRL得分 + DRL/先验比值}

> 起源：leo-congestion-routing 项目中，MVE 用 K-path 离散选择 beat ECMP 12%，但正式设计改用 per-edge 连续权重（单路径路由），表达力低于 ECMP 多路径分流。MVE 结果被直接用于支持 Contract 假设，但 MVE 验证的架构和正式架构完全不同。根因是 MVE 只记录了 ratio，不记录架构，后续阶段无法追溯证据的有效条件。

**降级条件**：如果文献中已有强有力的证据（如同场景同类方法直接对比），可跳过 MVE，在报告中记录跳过理由。

**不可降级的情况**：
- "组合新颖性"方向（A 方法首次用于 B 场景）不应跳过 MVE
- 维度 B 的空白原因为"没人想到"或"技术限制刚解除"时，不应跳过 MVE——因为没有前人实验可参考

**致命信号**：MVE 显示核心方法在最简条件下无结构性优势。

### 4a 决策

| 决策 | 条件 | 后续 |
|------|------|------|
| **Go** | A0 通过 + A'/A/B 无致命信号 + MVE 通过 | 进入 Step 5（Baseline 选定） |
| **Conditional Go** | A0 通过 + A'/A/B 无致命 + MVE 部分通过（有退化但有解释和改善路径） | 记录风险，进入 Step 5，在 4b 中验证改善路径 |
| **Pivot** | A0 致命或 A'/A/B 致命或 MVE 失败，但有明确调整方向 | 记录调整方向，回到 Step 1-3 补充调研 |
| **Kill** | A0 致命且无调整方向，或核心假设无法修复 | 记录失败原因和教训，释放资源 |

[MUST] 4a 结果记录到 `decision_log.md` 并经用户确认。Kill 立即终止，Pivot 回退。

### [FR-12] MVE→Formal 架构差异门控

> 起源：同 FR-11。MVE 架构摘要记录了证据的有效条件，本规则在仿真器设计阶段（GW Step 6）检查正式设计是否仍满足这些条件。

**触发时机**：GW Step 6（仿真器设计）完成时，在进入 Step 7（实现）之前。

[MUST] simulator-design.md 必须包含与 MVE 的架构差异对照表：

```markdown
### MVE vs Formal 架构差异

| 维度 | MVE (来自 §D 架构摘要) | Formal (本设计) | 影响 model→baseline 对比？ |
|------|------------------------|-----------------|---------------------------|
| 动作空间 | {MVE 架构摘要值} | {本设计值} | {是/否 + 具体理由} |
| 决策粒度 | ... | ... | ... |
| 对比范式 | ... | ... | ... |
| 奖励语义 | ... | ... | ... |
| 先验强度 | {MVE: DRL/先验 比值} | {Formal: 预期先验强度变化} | {是/否 + 理由} |
```

**门控条件**：

- 全部"否" → 通过，进入 Step 7
- 任一"是" → 必须做以下**二选一**：
  - (a) **新 MVE**：用正式架构跑最小实验验证假设仍成立（时间预算同 §D）
  - (b) **解析论证**：具体说明 baseline 能做 X，模型通过 Y 机制达到等价效果。论证必须可证伪（即存在一个具体场景能推翻论证）
- 无法完成 (a) 或 (b) → **禁止进入 Step 7**，必须修正设计使架构一致，或调整假设

> 为什么不允许空泛论证：(b) 要求"baseline 做 X，模型通过 Y 等价"而非"DL 能学到更好的策略"。后者不可证伪，任何结果都能事后合理化。前者要求指出具体机制，如果机制不存在（如单路径无法等价多路径分流），论证自然失败。

## Step 4b：仿真条件 + 资源风险验证（Baseline 选定后、仿真器设计前）

> 维度 C/E 依赖 Baseline 信息和仿真参数，需在 Step 5 之后执行。

### 维度 C：仿真条件可行性

[MUST] 检查：

1. 仿真环境能否创造条件让核心方法的优势体现？
2. 目标方法的关键特征在仿真中是否有足够大的差异信号？
3. 仿真是否包含目标方法所擅长处理的信号特征？（不包含 → 反模式）
4. 领域专属的仿真检查（通信领域见 `domain-comms.md` 的"过于平滑"预警）

**致命信号**：仿真条件无法支撑核心方法的关键特征。需修复仿真设计或调整方法选择。

### 维度 E：资源/风险比例

[MUST] 评估：

1. Baseline 代码可获取性统计（全部自实现 / 部分有代码 / 大部分有代码）——此时 Baseline 已选定，可准确统计
2. 时间投入估计 vs 预期贡献大小是否成比例
3. 如果方向失败，沉没成本有多大？能否产出次优成果？
   - 可以：条件边界分析、对比基准、方法可行性验证
   - 不可以：无任何可回收产出 → 风险过高

**致命信号**：全部 baseline 需自实现 + 方向失败的沉没成本无法转化为任何产出。

### 4b 决策

| 决策 | 条件 | 后续 |
|------|------|------|
| **Go** | 无致命信号，或风险已记录并经用户确认 | 继续 Step 6（仿真器设计） |
| **Pivot** | C/E 致命但有调整方向 | 回退 Step 5 重新选 Baseline，或调整仿真条件后重新评估 |
| **Kill** | 仿真条件不支持或有不可接受的风险 | 记录失败原因和教训，释放资源 |

[MUST] 4b 结果记录到 `decision_log.md` 并经用户确认。

## 质量门槛

- 4a 维度 A0/A'/A/B/D 均已评估
- 4b 维度 C/E 均已评估
- 致命信号（如有）已记录到 `decision_log.md`

- **路径合规**：`feasibility_report.md` 在 `projects/{name}/` 下

## 不达标时

- 4a A0 致命 → 问题-方法不匹配，直接 Pivot 或 Kill（不浪费 MVE 时间）
- 4a A' 致命 → 所竞争维度被简单策略覆盖，需 Pivot 到不同维度或 Kill
- 4a A/B 致命 → 方向根基有问题，Pivot 或 Kill
- 4a D 致命（MVE 失败）→ 核心假设不成立，Pivot 或 Kill
- 4b C 致命 → 可尝试修复仿真条件后重新评估
- 4b E 致命 → 考虑降低风险（找有代码的 baseline、缩小范围）
