## FR-01: 先验覆盖盲区

**反模式**：存在非 ML 的简单规则/启发式在主要优化指标上已达理论最优的 ≥90%，但可行性评估未识别这一信号，导致 ML 方法的增量价值被高估。

**首次发现于**：
- ISL 调度（Execute D025）：先验策略（keep-active + shortest ISL）覆盖 ~95% 最优，3 种 RL 方法全部未超越
- 抗毁路由（GW 4a）：Dijkstra 重路由恢复 100% 连通率，ML 方法的真正价值在拥塞维度而非连通性维度

**检查程序**：

1. 列出目标问题的所有优化指标（主指标 + 次指标）
2. 对每个指标，回答：是否存在非 ML 策略在该指标上已接近最优？
   - 如果文献中有简单方法达到 ≥90% 理论最优 → 标记为"已覆盖"
   - 如果无法判断 → 必须在 MVE 中加入该简单方法作为 baseline
3. 审查 ML 方法的创新声称是否建立在"已覆盖"指标上
   - 如果是 → **必须重新定位**到未覆盖的指标维度

**Pass/Fail**：
- Pass：创新声称建立在简单策略未覆盖的指标维度上
- Fail：创新声称建立在已覆盖指标上且未提供重新定位论证
- **致命信号**：主指标被简单策略覆盖 ≥95%，且无明确的次指标维度可竞争

## FR-02: 无溯源性能声称

**反模式**：可行性评估中声称"性能间隙 ≥X%"但不标注证据来源，或从不同场景/不同方法的数据外推到目标场景，导致性能预期失真。

**首次发现于**：
- 抗毁路由 4a 评估声称"≥15% 泛化间隙"，实际来自 GRLR 正常态路由消融（非故障场景、非泛化测试）

**检查程序**：

1. 检查 4a 评估中所有涉及数字的性能声称
2. 每个数字必须标注来源类型：
   - **[实证]** — 直接消融/对比实验数据（同场景同方法）
   - **[外推]** — 从 A 场景推断 B 场景 → 必须列出外推假设
   - **[论证]** — 结构性/理论分析 → 必须列出推导步骤
3. 来源类型为 [外推] 的声称不得作为 Go/No-Go 的核心论据

**Pass/Fail**：
- Pass：所有性能声称有来源标注，核心论据基于 [实证] 或充分论证的 [论证]
- Fail：核心论据包含无标注来源的数字，或 [外推] 声称作为核心支撑

## FR-03: 稻草人基线

**反模式**：声称方法 A 相对方法 B 有结构优势时，对比对象是裸 B（无领域特征），而非 B+合理特征工程。夸大了 A 的实际优势。

**首次发现于**：
- 抗毁路由 4a 评估对比"GNN vs MLP"，但竞品 FCRMJ 已证明 MLP+手工拓扑特征（度中心性+故障域衰减）在低故障率下有效

**检查程序**：

1. 列出声称的结构优势（如"GNN 拓扑感知 vs MLP 无感知"）
2. 检查：竞争对手方法加上合理的领域特征后，该优势是否仍然存在？
   - 什么是"合理特征"：该领域已发表的竞品论文中实际使用的特征
3. 如果增强后差距缩小到 <5%：
   - 结构优势声称不成立
   - 需重新定位（如"GNN 自动学习 vs 手工设计特征"而非"GNN 能做 MLP 做不到的"）

**Pass/Fail**：
- Pass：结构优势在增强基线对比下仍 ≥5%，或重新定位后论证合理
- Fail：结构优势在增强基线下消失且未重新定位

## FR-04: 验证实例失真

**反模式**：MVE/快速验证使用的简化实例移除了使所提方法具备优势的结构属性，导致验证结论无法外推到目标场景。

**首次发现于**：
- 抗毁路由 4a MVE 设计使用 6×4 网格，丢失了 Walker Delta 的轨道面结构和 ISL 可见性模式

**检查程序**：

1. 列出所提方法的核心假设（如"GNN 的优势来自捕获 X 结构特征"）
2. 检查简化实例是否保留了 X 结构特征
   - 如果简化移除了 X → 验证结论不可外推，必须换实例
3. 简化实例允许省略的：与核心假设无关的复杂度（如大规模、物理层细节）
4. 简化实例必须保留的：使方法 A 与方法 B 产生差异的结构属性

**Pass/Fail**：
- Pass：简化实例保留了与核心假设相关的全部结构属性
- Fail：简化实例移除了核心假设依赖的结构属性

## FR-05: 竞争维度错位

**反模式**：多目标优化问题在可行性论证时被当作整体评估，未按指标维度分解。创新声称建立在简单策略已最强的维度上，而在 ML 有空间的维度上却未建立论证。

**首次发现于**：
- 抗毁路由 4a 整体评估"故障恢复路由"可行性，未分解为连通性/延迟/拥塞/负载均衡四个维度。定位在"连通性恢复"——正好是 Dijkstra 最强的维度

**检查程序**：

1. 将目标问题拆解为独立的优化维度（≥2 个）
2. 对每个维度评估：
   - 先验覆盖度：简单策略在该维度的表现（高/中/低）
   - ML 改善空间：文献证据显示的改善潜力（≥10% / 5-10% / <5%）
   - 方法增量：所提方法在该维度相对增强基线的预期优势
3. 创新声称只能建立在"先验覆盖度低 + ML 改善空间 ≥5%"的维度上
4. 如果所有维度的先验覆盖度都高 → 标记为致命信号，与 FR-01 联合判断

**Pass/Fail**：
- Pass：创新声称建立在先验覆盖度低且 ML 改善空间充足的维度上
- Fail：创新声称建立在先验覆盖度高的维度上，且无替代维度可支撑

## FR-06: 工具链隐式依赖

**反模式**：引入新工具/数据源时，完整操作链路（认证→搜索→下载→转换→索引）未在框架文档中记录，agent 靠试错发现流程，消耗大量 token。

**首次发现于**：
- CNKI 中文检索（GW P0-3）：从发现需认证到写 cnki_login.py 到测试可用，花 15 轮交互
- IEEE 付费墙下载（LOG-001 FIX-2）：多次下载失败后才发现校园网 IP + Playwright 方案

**检查程序**：

1. 每次引入新工具/数据源时，必须在 tools-guide 或对应阶段文档中记录：
   - 前置条件（认证/IP/依赖）
   - 完整操作链路（端到端步骤）
   - 已知限制和常见失败模式
2. 不允许仅在 git commit 或 handoff 中隐含操作知识
3. 框架文档更新作为工具首次成功使用的同步动作，不延后

**Pass/Fail**：
- Pass：新工具首次成功使用后，操作链路已写入框架文档
- Fail：工具已被使用但操作链路仅存在于 commit 消息或 handoff 中

## FR-07: 方法类型假设

**反模式**：框架规则（奖励函数审查、MDP 试运行、状态/动作/奖励模板、反模式陷阱）隐含假设研究方向为 DRL。非 DRL 方向（纯监督学习/纯优化/系统设计）遇到大量不适用的步骤，agent 不知道该跳过还是变通。

**首次发现于**：
- LOG-001 P2-8："框架大量规则隐含 DRL 假设"
- LOG-005 杀手 3：beam-hopping 走到 Step 7B 才发现 GNN+RL(Gaussian policy) 根本不行，成功论文全用无监督

**检查程序**：

1. 框架中每条研究类型相关的规则必须标注适用标签：
   - `[DRL]` — 仅适用于深度强化学习方向
   - `[监督]` — 仅适用于监督/自监督学习方向
   - `[优化]` — 仅适用于纯优化方向
   - `[通用]` — 所有方向都适用
2. Agent 进入新方向时，先确认方法类型，跳过不适用的标签规则
3. 不适用规则跳过时，必须在 decision_log 记录跳过原因

**Pass/Fail**：
- Pass：框架规则有类型标签，agent 能正确识别并跳过不适用的规则
- Fail：非 DRL 方向被迫执行 DRL 专用步骤（如奖励函数审查），或跳过时未记录

## FR-08: 范式偏离未论证

**反模式**：方法论选择（如 GNN+RL）偏离该领域 top-3 成功论文的学习范式，但未显式论证为何偏离后仍适用。导致走到 Execute 阶段才发现方法不匹配。

**首次发现于**：
- beam-hopping（LOG-005 杀手 3）：GNN+RL(Gaussian policy) 失败，成功论文全用无监督
- ISL 调度（Execute D025）：连续分数+Normal 分布+top-K 选择→PPO 不适配动作空间

**检查程序**：

1. 在 Step 4a/6 方法论证时，列出 top-3 成功论文的学习范式（算法+动作空间+策略类型）
2. 对比所提方法与这些范式的差异
3. 每个差异必须回答：
   - 为什么需要偏离？（问题结构不同 / 范式有已知缺陷 / 新方法有理论优势）
   - 偏离后为什么仍可行？（跨域先例 / 结构性论证 / MVE 验证）
4. 如果无法回答 → 默认跟随成功论文范式

**Pass/Fail**：
- Pass：偏离有显式论证且包含可行性证据
- Fail：偏离成功论文范式但无论证，或论证仅基于"理论上应该可以"
