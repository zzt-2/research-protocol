## 候选方向 1: LEO 星座故障感知抗毁路由（推荐 ★★★★★）

### 核心问题
LEO 巨型星座中，卫星/ISL 故障后的快速恢复路由决策——利用 GNN 拓扑感知能力实现故障无关的泛化性恢复策略。

### 文献空间
- 故障恢复方向总计 36 篇（DRL 主流，如 DRL-driven Fault-tolerant Routing 2026）
- **GNN+LEO 故障恢复: 仅 2 篇**，且均非核心目标（1 篇 DTN 场景，1 篇 SD-LEO 链路可靠性）
- 空白类型: **方法空白**——所有 GNN+路由工作只解决正常态路由，无一将 GNN 拓扑感知用于故障后恢复

### 与 ISL 共享性
- **系统模型**: 完全共享同一 LEO 星座（Walker Delta, Starlink 参数）、ISL 模型、时变图结构
- **方法框架**: GNN 编码器 + DRL 决策框架可复用 ~70%，故障恢复需新增故障状态编码和恢复奖励设计
- **仿真平台**: 可直接复用 ISL 项目仿真器，增加故障注入模块

### 组合叙事线
```
ISL 调度（正常态优化）→ 故障恢复（异常态响应）→ 联合抗毁调度
```
递进逻辑: 第 1 章解决"正常运行时如何优化 ISL 拓扑"；第 2 章解决"故障发生时如何快速恢复"；第 3 章联合优化，让正常态调度预留冗余为故障恢复做准备。

每章可独立发表：
- 第 1 章 → 期刊如 IEEE TCOM/TWC
- 第 2 章 → 期刊如 IEEE TMC/TWC（GNN+故障恢复首创性）
- 第 3 章 → 期刊如 IEEE JSAC（联合优化框架）

### 初步问题建模
- **优化目标**: 最大化生存流量比例 + 最小化恢复时间 + 最小化端到端延迟增量
- **约束**: 并发故障数（1~N）、恢复时限、备用路径跳数上限
- **MDP 建模**:
  - 状态: 星座拓扑图（节点=卫星，边=ISL 状态：正常/故障/恢复中），各链路剩余带宽，受影响流量源-目的对
  - 动作: 为每条受影响流选择恢复路径（或恢复优先级排序）
  - 奖励: 恢复成功流量/总受影响流量 - 恢复延迟惩罚 - 路径跳数惩罚
  - GNN 角色: 编码动态拓扑，使策略对故障数量和位置具有泛化性

### 可行性评估: 高
- 纯 Python 仿真（NetworkX 建模拓扑 + 随机故障注入）
- 不依赖真实故障数据（几何模型生成故障场景）
- 与 ISL 项目共享仿真框架和 GNN backbone

### 风险
1. **竞品追赶（中）**: 2026 年已有 DRL-driven Fault-tolerant Routing，需尽快锁定 GNN 差异化贡献
2. **小故障场景 GNN 优势不明显（中）**: 需聚焦大规模多并发故障（≥5 节点同时故障）才体现 GNN 泛化价值
3. **创新深度（低-中）**: 不能简单给现有 GNN 路由加故障标记，需设计专门的故障感知图结构（故障传播建模、级联失效预测）

## 候选方向 2: LEO 卫星波束跳变调度（推荐 ★★★★☆）

### 核心问题
LEO 多波束卫星在非均匀时变业务需求下的波束跳变调度——利用 GNN 建模小区间空间干扰图结构，替代现有 MA-DRL 的独立 agent 假设。

### 文献空间
- Beam Hopping + ML: 50 篇核心（2025 年 34 篇，爆发增长）
- **GNN + Beam Hopping: 0/119** — 完全空白
- 主流方法: MA-DRL（MAPPO/QMIX）占 52%，同质化严重
- 空白类型: **方法空白**——所有工作将小区视为独立 agent，忽略了天然图结构（同频干扰边、邻接关系边）

### 与 ISL 共享性
- **系统模型**: 部分共享。共享 LEO 星座参数（轨道/卫星数），但 BH 侧重点关注下行覆盖（卫星-地面），ISL 侧重点关注星间链路
- **方法框架**: GNN + DRL 框架高度可复用，GNN backbone 可共享，但图结构不同（BH 是干扰图，ISL 是拓扑图）
- **仿真平台**: 训练框架（wandb, early stopping）可复用，但仿真器需重新开发（业务队列+波束矩阵+SINR）

### 组合叙事线
```
ISL 调度（星间路由）→ BH 调度（下行覆盖）→ 联合 ISL+BH 端到端调度
```
互补逻辑: "LEO 星座端到端资源调度 = 星间路由(ISL) + 下行覆盖(BH)"，两个子问题共享卫星功率和时隙资源。
- ISL 调度影响数据到达时间 → 影响各小区业务队列 → 影响 BH 决策
- BH 的功率分配影响 ISL 链路可用功率

### 初步问题建模
- **优化目标**: 最大化系统吞吐量 + 最小化平均排队时延 + 负载均衡
- **约束**: 波束生成数上限（卫星载荷）、每波束功率上限、同频干扰 SINR 门限、最小服务公平性
- **MDP 建模**:
  - 状态: 各小区业务队列长度、信道状态(CQI)、当前波束照射模式、邻星覆盖重叠矩阵
  - 动作: 时隙分配（哪些小区被照射）+ 功率分配
  - 奖励: 吞吐量 - 时延惩罚 - 公平性惩罚
  - GNN 嵌入: 小区为节点，同频干扰/邻接关系为边，GNN 提取空间特征替代 MLP backbone

### 可行性评估: 高
- 纯 Python 仿真（业务队列模型 + 波束照射矩阵 + SINR 计算）
- 信道模型可用 ITU-R P.618 标准模型
- 训练框架直接从 ISL 项目复用

### 风险
1. **领域过热（中）**: 2025 年 34 篇 BH+ML 论文，需确保 GNN 角度差异化显著
2. **GNN 增益不确定（中-低）**: 如果干扰关系简单（仅邻接干扰），GNN vs MLP 增益有限；需在复杂干扰场景（多星重叠+全频复用）验证
3. **与 ISL 联合优化复杂度（中）**: 端到端联合问题规模巨大，可能需要分层/分解策略
4. **仿真可信度（低）**: 纯 Python 仿真的简化假设可能被审稿人质疑

## 候选方向 3: LEO 路由感知联合 ISL 调度（推荐 ★★★☆☆）

> 注：从方向 A 中提取的细分切入点，作为备选方案。

### 核心问题
不独立做路由，而是将路由决策与 ISL 调度联合优化——GNN 同时编码拓扑和流量需求，DRL 同时输出路由表和 ISL 选择。

### 文献空间
- LEO 路由+ML: 77 篇（红海），但**联合路由+ISL 调度**仅 1 篇（Duality-Guided 2026，联合连通性+路由）
- 空白类型: 问题空白（路由和调度通常分开研究）

### 与 ISL 共享性
- 完全重叠——这是 ISL 调度方向的扩展，不是独立方向
- 风险: 独立性不足，可能被视为"ISL 调度的扩展版"而非独立研究问题

### 主要劣势
- 方向 A 整体红海（77 篇），联合问题虽然空白但太小众
- 与 ISL 调度方向重叠过多，论文结构中难以体现为独立章节
- 与已确认的 ISL 调度 Contract 存在冲突（Contract 冻结了路由用 Dijkstra 的公平规则）

## 推荐排序

| 排名 | 方向 | 推荐理由 | 主要顾虑 |
|------|------|---------|---------|
| **1** | **B: 故障感知抗毁路由** | GNN 空白确认（2 篇非核心）；与 ISL 调度天然形成"正常态→异常态"递进；系统模型完全共享；纯 Python 仿真可行；契合论文结构分析报告的"路由→调度→抗毁"推荐 | DRL 竞品已存在（2026），需快；小故障场景 GNN 优势不明显 |
| **2** | **D: 波束跳变调度** | GNN 空白更大（0/119）；MA-DRL 可扩展性差是已确认痛点；与 ISL 形成互补关系 | 方向更热（2025 年 34 篇）；与 ISL 系统模型部分不同（需新仿真器） |
| **3** | A 细分: 联合路由+ISL 调度 | 问题空白 | 与 ISL 方向重叠过多，独立性不足 |

### 推荐理由详述

**首选 B（抗毁）的核心论据**：

1. **空白最可 defended**: GNN+LEO 故障恢复仅 2 篇非核心工作，方法空白清晰且可论证
2. **论文结构最匹配**: thesis-structure-research 分析报告（34 篇博士论文精读）明确推荐"路由→调度→抗毁"层次递进型结构，B 直接对应"抗毁"层
3. **共享度最高**: 与 ISL 调度共享 100% 系统模型和 ~70% 方法框架，仿真器可直接复用
4. **递进逻辑最自然**: ISL 调度（正常态）→ 故障恢复（异常态）→ 联合抗毁调度，形成完整生命周期
5. **方法递进设计**: 可设计 GNN 方法递进——基础 GNN-AC（ISL 调度）→ 故障感知 GNN（抗毁路由）→ 多任务共享表征 GNN（联合优化），避免"同一方法跑三个场景"的单调感

**如选 D（波束跳变）的补充论据**：
- GNN 空白更大（0 vs 2 篇），首创性更强
- MA-DRL 可扩展性差（>40 小区收敛困难）是已确认的技术痛点，GNN 有明确改进目标
- 但需要开发新仿真器（BH 侧重下行），与 ISL 仿真相独立，工作量更大
