## 1. 为什么不能再地勘（最重要的诊断，必读）

### 1.1 地勘陷阱（核心坑）

**5 轮地勘卡死的根本原因**：每轮地勘执行后，主线都用"真信号够不够"判要不要进下一步——**但判据 A（baseline 真失效）不该在地勘阶段判，该在批评汇总阶段判**。

这是**工具错位**：
- 地勘阶段产出 = 候选论文清单（abstract 层，足够）
- 判据 A 信号 = baseline 真失效的物理证据（**全文层**，abstract 写不出）
- 主线错误做法 = 用 abstract 层工具判全文层目标，判 5 次都觉得"信号不够"，开第六轮

### 1.2 为什么 abstract 判不出判据 A

作者写 abstract 的动机：**吹自己方法好**（"我提出 X，比 baseline 好 Y dB"）。
判据 A 要的信号：**baseline 真失效**（"baseline 在常见条件下不行"）。

**叙事方向相反**。作者在 abstract 里写 baseline 失效是为了铺垫自己的贡献——所以会写，但写得轻（一两句 motivation），主要篇幅给"我的方法"。

所以 abstract 里 baseline 失效信号**必然稀**——**不是地没缝，是 abstract 这个载体天然少报缝**。S010 第三轮诚实重判 173 条 abstract 候选，真信号只有 1 条（0.6%）——这个数字反映的是 abstract 工具的天然局限，不是地的物理状态。

baseline 失效的**真正信号源**（都是全文层）：
- 综述论文的 open problem / future work 段（作者主动盘点 baseline 失效）
- 论文的 problem statement / motivation 段（作者描述 baseline 不足，比 abstract 详细）
- 论文的 related work 段（作者批别人方法）
- 批评汇总本身（S002 框法乙"找被批的方法"）—— 本来就是全文层信号

**这些都是全文层信号，不是 abstract 信号**。

### 1.3 因此 A/B 分离诊断的真实状态

S009 悬而未决 #11"A/B 分离诊断"——**S010 没真正完成，也不能在 abstract 层完成**。
- 173 条 abstract 候选真信号 1 条（0.6%）—— **这个数字不是"A/B = B 成立"的证据**，是"abstract 工具判不出 A/B"的证据
- A/B 真判定 = 选地后精读全文 5-10 篇，看 baseline 真失效信号在全文层的密度
- **现在不能下"地没缝"结论**——工具错位，证据等级不够

### 1.4 "卫星光学" 检索词污染的真实影响范围

S010 发现"satellite optical"在遥感语境指光学观测卫星（非通信），43% 召回是遥感论文。**但这个污染的范围被高估了**：
- 污染侵蚀的：v3/v4 主表的子地带分布统计（地形图失真）
- 污染**不侵蚀**的：173 条**人工 abstract 判读**（人工读 abstract 排除了遥感，所以 0.6% 这个硬数字不受污染影响）

所以"地基污染侵蚀 A/B 结论"是 S010 后半段的**错误判断**——A/B 建立在人工判读上，本来就牢（虽然 0.6% 这个数字本身反映的是 abstract 工具局限不是地没缝）。

### 5.2 选地标准（不是选方向）

**这是关键区分**：选地不是选研究方向，是选一块地进批评汇总。选地标准：

1. **baseline 密度高**（批评汇总要找"被批的方法"，方法多才有得批）—— 调制/检测 baseline 密度高
2. **非饱和**（避免 4b#1 那种"刚 Kill 又遇到"）—— 编码地带慎选
3. **abstract 信号最硬**（虽然 abstract 层信号弱，但相对硬的优先）—— 看各子地带真信号密度（虽然绝对值低，但有相对差异）
4. **方法论边界安全**（不被老师砍）—— 4 块都安全

**候选优先级建议**（用户拍板，新对话不替选）：
- 信道建模（111，池最大，但多条 abstract 自陈模型失效——这是物理层分析缝，判据 A 间接）

- AO（30，跟 DSP 补偿同构，理论上 baseline 失效信号应该硬，但池小）

### 5.3 选地决策机制

**精读子 agent 任务**（gw-read）：
- 子 agent 读 content.md 全文
- 按模板提取：**problem statement 段** + **related work 段** + **open problem / future work 段** + **作者点名批的 baseline 是什么 + 批什么 + 改进是什么**
- 返回按模板提取的结构化数据（≤500 词/篇）
- **关键**：子 agent 要找的不是"作者提出什么方法"，是"作者**批**baseline 什么"——批评汇总框法乙（H001 定义）

**精读范围**：5-10 篇代表论文（不全读）。代表论文选取标准：
- 高被引（基础性强）
- 近期（2022+，反映当前 baseline 状态）

**单子 agent ≤15 分钟**（AGENTS.md 子 agent 时间上限）。如果 5-10 篇超时，分批派。

### 6.3 批评汇总产出格式

按 `H001` §产出格式 + `S002` 框法乙三层表：
- **层 1：批评维度表**（每篇提取的批评点，按维度归类：baseline 类型 / 失效条件 / 改进方向）
