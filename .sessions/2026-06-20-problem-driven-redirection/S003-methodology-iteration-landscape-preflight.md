## 记录：本次讨论的完整脉络（九步）

### 第一步：用户问"为啥路由顺、FSO 这么难"

用户原话："我在想，我这个研究协议一开始，是找的路由方向，为啥当时那个方向挺顺的，这边这么难搞"

这个问题是破局起点。主线没有凭印象答，先去读路由专题的实际 contract（`projects/_archive/leo-congestion-routing/contract.md`）核实"顺"具体长什么样。

### 第二步：路由为什么顺——读 contract 后的发现

路由 contract 的 hypothesis：**链路故障率 ≥5% + 非均匀流量时，ECMP 等价路径被打破 → GNN 消息传递做负载感知分流 → MLU 降低 ≥10%。** MVE 实测 GNN/ECMP=0.88，真有 12% 增益。

**结构特征**：baseline（ECMP）在一个普遍存在的条件（卫星 ISL 故障 8% 是常态）下，因为明确的假设（等价路径）而真失效，换方法真有用。不是"找洞填"，是"baseline 在常态下真塌"。

### 第三步：FSO 为什么难——5 次失败的结构性诊断

5 次失败全撞在同一结构上：每次都假设了"一个让 baseline 失效的 C"，实际那个 C 下 baseline 已最优。

| 方向 | 以为 baseline 失效的 C | 实际 |
|---|---|---|
| N1 PCS | 16-QAM 有整形空间 | 整形空间不存在 |
| ③ MCS | 仰角变化有排程增益 | oracle 0.09dB，增益不存在 |
| A3 CPE | 相位有动态可补 | 漂移 0.008rad，损伤不存在 |
| 4b#1 交织 | 突发宽自适应有用 | Lburst≪容量，空间不存在 |
| (c) GG-LLR | baseline 用次优 LLR | 理想CSI下已最优，改进不存在 |

**根因**：5 次都"我以为有缝"，实际这块物理地（中弱湍流 σ²_R<1）被物理压死，根本没有"baseline 失效"的缝。**不是方法不好，是地没缝**。

### 第四步：结构性差异一句话

**路由顺，是因为有"baseline 在常态下真失效"的缝；FSO 难，是因为这块地被物理压死没缝。** 路由像"地震带造抗震桥"（地震常态、真塌、真有用）；FSO 5 次像"我以为桥塌实际没塌"（这块地没地震）。

### 第五步：用户追问"路由那边比较简单？代码很好写？"

用户原话戳到第三个关键差异。主线确认：这不只是工程便利，是**结构性研究类型差异**。

| 维度 | 路由（顺） | FSO（难） |
|---|---|---|
| 问题建模 | 离散组合优化 | 连续物理信道 |
| 一次实验成本 | 秒级确定 | 分钟-小时级 + MC 噪声 |
| baseline 最优性 | 跑一下就知道 | 要先解析证明 |
| 参数错误代价 | 重跑即可 | 一个错→伪信号→整轮废（A3 1885×）|
| 增益来源 | 算法逻辑改进 | 物理假设是否成立 |

**路由的问题成立性 = 工程可验证**；**FSO 的问题成立性 = 物理可证明**（且依赖参数溯源，链条长每环可错）。

### 第六步：主线第一反应（错的）——把路由条件当通用标准

主线提议 4 条"挑地判据"：baseline 真失效 + 工程可验证 + 参数不敏感 + 跑一下有数。**用户立即反对**：原话"这个很难满足啊？这几条并不是目前这个方向很匹配的？只能作为难度参考？"

用户对了。主线把路由那块地的"完美条件"当通用标准，是**把特例当通用**——FSO 这种连续物理领域本就匹配不上这 4 条，匹配不上不等于不能做。

### 第七步：修正——4 条拆成 1 硬 3 软

主线拆开那 4 条，发现混了两个东西：

- **条件 A（地有没有缝）** = baseline 在常态下真失效 + 改方法真有增益。**真·必要条件**——5 次失败全是这条不满足。
- **条件 B（好不好挖）** = 工程可验证 / 参数不敏感 / 跑一下有数。**难度参考**，不是必要条件——满足只是做得快，不满足只是做得慢。

**真正卡死 FSO 的是 A（没缝），不是 B（难挖）。** B 是放大器：有缝但难挖慢一点能成；没缝还难挖才死。

判据修正：**A 是 Go/No-Go 硬判据（缝），B 是工作量预估软参考（难度）**。这跟 glossary 四判据 + FR-21 oracle 上界完全对得上——FR-21（增益上界 <0.5dB Kill）本质就是在量化检查 A。

### 第八步：协议怎么改 / 先改还是先测

用户问三件事。主线答：

1. **协议要加什么**：当前协议 GW Step 1（检索）之前没有"选地"这一步——Step 1 检索词已经预设了方向，但"这块地选对没"协议不管。要加 **Step 0 地勘**（用判据 A 筛子地带）。三改造（四判据/Q#链/门控）不动，地勘是它们上游一层。

2. **先改协议还是先测**：**先测不改**。理由：现在改协议又是"先有方法找问题"（跟 Supervisor-Skills 那次一个错）。地勘是个 idea 不是方法，没验证过不该塞进协议地基。先在 thesis-fso 上试，产出了实在判断再考虑固化。

3. **讨论充分了吗**：差一点——"地勘具体怎么做"还没定。

### 第九步：用户给地勘形态——大范围检索 + 全留拉表 + 分类

用户原话："感觉可以最大范围关键词？然后把它们做的啥都记下来拉表，之后分类？没有一开始的大规模检索，就没有后续。感觉咱们之前每次检索之后，留下几个，这么搞完，后面每次都没一点印象"

**这句话点破了之前检索的结构性缺陷 + 给了地勘的具体形态**：

- 之前每次检索完只留"几个候选"，被筛掉的大多数直接消失 → 下次对话对这些没记忆 → 反复检索反复筛反复忘 → 永远在原地打转（FSO 载波同步被筛掉 N 次，下次新对话的我看到又觉得"没试过"→ 又撞死）

- **地勘 = 大范围、全留、分类沉淀的检索**。跟之前检索的区别：范围最大（不预设方向）/ 目的是摸清整个领域在做什么 / 全留拉表（不留几个丢其余）/ 产出是"谁在做什么"全景图。

主线提议拉表最小字段（每行）：子地带 | 做的事 | 是否跟湍流强相关 | baseline 是谁 | 增益怎么验证 | 缝潜力初判。分类按缝潜力三分：🟢 有缝潜力 / 🟡 不确定 / 🔴 死地饱和。**🔴 特别重要**——每次死一个方向在表里标 🔴+理由，就是领域记忆，下次不再撞。

产出存到固定位置 `projects/thesis-fso/landscape.md`（与 literature_notes 平级），让所有对话都能读到。

### 第十步：批评汇总和地勘顺序——不换，是加一层

用户问"批评汇总和地勘顺序要不要换"。主线答：**不换，是加一层**。地勘在批评汇总上游——

- 地勘：输入=大背景，输出=子地带清单 + 缝潜力初判
- 批评汇总：输入=某个选定子地带，输出=问题候选 Q#

之前直接跑批评汇总 = 跳过地勘直接进预设的错地（FSO 物理层 DSP 死轴）。正确链路：**地勘全景 → 分类选地 → 批评汇总找问题 → 四判据 → 4a**。批评汇总不消失，从"第一步"降成"地勘之后的第二步"。

**关键细节**：地勘阶段不用批评汇总的框法乙（收批评/隐式批/改进动机）。地勘要全景不是批评视角——如果套框法乙会只看到有批评的地方，漏掉"很多人做但没人批"（可能是饱和也可能是大家都觉得没问题但其实有问题——后者更危险）。地勘检索词更宽（只限大背景），拉表字段不带批评筛选；等选定地进批评汇总再用框法乙深挖。

### 第十一步：背景约束的真实边界——开题其实没那么锁

用户给了决定性信息：

- "开题具体章节内容无所谓，标题对上就行。别的我不在乎"
- 标题 = **"星地湍流信道激光通信处理技术研究"**
- "湍流其实实在不行可以去掉"
- "至于开题，建议你别管。内容完全无所谓，后面全换了都行"

**这把之前所有"FSO 物理层三轴锁死"的悲观判断解开了**。真实约束只有一条：**导师锁的是"星地激光通信"大背景，标题对得上就行**。湍流可去、章节可换、内容可废。

标题逐词拆："星地"（锁）/ "湍流"（**可去**）/ "激光通信"（锁）/ "处理技术"（**不是"信号处理"，是宽义的"处理"，含信道/链路/系统/光学处理**）/ "研究"。

地勘的检索范围由此明确：**星地激光通信全谱**（不预设方向、不锁湍流、不锁 DSP），让"做什么"从结果涌现。

- 之前（S001）：四判据是唯一 Go/No-Go
