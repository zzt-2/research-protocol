## 下一步干什么

**第一件事不是派子 agent，是读 S001 + topic-index 不变量**（确保新对话的我没忘方法论纪律）。

然后派子 agent 执行批评汇总：

- **工具**：`tools/search`（脚本，不是 web search——守主对话禁令）。可补 `tools/blit --source cnki` 搜中文学位论文。
- **检索范围**：星地 FSO **物理层链路**（载波同步 / 信道估计 / 调制 / 编码 / 均衡）+ **目标函数**（BER vs 中断概率/容量/可用度）。背景锁死星地 FSO。
- **年份**：2019+（thesis-fso master-state 项目级参数）。
- **筛选标准（框法乙，用户确认）**：收三类——① 明确批评句（"X fails / is suboptimal / limited by"）② 隐式批评（"现有方法假设 X，但实际 Y"）③ 改进动机（"we address the limitation of"）。**排除**作者自己写的 future work / limitation（= 被动读局限，已否决）。
- **产出格式（强制，给模板）**：三层结构——
  1. 批评维度表：维度名 | 该维度下被批的方法 | 批评角度（A 失效假设是什么）
  2. 被批方法表：方法名+年份+来源论文 | 被批次数 | 批评角度收敛在哪
  3. 时效检查表：被批的洞 | 现在补了没（✅补了/❌没补/⚠️部分补）| 补它的论文+年份
- **纪律**：只汇总不下判断、不臆造、不挑（汇总完主线判断）。理想 AWGN 链路等跟湍流无关的，标注不剔除，主线筛。

**子 agent 回来后，先别急着选 Q#。按下面的偏航检查清单，看方法论偏没偏。**

## 纪律（和下一步直接相关的约束）

### 偏航检查清单（用户在新对话照这个看我偏没偏）

用户原话："你自己做了后面偏了我都没发改。"——所以偏航必须可检查。新对话的我做完每一步，用户照这清单对照：

**A. 有没有滑回"先有方法"？（5 次失败的同一种病，最致命）**
- [ ] 批评汇总的检索词，是不是**方法中性**的（搜"FSO carrier synchronization limitation"而非"DPLL FSO"）？如果检索词里预设了具体方法 → 偏了
- [ ] 选精读对象时，理由是"这个方法被批得最狠/裂缝最大"，还是"我觉得这个方法有意思"？后者 → 偏了
- [ ] 有没有出现"这个方法应该能用，我们试试"这种确认式思路？有 → 偏了

**B. 有没有放水四判据凑数？**
- [ ] 过判据时，每条 ✅ 是真有证据，还是"应该算过吧"？后者 → 偏了
- [ ] 判据 2（方法产出形态）有没有被含糊带过（"大概能产出个公式"）？含糊 → 偏了
- [ ] 有没有为了"这次得出点东西"降低标准？有 → **方法论废，立即停**

**C. 种子来源对不对？**
- [ ] Q# 候选是**从批评汇总里长出来的**，还是又回到开题报告 4 条线索（VV/DPLL/SEP/编码辅助）？后者 → 偏了（线索已降级为事后对照，不当种子）
- [ ] 有没有"我自己想到一个方向"绕开汇总？有 → 偏了

**D. 有没有闷头跑不停下来看方法论？**
- [ ] 汇总完，是直接选 Q# 往下冲，还是**先停下来评估"汇总这步方法论行不行"**？直接冲 → 偏了
- [ ] 每步能不能说清"为什么走这步"？说不清 → 偏了

**出现任何一条偏航，用户喊停，我（新对话的我）必须回到 S001 + topic-index 不变量重新对齐，不准狡辩。**
