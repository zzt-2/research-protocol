# [S001] 方法论定盘：从"精读找问题"到"批评汇总找种子"

> 2026-06-20 | GW 重定方向 | 状态：方法论已定盘，待执行

## 目标

把本轮关于"怎么找问题"的完整讨论定盘成可执行打法，并锁定本次实战的根本目的（验证方法论，不是推进论文）。

## 背景：改造后框架有质检无研发

framework-evolution 三改造（LOG-001）刚落地：glossary 定义了"问题"（四判据 M/C/A）、contract 打通了"问题→假设"Q# 引用链、master-state 加了跨 Step 硬门控。**这些全是质检标准（判据/门控/链路），回答"这个问题合不合法"。但"怎么找到问题"这个研发动作，框架只说了"精读填第 7 项 M/C/A 表格"，规定得非常软。**

用户的不安正在此：判据再硬，找法不行，照样产不出好问题。这个不安是对的——改造前 5 次失败之前也"读"过论文、也写了 literature_notes，照样跑去撞死。所以"读"不保证找到问题。

## 记录：讨论推演的完整脉络

### 第一步：戳破"精读就能找到问题"的轻巧

主线最初的说法是"问题从精读浮出来"。用户质疑：5 次失败之前也读过。主线承认说得太轻——**"读"不保证找到问题，关键是"带着什么读、读什么、读完产出什么"，而这步框架没怎么规定**。

### 第二步：识别最大的失败风险 = 滑回"先有方法"

用户明确指出：最可能栽在"滑回先有方法"。这是**机制必然**，不是自律问题：

- 一旦带着"我想做 DPLL"进精读，每读一句都在回答"DPLL 在这能用吗"——这是**确认题不是发现题**
- 确认题永远能找到支持证据（任何方法都有适用角落）→ 路径必然通向"能用 → 那就做"
- 更阴险：**开题报告线索本身携带这种偏差**。H002 的 4 条（VV窗口/DPLL/SEP/编码辅助）是从方法反推出来的，不是从问题长出来的。拿它们当起点 = 起点就埋了自上而下

**所以开题报告 4 条线索不当种子**。用户原话："开题报告那几个质量确实不咋够。" 它们降级为事后验证对照。

### 第三步：否决"被动读局限"

主线提议精读填 M/C/A，用户否决"被动读局限绝对不行"。理由：

- 局限是作者**自己**写的，大概率是难啃硬骨头 / 套话 / 作者自己没想到（那他不会写进局限）
- **作者不知道或不愿承认的**才是金矿，而它在局限清单里根本不出现
- 被动读局限 = 在别人划好的格子里找答案

### 第四步：转向"假设审计"

主线推到：找法应该是**假设审计**——审方法的关键假设（"假设不成立方法就垮"的那种），逐假设比对你场景 C，假设失效 + 影响 M 性能的裂缝才是 Q# 种子。**天然防自上而下**（你审的是别人的假设，不是自己的预想）。

用户认可这个方向，但点破更深一层："多汇总别人怎么指出不足，才能有自己的想法，不然闭门造车不太行。"

### 第五步：定盘 = 批评汇总找种子

用户这句把方法论根基点透：**自己的问题意识不是凭空长出来的，是读完别人的批评、被别人的视角重塑后自然分化出来的。** 这是做研究正路，跟改造前"我有个想法→去文献找支持"相反。

主线把"批评汇总"具体化成三层结构：

| 层 | 汇总什么 | 产出什么 |
|---|---|---|
| 1 批评维度 | 领域里大家**用什么角度**批别人（假设不成立/复杂度高/只在仿真/依赖理想CSI/...） | 知道 Q# 可以长在哪些维度上（A 不是只有"假设不成立"，还有"假设太理想""假设不可获取"） |
| 2 被批方法 | 哪些 baseline 被反复批、批的角度收敛在哪 | 被多角度反复批的 = 真有裂缝的热点，值得审 |
| 3 你的判断 | 被汇总的批评里，哪些在你场景（星地FSO）下**还没人解决** | 批评 × 场景 × 未解决 的交集 = Q# 候选区 |

**这套是领域驱动而非预想驱动**——连"做不做 DPLL"都不事先定，是汇总完看哪个方法被批最狠、裂缝最大才定。

### 第六步：防 TL-03（别人做的当机会）

批评汇总有个陷阱：别人批的角度可能已经被人补了。领域热点往往竞争激烈。所以汇总必须带**时效检查**：被批的洞现在补了没有？补了→不是 Q#（没新颖性）；没补或补不够→候选。这把 TL-03（把别人做的当机会）防了——不是看"别人做了 X"，是看"别人批了 X 但没人补 X"。

### 第七步：范围讨论 — 为什么不止"载波同步/信道估计"

主线最初提"星地 FSO 载波同步/信道估计"做汇总范围。用户警觉："可能不够大？"

主线自我否决：载波同步/信道估计 = **C3 单链路 DSP 里的子模块**。一上来锁这里 = 锁在**已经撞死过 5 次的那根轴上**。5 次撞墙的根因正是 C1+C2+C3 三轴锁死、老在 C3 上挪模块。

定三个层次：
- 层 1（窄）：DSP 模块（同步/估计/检测译码）= **5 次全死的层，排除**
- 层 2（中）：整个物理层链路，**含目标函数本身可质疑**（为什么是 BER？中断/容量呢？）= **选定**
- 层 3（宽）：跨场景（pointing/多波束/网络）= 太散，且导师明说不跑出星地 FSO 背景

**选层 2 的关键**：把 C2（目标=BER）也纳入可质疑前提，不只审 C3 模块。"现有方法都优化 BER，但场景 C 下中断才是瓶颈"本身就是 Q# 维度。

### 第八步：确认导师约束的真实边界

主线担心层 2 放开 C2 会撞导师"3章对应星地场景下的问题"。用户澄清：**导师那句只锁大方向（星地 FSO 背景），不锁单链路物理层 BER**。所以质疑 C2 合法。用户确认层 2 + 认"质疑为什么是 BER 本身可能产出 Q#"。

### 第九步：用户锁死根本目的

用户提醒："这次的目标，没忘吧？之前几次都不行，所以想了个新方法论，试着用它产出可行内容。这是根本。大框架别忘了，不然后面容易偏，容易转死胡同。"

主线确认并把纪律写死：**这次的目标是验证方法论，颗粒无收好过凑数。** 放水一次方法论就废，5 次失败的门全白堵。

## 验证标准（方法论验证，不是 Q# 验证）

跑一步停一步看方法论表现：

| 阶段 | 看方法论什么 | 不只看 Q# 什么 |
|---|---|---|
| 批评汇总后 | 汇总这步产出信息质量够不够支撑下一步？方法对不对？ | 不急着选 Q# |
| 选候选过四判据 | 四判据实战中真能筛吗？有没有"看着像 Q# 其实伪裂缝"？判据够不够用？ | 不只看候选行不行 |
| 进 4a | 假设审计里物理判断占多大比重？框架兜得住多少？ | 不只看 Q# 能不能 Go |

**失败判据（什么算方法论没过）**：
- 为了有产出放水四判据 → 方法论废
- 跑回"先想做什么方法" → 方法论废
- 批评汇总产不出结构化信息、信号被噪音淹没 → 汇总这步方法要改（不算方法论废，算迭代）

**成功判据（什么算方法论过了）**：
- 不论最终有没有 Q#，全程没有滑回"先有方法"
- 批评汇总产出了结构化的"批评维度 × 被批方法 × 是否已补"信息，能支撑下一步判断
- 每步能说清"为什么走这步"，不是凭感觉

## 后续

**下一步（具体可执行）**：派子 agent 执行批评汇总。

- 工具：`tools/search`（不是 web search，守主对话禁令）。可选 `tools/blit --source cnki` 补中文文献
- 检索范围：星地 FSO 物理层链路（同步/估计/调制/编码/均衡）+ 目标函数（BER vs 中断/容量/可用度）
- 年份：2019+（本项目 baseline 年份，见 thesis-fso master-state 项目级参数）
- 产出格式（强制）：三层结构——批评维度 / 被批方法 / 是否已补（时效检查）。每条带来源论文。
- **筛选标准（框法乙，已确认）**：收三类——① 明确批评句（"X fails / is suboptimal / limited by"）② 隐式批评（"现有方法假设 X，但实际 Y"）③ 改进动机（"we address the limitation of"）。**排除**：作者自己写的 future work / limitation（那是被动读局限，已否决）。理由：聚焦"别人指出的他人方法的失效假设"（= Q# 的 A），覆盖顶刊常见的不直接批但隐式指 gap 的写法。
- 纪律：只汇总不下判断、不臆造、不挑（汇总完主线判断）
- 预期障碍：物理层链路可能捞回跟湍流无关的（如理想 AWGN 链路研究），子 agent 要标注但不剔除，主线判断时再筛

**子 agent 回来后**：不急着选 Q#，先看方法论表现（汇总质量），再一起看哪个裂缝最大最适合做 → 那才是精读对象（精读对象由汇总决定，不由开题报告决定）。
