### D002 Bug1 究竟改了什么

1. **Numerator：没有统一。** NDA 仍计 1024-bit errors，DA 仍计 768-bit errors，selector 仍根据 branch command 在两种 error count 之间切换。
2. **Denominator：改了。** 原脚本 NDA 除 1024、DA 除 768、selector 除实际选中分支的 768/1024 之和；修复版统一除 `N_win×1024`。
3. **Comparison object：改了。** 原脚本以每 seed 事后 `min(NDA,DA)` 作对照；修复版改为分别对固定 NDA 和 DA_full，并另加 `Σ_b min(ne_n,b, ne_d,b)` 的 post-hoc count lower envelope。
4. **为什么不够：** 修复了“分母随 selector command 变化”，没修复“分子的被评分 bit 集合随 selector command 变化”。

### `switch_ber_mean` 能合法称什么

- 它不是 BER：BER 要求分子错误事件与分母试验总数来自同一冻结 population。
- 它不是 net BER：“net”不能将未解码位自动改为零错误。
- 它不是 error density：density 仍要有物理上统一的 support/measure；此处 support 随 branch 改变。
- 最宽松且不误导的名称是 **decoded-payload error-count per fixed-duration processing window**，但这只是诊断量，不能作为通信性能增益。

### 病态退化测试

若 NDA 和 DA 在各自被评分 bit 上都有相同错误率 `p`，selector 选 DA 的窗比例为 `f`，则即使没有任何 per-bit 性能改善，Fig.5 仍给出

`G = 10log10[1024 / ((1-f)1024 + f×768)] = 10log10[1/(1-f/4)]`.

`f=1` 时自动得到 `10log10(4/3)=1.249 dB`。更极端地，若某分支发送/评分的 payload 趋近零，其 error count 也趋近零，指标会自动变“更好”。这个退化极端否定了它作为 performance gain 的资格。

1. 标准 BER winner = `argmin(nda_ber_mean, da_ber_mean_data)`；

## 6. Pilot-overhead 记账审计

### 6.1 D009 自身

- `PILOT_OVERHEAD_DB = 10log10(4/3)`，来自 spacing=4 时等信息吞吐下 DA 多发 pilot 的总能量代价（`_b11_params.py:65-68`）。
- formal 坐标定义为 `gamma_tot,NDA=gamma_d`，`gamma_tot,DA=gamma_d+1.249`（`fair_comparison.py:4-19,28-44`）。
- 逐点公式 `(s_da_d_needed + overhead) - gtot` 只加一次（`fair_comparison.py:120-132`）。
- 30-seed 持久数值 strong/uplink-moderate/uplink-strong 为 2.508910/2.442983/3.101257 dB；减 1.249 dB 得 data-SNR 差 1.260/1.194/1.852 dB（`_fair_gain_summary_30seed.json:3-8,44-98`；当前 D009 `decisions.md:294-304`）。

判定：**D009 数值记账 PASS，没有在自身公式内重复加 1.249 dB。** 截至独立复核时，当前 `results.tex:25` 已正确区分 data-symbol-SNR 的 1.3/1.2/1.9 dB 与 total-energy-equivalent 的 2.5/2.4/3.1 dB，并明确该固定分支比较不同于 selector-output metric。

### 6.2 Fig.5 与 D009 的关系

- Fig.5 的 `/1024` 在 ratio 中约掉，并没有将曲线转换到 total-energy 坐标。
- selector 选 DA 时少评 25% payload；即使 per-bit error probability 完全一样，也能最多机械获得 1.249 dB 的 error-count ratio 正值。
- D009 是对 DA 的 pilot 资源代价进行等吞吐总能量换算；Fig.5 则是将这些未评分位在 error count 中当成不可错位。它们不是同一物理指标，不能相加或互证；若并列成两项独立性能优势，会造成 pilot-resource 语义混乱。

最终判定：**无数值公式内的“加两次”；Fig.5 是 branch-dependent population 造成的指标伪增益，与 D009 并列会造成资源语义混乱，但本证据不足以严格证明“双重记账”。** 如果未来要给 selector 做 total-energy performance，必须逐窗根据 branch command 记账 payload 与 pilot energy；现有 JSON 缺 branch counts，无法离线恢复。
