## 发现

### Change Contract `CCE-CC-004 v2`（BLOCKED / REJECTED AS COMBINED BATCH）

将论文身份从 estimator selection 上移到 D014 已批准的 received-power-aware adaptive CPR method/scheme，同时删除约 250--350 个英文词的高置信重复，不改变算法、数据、参数、指标、公式或结果含义。

标题候选仅冻结为合同输入，不在本轮实施：

`Received-Power-Aware Adaptive Carrier Phase Recovery for Turbulent Satellite--Ground FSO Links`

Batch A 增加四条强制合同：

1. **身份层级**：adaptive CPR method/scheme → two-stage received-power-aware controller → existing DA/NDA branches。
2. **adaptive 语义**：仅指每 256 样本窗的 branch routing；不指 estimator 参数自适应、在线学习、regime retuning 或新估计公式。控制输入还包含 nominal data-symbol SNR，不得写成 received-power-only。
3. **结果归因**：3.1 dB 只属于 fixed NDA 对 fixed DA；约 1.3 dB 才属于 selected-output 相对 fixed NDA。逐句检查主语、比较对象和数字，禁止把 3.1 dB 归给完整 adaptive method。
4. **非机械换名**：每个 CHANGE 位置必须同时调整论证职责；只把 `selector` 替换成 `method` 而保留原因果结构即验收失败。`selector/selection` 可继续作为内部机制、Results 评价对象和 Fig.5 指标对象。

#### 验收标准

1. 标题、摘要、引言贡献句、Method 身份和结论的外层主语均为 adaptive CPR method/scheme；`selector/selection` 只作为内部机制。
2. 正文净减验收窗收窄为 307--338 词；超出该窗须逐句解释，超过 350 词触发必要信息丢失复审。
3. 上述真实性、公平性和指标边界逐项仍在，且各只出现于承担职责的位置。
4. `system_model.tex:14` 不被擅自补来源；参数处理等待 R008。
5. fresh build 后记录页数、warning、undefined/overfull/underfull；逐页检查；独立 reviewer 对定位、事实和删减做 C/I/M 审查。
6. `adaptive` 首次定义为 windowwise branch routing；不出现 new/novel estimator、online learning、在线调参、单分支实际执行或计算节省等无证据声称。
7. `method.tex:4` 完成 `paper line -> caller -> callee -> selected metric/output` 追踪；双分支预计算与 error-count mux 被准确描述。

#### Stop conditions

- R008 证明参数改动会牵动场景或结果时，参数批次与本合同继续隔离，不顺手重跑。
- 精炼导致任何信息访问、指标或公平性边界消失，立即回退该局部并标 BLOCKED。
- 标题或贡献句需要把控制器称为新 estimator 才能成立，则 D014 定位合同失败，停止 WRITE。
- 若现有实现只能支持 error-count mux，不能支持统一 carrier-corrected sequence 或只执行所选分支，则 Batch A 保持 BLOCKED；不得用概念图替代实现证据。
- 任一修改把 fixed-estimator 的 3.1 dB 归给完整 adaptive method，立即 BLOCK。

## 结论

精炼 Batch B 的逐句合同与 307--338 词预算已通过独立审查；R011/V010 已确认定位 Batch A 的 selected-output 实现真实性 FAIL。按 D015，`CCE-CC-004 v2` 作为组合 Batch 被否决，禁止进入 WRITE。后续只能把纯精炼另立合同，或先拍板真实性路线后重建定位合同。
