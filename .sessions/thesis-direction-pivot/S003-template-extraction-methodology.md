# [S003] 参考论文模板提取方法论

> 2026-05-29 | Day 1 | 完成

## 目标

确定从参考论文提取写作模板的方法论：模板文件应包含哪些字段、到什么粒度、以什么格式呈现，才能在后续手动写作时有效指导并避免已知坑点。

## 记录

### 1. S017 回顾：之前开题报告的11轮修复教训

S017记录了路由方向开题报告从v1到v3共11轮、108个问题的修复过程。核心发现：

**策略层面的教训：**
- **"让LLM写全文"策略本身失败** — 11轮提示词调优后仍有大量残留问题
- 否定规则遵守率30-50%，加入few-shot后提升至约70% — 不够
- 审查和修复之间有"修了但没修全"的系统性不足（经验#22）

**技术层面的系统性问题（按严重程度）：**

| 问题类型 | 出现次数 | 根因 |
|---------|---------|------|
| 翻译腔（"使...成为""被激活"等） | 27+ | LLM训练数据以英文为主 |
| 文献综述清单体（逐篇罗列） | 7段 | LLM逐篇处理习惯 |
| 数据三重出现（二/三/七节） | 6项×3次 | 开题报告七节结构特有问题 |
| 超长句（>60字） | 22处 | LM不拆句 |
| 引用位置错位（跟人名不跟论断） | 11处 | LLM视方法名+引用为整体 |
| "本章"滥用 | 8处 | 开题报告≠论文，语境错位 |
| 段落衔接断裂 | 9处 | LLM段落间缺乏过渡 |
| 元叙述（"本节阐述..."） | 4处 | 英文"This section presents"直译 |
| 括号堆砌 | 40处 | LLM系统性倾向括号补充 |

**26条经验教训中与模板设计直接相关的：**
1. 否定规则不够，需要肯定性示范（经验#1）
2. 提示词中示范本身是错误来源（经验#2）
3. 翻译腔是最顽固问题（经验#3）
4. 引用格式三个层面：格式+位置+密度（经验#4）
5. 审查需参照对比（经验#5）
6. 检索报告体是LLM系统性缺陷（经验#16）
7. 段落衔接是LLM长文写作薄弱环节（经验#17）
8. 清单体源于逐篇处理习惯（经验#18）
9. 修复需要系统性全文扫描验证（经验#22）
10. 引用密度与学术体裁不匹配（经验#26）

### 2. 架构文档讨论：写到什么程度

用户提出问题：帮助完成开题报告的架构文档（指导性文件），到什么程度才能避免后续踩坑？

**结论：架构文档要详细到用户能自己写第一稿，LLM只负责查和排。**

具体要求：
- 每段的内容分配：不只是"描述挑战"，而是"挑战1=GG模型参数估计精度不够，引曹明华2020+Amirabadi 2019"
- 每段的引用锚点：写明2-3篇具体论文及支撑论断
- 数据分布策略：哪个数字在哪个节完整出现
- 三章串联逻辑：Ch2输出→Ch3输入→Ch4输入

**分工原则：**
- 用户做：段落内容决策、核心论述、引用选择
- LLM做：文献批量检索、格式排版、术语一致性检查、引用格式校验

### 3. thesis-platform 四个专题调研

4个子agent并行调研了 thesis-platform 项目的四个相关专题：

#### 3.1 thesis-write-pipeline（2026-05-24）

**最有价值**。包含一套成熟的蓝图→大纲→写作三层规划体系：

- **蓝图协议**（`蓝图协议.md`）：论证主线(3-5句) + 章节功能定位 + 章节间衔接要点 + 论证闭环映射 + 可验证约束 + 篇幅规划
- **大纲协议**（`大纲协议.md`）：核心大纲（跨章对齐）+ 章节大纲（执行细节），含衔接上下文、段落组织、数据映射、引用规划、公式呈现决策
- **典型问题.md**：全文/章节/句级/AI风险四层问题导航
- **S004质量诊断**：Ch1 56%正确/16%编造，Ch2 64%正确/25%符号反转（灾难性），Ch3 79%正确

**关键设计决策：**
- 完全自包含原则：禁止外部文件引用、禁止占位符
- 权威表(Authority Table)机制：数据保真层级 A>C>E>B
- 多轮合成策略（大材料三轮：A+B+C / D+F+G / E）

#### 3.2 material-preprocessing-workflow（2026-05-20）

四步串行流水线：输入盘点→文献基础建设→材料提取合成→验证。

- 材料包A-G七段结构（研究问题/文献/贡献/方法/证据/术语/实验设计）
- 反误归属7原则：只组织不创造、单一证据出现、引用关键文献等
- Map-Reduce架构：分块提取→合成（优于单次调用）

**对当前任务的适用性**：A-G结构可简化用于组织文献，但完整四步流水线过重（文献量不够大）。

#### 3.3 paper-evaluation（2026-05-15）

VIP评价框架三层架构：
- 底线合规（4项否决权）
- 研究质量（3维度A-D评级）
- 详细要素评分（5大类19子指标）

引用质量指标：核心期刊引用率≥30%优秀、近5年引用≥50%高质量。

**对当前任务的适用性**：引用质量标准和文献覆盖完整性检查可参考。

#### 3.4 prompt-methodology（2026-05-29）

从24个真实会话提取的151条规则，15条核心原则：

**与模板设计最相关的原则：**

| 原则 | 一句话 | 对模板的意义 |
|------|--------|------------|
| 闭世界优先 | "只用X" > "不能用A/B/C/..." | 模板应给正面示范而非禁止清单 |
| 三元组 | 每个禁令配替代方案+示例 | 约束列需要替代写法 |
| 可见度阈值 | 关键约束≥1%token量 | 模板中约束不能被淹没 |
| 问题级引导 | 描述目标状态不指定操作 | 模板说"达到什么效果"不说"用什么词" |
| 分层升级 | 措辞→结构→工程→重定义 | 模板应预判失败模式 |

**LLM角色定位：**
- 执行者：善生成/改写，不善精确数字/格式
- 诊断者：善发现问题，不善可靠量化评分
- 判断者：善事实Y/N判断，不善程度判断

### 4. 深入阅读的关键文件

3个子agent深入阅读了蓝图协议、大纲协议、典型问题清单、提示词方法论通用版。

**蓝图协议核心要素：**
1. 论证主线：3-5句"故事脊椎"
2. 章节功能定位：每章要说服读者什么
3. 章节间衔接要点：上游结论→下游起点
4. 论证闭环映射：Gap→Contribution→Conclusion对齐
5. 可验证约束：2-4条硬约束用于后续检查
6. 篇幅与体量规划

**大纲协议关键约束：**
- 核心大纲（~1500-2200字，跨章可见）+ 章节大纲（~800-1500字/章）
- 每章包含：衔接上下文、小节划分与段落组织、数据映射、引用规划、公式呈现决策
- 完全自包含：禁止占位符、禁止内部溯源编号、数据必须带含义

**典型问题清单（AI生成风险四条）：**
1. 参考文献编造 → 所有引用必须人工核实
2. 数据与统计量虚构 → 数据必须来源实际实验
3. 引用内容失真 → 引述式引用尤其常见
4. 占位标记残留 → 说明内容未经核实

### 5. 模板格式设计讨论

**现有S001-annex-paragraph-template.md的问题：**
- 没有论证链（每段在整体中的角色）
- 没有引用规范（引几篇、引在哪里、支撑什么论断）
- 没有衔接要求（段与段之间怎么过渡）
- 没有质量检查点（写完怎么验证合规）

**用户明确的需求：**
- 提取模板用于后续工作（不只是这一次开题报告）
- 模板是通用工具，可从不同参考论文提取
- 由于手动写作，来不及用完整管线，靠自查
- 最新规划（蓝图/大纲）打算做成自包含的

**提议的模板格式：**

```
# [文档类型]模板 — 提取自[作者/年份]

## 元信息
- 来源论文: [完整引用]
- 文档类型: 开题报告 / 学位论文
- 适用条件: [什么时候用]

## 论证主线（3-5句）

## 结构总览
[章节关系 + 每节功能 + 节间衔接]

## 逐节模板

### [节号] [节名]
> 功能: | 继承: | 输出: | 篇幅:

| 段 | 功能 | 来源示例(1-2句) | 关键约束 | 自查 |

## 段间衔接句库
[按类型分类：递进/转折/并列/总分]

## 句式模式库
[好句式 + 适用场景]

## 全局质量检查点
```

**关键设计理由：**
- "功能+继承+输出"来自蓝图协议 → 解决段落衔接断裂
- "来源示例"只取1-2句 → 看清模式但不过度模仿
- "关键约束"列来自S017经验 → 预埋已知坑点
- "自查"列来自典型问题.md → 每段写完有检查项
- 分离结构和内容 → 模板可跨论文复用

### 6. 三方交叉审查结果

3个子agent分别从**结构完整性**（architect）、**防坑能力**（critic）、**实际可用性**（planner）三个角度审查提议的模板格式。

#### 三方共识

1. **跨段/跨节信息缺失**：当前格式是纯段落级的，但最顽固的问题（数据三重出现、术语不一致、机械句式重复）都是跨段/跨节的。逐段自查只能覆盖约40%的问题。
2. **全局约定缺失**：术语统一、时态规范、自称约定、引用风格这些写作前必须锁定的信息目前无处记录。
3. **信息太散**：写某一段要翻4个地方（主线/表格/衔接库/句式库），不如一张表看完一节。

#### 各方独立发现

**结构完整性（architect）：**
- 缺少全局约定表（术语/时态/自称/引用风格）— 低工作量高影响
- 缺少图表规划表（编号/标题/数据来源/首次引用位置）
- 缺少跨节依赖图（三元组：源节→目标节→依赖内容）
- 缺少篇幅预算（各节目标+总量约束）
- 逐段粒度正确，但建议增加"关键句位置"标注（首句/末句功能）

**防坑能力（critic）：**
- "自查"列只能覆盖~40%问题，60%需要跨段/跨节/全局机制
- "关键约束"需要拆分：全局约束清单（适用所有节）+ 段落特定约束（仅该位置独有）
- 全局检查应按问题类型组织（L1句子级grep / L2段落级 / L3全局级），不按文档区域
- 缺少：数据分布图、引用密度规划、时态规范、粒度指南、元语言禁令
- **关键洞察**：D009确认"人写LLM查"，人类写作时翻译腔/AI味风险可能显著降低。约束应聚焦人类也容易犯的问题（数据重复、术语不一致、引用位置、段落衔接）

**实际可用性（planner）：**
- 当前格式提取需60-90分钟，太重；目标30-40分钟
- "句式模式库"和"衔接句库"提取痛苦、边界模糊（"通用模式"vs"偶然措辞"难以区分）
- "来源示例"1-2句刚好：能看出模式和节奏，不诱导逐句替换
- **如果只保留3个核心**：论证主线 + 逐段四列表格（功能/示例/衔接/约束） + 段间衔接要求
- 衔接应并入逐段表格的"接/传"列，不独立成章

#### 修订后的最终格式

```
# [文档类型]模板 — 提取自[作者/年份]

## 元信息（3行）
## 论证主线（3-5句）

## 全局约定（一张表）
| 类型 | 约定 | 首次定义位置 |
术语 | 时延（非延迟） | 1.1
自称 | 本课题 | —
时态 | 研究内容=现在时，预期=将来 | —

## 逐节模板（每节一张表）
### [节号] [节名]
> 功能: | 继承: | 输出: | 目标篇幅:

| 段 | 功能 | 衔接(接/传) | 示例(1-2句) | 约束+自查 |

## 跨节数据分布（一张表，可选）
| 数据 | 完整出现 | 概括引用 |

## 全局检查（按层级，可选）
### L1 句子级(grep): 翻译腔残余 / 单句>50字 / 引用跟人名
### L2 段落级: 引用密度 / 段间过渡
### L3 全局级: 数据分布 / 术语统一 / 机械句式频率
```

**相比v1的变化：**
- 砍掉"衔接句库"和"句式模式库"独立章节 → 衔接并入逐段表格
- 新增"全局约定"表（低工作量高影响）
- 新增"跨节数据分布"表（可选，防数据三重出现）
- 新增"全局检查"按层级组织（可选，写完后grep用）
- 逐段表格从3列扩到4列（功能/衔接/示例/约束+自查）
- 预计提取时间：30-40分钟

### 7. 模板实测与迭代

子agent用S004模板重写了旧开题报告1.1节的前3段，验证模板效果。

**测试结果：**
- 结构清晰度提升约40%，衔接质量提升约30%，总体提升约35%
- **最有用**："功能"列 — 直接回答"这段干什么"
- **次有用**："约束+自查"列 — 提供客观完成标准
- **最没用**："示例(1-2句)"列 — 太短，看不出段内微节奏
- **最大不足**：只管"这段干什么"，不管"这句话怎么写" — 段落内部展开模式（先讲什么后讲什么、引用嵌在哪、收束句模式）是空白

**关键改进：示例列从1-2句扩到4-6句(~100-150字)**
覆盖"开头衔接句→核心论述→引用嵌入→结尾传递句"的完整段内微节奏。已在S004中更新1.1节P1-P9和1.2.x节P1-P10的示例。

**次要发现：**
- P1"按时间递进"约束偏死板，应允许逻辑递进替代
- 全局约定表属于"写完后检查"而非"写作时参考"
- 示例列对P1-P2（背景段）价值不大，对P3-P9（挑战/文献/空白段）价值最大

### 8. 第二轮实测：扩写示例后的效果验证

子agent用修订后的模板（示例扩到4-6句）重写了旧开题报告1.2.1节（路由方法综述），与第一轮对比。

**对比结果：**

| 指标 | v1（1-2句示例） | v2（4-6句示例） |
|------|----------------|----------------|
| 整体评分 | ~6/10 | 8/10 |
| 结构提升 | 40% | 50% |
| 衔接提升 | 30% | 40% |
| 清单体解决 | 部分 | 基本解决 |

**改进最大：**
- P3（方法分类）和P7（文献例举）——4-6句示例清楚展示"归纳句先行→分组展开→收束"微节奏
- P7清单体问题基本解决：示例首句"这些工作均采用MLP或CNN架构，在弱湍流下取得1-3dB增益"明确展示"先归纳后展开"

**仍存在的不足：**
1. P8-P9（缺陷分析）：示例展示了归纳结果，但没展示"如何从多篇论文上升到结构性缺陷"的过程
2. **新发现的张力**：P9类段落（综合判断型）需要论证方法论层面不足，但这类论断没有直接文献可引，引用只能旁证空白存在——与"引用紧跟论断"的约定冲突。模板未给出处理方案
3. P5（方法2优缺点）与P7（文献例举）内容有重叠，模板假设的P4/P5→P6→P7链路实际写作时边界模糊

- 解决P9引用张力问题
