## 质量标准

- **论文图表必须对标实际论文成图，而不是只检查信息齐全；拒绝汇报图式卖点标注和海报式框图** [durable] — 来源：S006（连续纠正曲线比例、标志、线宽与 Fig.4 观感）+ S011（2026-07-13 要求子 agent 核查对标论文标题/坐标/字体/架构图，并明确否定旧 Fig.1）。执行要求：正式画图前先看至少 3 篇同类论文实图；按最终单双栏尺寸检查字体、图例和视觉层级；框图同时审数据流/控制流语义，不能只审“模块都在”。
- **论文框图的节点内部也必须呈现真实科研对象，不能用可解释但贫乏的简笔图标代替** [durable] — 来源：S017/D017（反复否决无意义组合图元）+ D019（要求少字，并把实际技术图缩小嵌入节点）。执行要求：优先用项目数据/模型生成真实微图；次选有明确同角色证据的领域图元；节点内部真实性单列视觉验收，不能被结构 PASS 替代。
- **警惕主线"急于给方向性结论"——过早收敛（过早 Kill 或过早 Go 都是同一病）** [durable] — 来源：D004/D007（过早 Kill：oracle 上界误杀能赢传统 baseline 的方向 + 2026-06-28 "你很容易怀疑自己"，主线把 M-C-A 起草的表述错误当方向死）+ S023（误判红海：2026-06-30 "做得多才容易水"，主线把"做得多"误读红海忘 TL-12 第 4 条）+ **S024**（过早收敛 + 过早推进：2026-07-01 "怎么能只看一个就断定不行"+"有点东西就推进"，主线单锚判大领域 + 拿到 open problem 就想选切入点）+ **S027**（急于推进太多步骤：2026-07-02 "干太多了？别干这么多啊？精度很占上下文的"，主线单对话跑报到+扫描层+穷举门控+判读层第一批远超 AGENTS.md 3 步上限）+ **S028**（急于判读：2026-07-02 "你这怎么还是按以往的去判呢？是不是最好丢掉一些限制，不然咱们弄的不全？"，主线判读层又退回逐个 Go/Kill 老模式，跟用户 S024 要的"穷举式精读全列出分优先级/先看全再判"相反——第 6 次验证）。**根因不是"过早 Kill"也不是"过早 Go"也不是"单步推进太快"也不是"判读模式错"，是"主线急于推进"——不管收敛到 Kill/Go、不管单步还是多步、不管用哪种判读模式，都急于往前赶（还没看全就开始判）。防线：D017 穷举门控 A（扫描穷举完 + 用户确认全景才推进方向性判读）+ abstract 层判不出/矛盾时强制升级到全文/综述层 + 严格守 AGENTS.md 单对话 3 步上限 + **D018 判读层中性提取代替边摸边 Kill（全摸完才排优先级，防判读层阶段提前砍）**。**
- **动笔前必查历史积累——"不查已有规范就自创"是反复出现的失职模式** [durable] — 来源：S003（2026-07-09 "你为啥不看之前的日志？我应该之前讨论过吧？"——重写简报没查 D-010/COMPARISON_REFS/R001）+ **S004**（2026-07-10 "你有好好看看之前开题报告咋弄的吗？写作规范文档可没少说相关的？"——写 CCISP 流程规划只做外部对标，没查 `毕设/写作质量规范.md`+`writing-patterns-*.md`+`section-outline.md` 四层开题写作规范积累；TL-31/FR-24 同型第 N 次）。**根因：接到任务后急于产出，把"类似但不完全相同"当"完全不同"跳过已有积累。防线：任何写作/规划任务动笔前，先 grep `.sessions/` + `毕设/` 找已有规范/模式/句式积累，判断哪些能复用哪些要适配，再决定要不要新建。已有积累是"类似但要适配"不是"完全不适用"。**

## 沟通方式

- **研究推进必须有少量权威入口，明确区分“在列计划 / 接口 smoke / 正式开跑 / 被阻断”** [durable] — 来源：2026-07-18 多次追问“一批跑到哪里、在做啥、地基是不是我想的、代码文档乱不乱” + D013“我不知道你在跑啥，甚至不知道有没有在跑”。执行要求：每个研究项目固定 formal、sandbox、Scout 三层入口；任何阶段切换先更新入口，不让用户通过翻 session 或猜 batch 名判断状态。
- **遇到自己不懂的技术细节，会诚实说"我不知道"，并把判断委托给主线** [durable] — 来源：2026-06-28 "1我不知道。你有找到吗？"+ "你直接继续吧。我对这块没啥了解"。用户不假装懂，会直接戳穿主线无据的断言（"你有找到吗"），委托后要求主线自推进并汇报，不要求逐个停下问。**主线应：诚实标注未验证假设 + 主动查证 + 每步汇报结果。**
- **强烈情绪信号带脏字"tm"** [observation] — 来源：D004/D005/D003 多次（"tm好难搞""tm有多少人在造垃圾""tm没按协议来"）。带"tm"通常是 frustration 信号（对颗粒无收/对跳步/对严苛标准），触发时主线应停下理解根因，不要忽视。
