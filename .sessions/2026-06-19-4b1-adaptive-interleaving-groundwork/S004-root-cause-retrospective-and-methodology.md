## 记录

### 1. 5 次死因逐个拆解（不笼统归"Cn² 窄"）

把"Cn² 跨度窄"这句笼统结论拆开。5 次失败撞的是**不同的底层假设**，只是它们落在同一个前提交集里：

| # | 方向 | 撞的底层假设 | 证据（量化） |
|---|---|---|---|
| 1 | N1 (PCS on 16-QAM) | **P1**：16-QAM 阶数够大有整形空间 | ν 搜索 18 组全选 0；AWGN 控制 MB < uniform |
| 2 | ③ (MCS 排程) | **P2**：调制参数空间够大，仰角感知有增益 | oracle 上界 0.09dB，8/12 case=0（全程最优固定=仰角感知） |
| 3 | A3 (pilot CPE) | **P3**：信道里有时变相位损伤可补 | AO 残余 τ_c~1ms（159Hz），8.2μs 序列内漂移 0.008rad ≪ pilot 估计噪声 |
| 4 | 4b#1 (自适应交织) | **P4**：突发长度分布够宽，自适应换 B 有意义 | Lburst 60-428 ≪ B=27 容量 810，0/15 仰角超容 |
| 5 | (c) (GG-LLR 译码) | **P5**：baseline 用了次优 LLR，接 GG 有信息增量 | 理想 CSI 下高斯 LLR(B2) 信息 ≥ GG 边际(B3)，B3 一致差 1.28-1.82dB |

**P1-P5 不一样**：P1/P2 撞"参数空间窄"，P3 撞"信道动态太弱"，P4 撞"突发分布窄"，P5 撞"baseline 已最优"。

### 2. 共同前提 C（5 次全中，真正"殊途同归"的归处）

5 次共享的不是某个具体假设，而是**一组上层前提**：

- **C1 信道设定 = 星地 LEO + 中弱湍流（GG，σ²_R zenith 主要 <1）**——5 次全部。唯一一次都没动过的变量。
- **C2 目标 = BER 提升**（或代理 AIR/容量）——5 次全是。
- **C3 处理层 = 单链路物理层 DSP/编码**——5 次全是。

**C1 的物理后果链**（关键，解释为什么换模块没用）：

> 中弱湍流（GG, σ²_R<1）→ 闪烁幅度小 + 突发短 + 相位动态慢 + 参数空间窄 → **同一物理事实的四个侧面同时塌掉**（P1/P2/P3/P4 全中）

换模块只是绕到这条后果链的不同侧面包抄，但 C1 设定一旦固定，它的四个物理后果**分别**封死了 PCS/排程/CPE/交织的空间。换第五个模块（译码 (c)）时撞的是 C2+C3+baseline，但同样被 C1+C2 压着——(c) 的 −1.8dB 说明：**C1 设定下即使 baseline 看似"次优"，它也已是 C1 设定下的最优**（理想 CSI 在这设定下天然可用，高斯 LLR 已最优）。

**复盘核心结论**：打转的根因**不是"模块换得不够多"，是 C1+C2+C3 这组上层前提 5 次全锁死没动**。

### 3. 三个前提的可松动性分析（哪个最有出口）

| 前提 | 物理性质 | 松动后能否打开 | 先验死结（未验） |
|---|---|---|---|
| **C1 信道设定** | 物理根因。子维度（强湍流/GEO/上行/频段）可换 | **最可能打开**——强湍流 σ²_R>1 下，闪烁大/突增长/相位快/参数空间宽，P1-P4 封死条件可能同时解除 | 强湍流星地中文硕论先例够不够（答辩风险）+ 老师认不认这场景 |
| **C2 目标=BER** | 隐含假设，从未被老师确认 | **取决于老师定义**——若"指标提升"含时延/复杂度/资源/功耗，C2 可松；R001 完全没扫过非 BER 类硕论，是真正的空白区 | **老师"指标提升"定义未量化**（H001/S003 头号债务，只能用户去问） |

### 4. 元问题诊断（"做事方式"哪里不对——方法论原料）

从 5 次失败提炼出 4 条元问题（不是"哪个方向不行"，是"我们怎么做事"）：

| # | 元问题 | 5 次中的表现 | 后果 |
|---|---|---|---|
| **M1** | **从不挑战上层前提** | C1/C2/C3 锁 5 次没动，每次只在前提内换模块 | 第 N 次必然撞同一物理后果链 |
| **M2** | **"老师指标提升"定义从未核实** | 4b#1 时延 Pivot 直接死在无先例；5 次全假设 BER | 最高杠杆的未知数却零成本零动作 |
| **M3** | **顺序反了：先选模块再验可行性** | 每次都是"假设某模块有空间 → MVE 验 → Kill" | 投入大、信号晚（要跑完 MVE 才知死） |
| **M4** | **没有"全前提空间扫描"这一步** | 5 次都是局部探索，从没系统扫过 C1×C2×C3 哪些格子打开 | 不知道剩下的空间长什么样，无法定向 |

### 5. 方法论（指导后续的做事方式）

针对 M1-M4，定 5 条纪律作为"重定方向 v2"及后续的指导方法论：

#### 方法论 R1（针对 M1+M4）：**先扫前提空间，再选模块**

任何新候选，**必须先声明它落在 C1×C2×C3 前提空间的哪个格子**。C1/C2/C3 三个前提轴：

- C1 信道设定：中弱湍流（已 5 次死）/ 强湍流低仰角 / GEO / 上行链路 / 不同频段 / 不同体制
- C2 目标：BER（已 5 次死）/ 时延 / 复杂度 / 资源 / 功耗 / 吞吐
- C3 处理层：单链路 DSP（已 5 次死）/ 单链路系统级 / 收发架构 / 帧结构

**规则**：新候选若落在"已 5 次死"的格子（中弱湍流 × BER × 单链路 DSP），**默认拒绝**，除非能论证它不撞 P1-P5 任一。这是治理级约束——重定方向 v2 专题的 session-governance skill 应把它当不变量检查。

#### 方法论 R2（针对 M2）：**"老师指标提升"定义是前置门控**

在投入任何新方向探索前，**必须先和老师确认"指标提升"到底指什么**。这是零成本（一句话）、最高杠杆（决定 C2 整条轴开或关）的动作。4b#1 已实证：假设指标=BER 的代价是一个完整方向的 Kill。

**规则**：重定方向 v2 启动后第一件事不是选方向，是用户去问老师指标定义。在此之前选方向都是赌博。

#### 方法论 R3（针对 M3）：**前置门控先于 MVE**

候选的可行性判定顺序必须是：
1. **前提空间声明**（R1）——落在哪个格子，撞不撞 P1-P5
2. **物理前提核查**（量化主导损伤 / 物理后果链是否打开）——5 分钟级纸笔/解析，不跑仿真
3. **oracle 上界门控**（FR-21 式，baseline 一手校准）——解析上界，不跑完整 MVE
4. **MVE**（前 3 步全过才到这里）

**规则**：禁止跳过 1-3 直接进 MVE。5 次里 4b#1/N1/③ 是"先 MVE 后发现物理天花板"，A3 是"MVE 参数拍脑袋后才发现"，都是 R3 违反的教训。

#### 方法论 R4（针对 M1）：**每轮探索必须显式标注"动了哪个前提"**

每个新候选/session note 必须在开头声明："本轮候选动的是 C1/C2/C3 中的哪个（哪些）轴"。如果一轮下来三个轴都没动（只换了模块），**触发警报**——这是第 N 次殊途同归的前兆。

**规则**：这是 M1 的结构性防护。session-governance skill 在写 session note 时检查这个字段。

#### 方法论 R5：**失败优先沉淀，不重蹈**

5 次失败的 P1-P5 + 物理后果链 + 4 条元问题，作为重定方向 v2 的**自动筛子**：任何新提案撞这些族，直接砍，不重新论证。

5 次已验证的死法（C1=中弱湍流下）：PCS on 16-QAM / MCS 排程 / pilot CPE / 自适应交织 / GG-LLR 译码。**这 5 个在 C1 设定下永久排除**（除非换 C1 子维度）。

### 6. 复盘对后续的具体含义

复盘不是为了"知道为什么失败"，是为了**改变后续做事方式**。直接推论：

3. **扫描结果出来后**：才在打开的格子里选模块，用 R3 前置门控范式验证。
