# [R001] 写作材料价值盘点与漏点分析

> 2026-06-14 | 关联：2026-06-14-proposal-log-distillation / D002

## 调研问题
300 个写作材料里：(1) 有什么珍贵内容 (2) 哪些容易漏 (3) 哪些可能是作废的旧方向（日期约束）

## 发现

### 扫描方法论：按"四个问题"扫，不按文件扫
带四个具体问题找答案（A 痛点 / B 标准 / C 范例 / D 流程），比"挨个读文件"漏得少。

### 七个易漏的值钱内容（按"漏了会心疼"排序）

1. **草稿版本 diff —— ⚠️ 已被用户修正（2026-06-14）**
   - 原假设：draft-s1.2-v1→v5 是最好的"原文→改后" few-shot 素材
   - 用户修正：版本演进快（大改），真正精修打磨在**一个版本内部微调**（很可能未存独立文件，已丢）。版本间 diff 捕捉大改不是精修，当 few-shot 质量存疑
   - **C 维度素材来源调整**：草稿 diff → 改为 **导师批注前后对比 + ai-trace 标注点 + writing-patterns 正反例**（这些才是细粒度改写证据）

2. **导师批注背后的元标准**（开题报告v2-导师批注.md / 开题报告v2-带批注提取.md）
   - 字面是改句子，背后是学术写作潜规则（如删过渡句=不许凑字数填充）
   - 防：只抄批注字面，漏掉背后的评判逻辑（元标准才是 B 维度真东西）

3. **ai-trace-report.md（209行）**：自检开题报告 AI 痕迹，A 痛点硬证据 + 直接对应 paper-eval AI 痕迹检测器
   - 防：小文件、名字不起眼，被当普通日志一扫而过

4. **PROMPT + H + S 三件套必须配对读**：孤立读拆散来龙去脉（PROMPT=任务，S=讨论过程，H=交接结论）
   - 防：子 agent 一个文件一个文件孤立读，把三件套拆散

5. **writing-patterns 反面例子**：写作规范里"别这样写"的部分 = A 痛点 + paper-eval 检测器弹药
   - 防：子 agent 只摘正面范例（好摘好看），漏反面

6. **口述稿 + defense-principles（开题PPT/）**：答辩"怎么把研究讲清楚"的逻辑 = B 维度来源
   - 防：在 开题PPT/ 目录，被当"PPT 附属"忽略

7. **thesis-lessons.md（26.5K，根目录散落）**：跨专题血泪教训，可能混写作相关
   - 防：根目录散落，最容易忘

### 日期/方向约束（用户强调：别把旧的当真理）
- 论文方向 **2026-05-29 pivot 到激光通信**（thesis-direction-pivot 专题起；信道建模→预均衡→同步）
- 2026-05-29 前的旧方向（路由/GNN）材料 = 可能作废，不当素材
- 扫描范围已限在 pivot 后专题（direction-pivot / writing-prep / advisor-revision / writing + 毕设/），旧方向专题（thesis-final-review / _archive 路由GNN 项目）不在范围
- 子 agent 对每材料标日期/方向，pivot 前的标"可能作废"

## 结论
1. **两阶段实读**：先粗扫一遍（实际读但快，目的=发现全貌+意外，不是精细提取）→ 再 pilot 精细验证模板 → 放大全量。粗扫≠文件名偷懒（用户已否决偷懒），粗扫是全量实读的第一遍
2. **C 维度素材来源调整**（见发现1）：草稿 diff → 导师批注对比 + ai-trace + 正反例
3. **日期约束**：pivot（2026-05-29）前的材料标"可能作废"

## 对决策的影响
- pilot 挑选策略：故意挑能验证漏点的（一份导师批注 + ai-trace + 一组 PROMPT/H/S 三件套 + 一份 writing-patterns 看能否挖反面）
- C 维度产出落点（D002）不变（→ S033 few-shot），但素材来源从草稿 diff 调整为批注/trace/正反例
- 粗扫子 agent 必须实际读内容（快速过 ≠ 不读），带四个问题 + 七漏点 + 日期约束
