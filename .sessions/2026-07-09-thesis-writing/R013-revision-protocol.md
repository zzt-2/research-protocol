# [R013] 改稿影响传播章程

> 2026-07-12 | 关联：专题 2026-07-09-thesis-writing / 写作战役完成后投稿准备阶段
> 用途：导师/审稿人反馈后，改一处牵一片，按本章程一次改完不出错
> 触发：每次收到反馈时先读本章程，按流程执行

## 调研问题

导师/审稿人反馈后怎么改稿？改一处牵一片（改个数字要跨五处正文，改个公式要动 R011 三表，改逻辑链要重写多节），现想必然出错（D004 口径方向踩三次就是因为没清单凭印象改）。怎么提前定好流程，让每次改稿一次改完、不返工、不遗漏？

## 核心纪律：攒全了再走流程（批次化）

**改稿流程有固定开销**（grep 列清单、交叉检查、记录）。每来一条反馈就开一轮流程，开销太重。必须**攒全了再批量走**。

### 问题登记（收到反馈先登记，不立即改）

每收到一条反馈，登记到 `revision-queue.md`（本专题下），**不动正文**：

```
| # | 来源（导师原话→voice.md）| 内容（要改什么）| 初判级别 | 状态 |
|---|---|---|---|---|
| Q1 | voice.md 2026-07-15 | 纵轴画到 1e-5 | L2 | pending |
| Q2 | voice.md 2026-07-15 | crossover 左移要解释 | L5 | pending |
```

登记时只做初判（大概几级），不做详细分析。详细分析留到批次处理时。

### 批次触发条件（满足任一即开流程）

1. 导师明确说"反馈完了" / "就这些" / "这是最后一轮"
2. 攒到 **≥3 条**实质性反馈（措辞 typo 不算）
3. 距投稿 deadline 倒推**只剩改稿+转 LaTeX 的时间**（无缓冲）
4. 用户主动决定"够了，开改"

**反面教训**：来一条改一条 = 每次都重新 grep + 重新交叉检查 + 重新读上下文，同样的事做 N 遍。D004 口径方向踩三次，部分原因就是零散处理没整体校验。

### 批次处理顺序（从底层到表层）

一次批次内多条改动，**按影响层级从底到顶执行**——底层变了表层要跟着改，先改表层再改底层 = 表层白改：

```
L6 定位/贡献（回 step4a，不出本章程）
  ↓
L5 逻辑链（R009）→ 重估 R012 大纲 → 重估受影响节
  ↓
L4 公式（R011 公式清单+符号表+术语表）
  ↓
L2 数字/口径（R012 数字清单）+ L3 图表（F2 规格）
  ↓
L1 措辞/句式（正文局部）
  ↓
统一交叉检查（一次做完，不每条做）
```

**同级别合并**：多条 L1 措辞可以一次 grep 一起改；多条 L2 数字可以列一张总清单一次改完。

## 六级改动分类

| 级别 | 类型 | 典型触发 | 影响范围 | 决策在哪 |
|---|---|---|---|---|
| L1 | 措辞/句式 | typo、口语化、句式优化 | 局部 1-2 句，可能跨节 grep | session note |
| L2 | 数字/口径 | 导师定 fair/naive、纵轴范围 | 跨四-五处正文 + Tab.1 + 脚注 | session note（含 D### 如涉及口径方向）|
| L3 | 图表 | 某 Fig 论点/画法变 | 图规格 + 正文引用段 | session note |
| L4 | 公式增删改 | 加推导、删公式、公式形式变 | R011 三表 + 正文多节 + 编号 + 交叉引用 | **decisions.md D###** |
| L5 | 逻辑链 | 导师要求解释 crossover 左移 | R009 → R012 → 可能多节重写 + 不变量回查 | **decisions.md D###** |
| L6 | 定位/贡献 | 换主卖点、推翻切换 framing | 几乎全文 | **回 GW step4a，不出本章程** |

**L4 以上是架构级**——动 R011/不变量，必须建 D### 记录，不能只在 session note 里改。

## 每级 checklist（一次改完清单）

### L1 措辞级

- [ ] 定改动点（哪句哪个词）
- [ ] grep 全篇该词/短语所有出现位置
- [ ] 逐处替换（不能只改一处）
- [ ] 查替换后不引入新自造词（查 R011 术语表）
- [ ] 记录旧文本（可回退）

### L2 数字/口径级（最高频失误区，D004 同型）

- [ ] **先定口径**：新数字什么口径（naive/fair/data/net）？**用代码行验证加减方向**（读 fair_comparison.py:109 或对应脚本，不凭字段名/印象——这是 D004 教训的核心）
- [ ] **列受影响处清单**（grep 数字值 + grep 口径标注）：
  - Intro 贡献句 / Method（如有）/ Results §IV-B / Conclusion / Abstract / Tab.1 / 脚注模板
- [ ] 逐处改，**数字值 + 口径标注同步改**（不能只改数字不改标注）
- [ ] grep 验证新数字四处一致
- [ ] grep 旧数字无残留
- [ ] 记录口径决策（涉及方向变更建 D###，引用 voice.md 导师原话）

### L3 图表级

- [ ] 定新论点（这张图现在表达什么）
- [ ] 查正文所有引用该图的段（"as shown in Fig. X"）——论点变引用段也要改
- [ ] 改 F2 规格表对应项
- [ ] 查是否跟其他图/表信息冗余
- [ ] 图数/表数仍在 R010 范围（4-6 图 + 0-2 表）
- [ ] 记录

### L4 公式级（增/删/改公式）

- [ ] 定改动：增 / 删 / 改
- [ ] **查 R011 公式清单**——增删后同步更新
- [ ] **查 R011 符号表**——新公式引入新符号？符号冲突？
- [ ] **查 R011 术语表**——新公式需新术语定义？
- [ ] **公式编号重排**——删中间公式后面编号挪；增公式插哪号
- [ ] **查正文所有引用编号处**（"as in (2)"）——编号变引用也变
- [ ] 查粒度仍对齐 R010（直接给 vs 推导）——导师要加推导是力度变化，R010 §2.3 基准同步
- [ ] 建 D### 记录

### L5 逻辑链级（R009 某段变）

- [ ] **先回 R009 定稿原则**——这段变有把握吗？（R009 原则：只放有把握内容，没把握不写）
- [ ] **查 R009→R012 传导**——逻辑链变→5 节大纲分配可能变→正文可能重写
- [ ] 列受影响节清单（可能不止一节）
- [ ] 逐节评估：受影响吗？怎么改？改多少？
- [ ] 改正文 + grep 数字/术语/framing 一致
- [ ] **查不变量**——是否触动不变量 5/6/7（deep fade / 黑话 / crossover 只呈现数据）？触动要重新讨论（不动手，先讨论）
- [ ] 建 D###（逻辑链变更是架构级决策）

### L6 定位/贡献级

- [ ] **这不是改稿，是回 GW Step 4a**（FR-22）——定位推翻 = 研究方向调整
- [ ] 回 step4a 专题讨论：新定位是什么？数据支撑吗？
- [ ] 可能触发：重新走 P3（叙事结构）→ W1-W5 重写
- [ ] **不动正文，先回框架讨论**

## 通用流程（每个批次走一遍）

```
1. 攒问题 → revision-queue.md 登记（不立即改）
2. 批次触发 → 读 queue 所有 pending 项
3. 一次性分级 → 每条定 L1-L6
4. 排序 → 从底层到表层（L6→L5→L4→L2/L3→L1），同级别合并
5. 执行 → 按各级 checklist 改
6. 统一验证 → grep 数字/术语/framing 一致 + 交叉检查 + 更新 queue 状态
7. 记录 → session note（L1-L3）/ decisions.md D###（L4-L5）/ 回 step4a（L6）
```

## 三条防错纪律（最高频踩坑）

**1. 改前先列清单，不直接动手**
任何 L2 以上改动，第一步 grep 列出所有受影响处，列成 checklist，再逐处改。D004 踩三次就是因为没列清单凭印象改。

**2. 数字改动必须用代码行验证口径**
报任何"已扣/净值/含水分"口径，改前读对应脚本代码行确认加减方向。不凭字段名（"fair"不一定是"公平"）、不凭印象、不凭"上次查过"。这条单独列因为它是本项目最高频失误（D004 三次 + R003§B 一次）。

**3. L4 以上回查 R011 + 不变量**
公式增删触动术语/符号表（L4）；逻辑链变动触动不变量 5/6/7（L5）。这两级改完必须回查 R011 三表交叉一致性 + topic-index 不变量段落，不能只改正文。

## 结论

改稿章程定稿。核心是**批次化**（攒全了再走流程）+ **六级分级**（按影响范围定 checklist）+ **从底层到表层排序**（避免返工）+ **三条防错纪律**（列清单/验口径/回查 R011）。
