## 调研问题

外部 repo [HKUSTDial/Supervisor-Skills](https://github.com/HKUSTDial/Supervisor-Skills)（港科广骆昱宇，博导十年经验封装成 AI Skills）的"找 idea / 找问题"方法论是什么？与我们的"批评汇总 + 假设审计 + 问题四判据"对照，哪里比我们成熟、哪里不如我们、哪里可启发？

## 发现

### A. 它的核心方法（handbook 02_Idea_Generation 三阶）

1. **渐进式创新 — 五维框架**（2.2，主力）：拿现有最好的 Baseline，沿 5 正交维度问"它哪里不够"——更高(效果)/更快(效率)/更强(鲁棒)/更省(成本)/更广(跨界)。每维有 canonical 切入点策略（如"更高"含信息模态补全/反馈驱动/错误根因分析）。
2. **颠覆式创新 — 四思维范式**（2.3，进阶）：第一性原理（打破隐含假设）/ 房间里的大象（社区回避的硬骨头）/ 技术周期前瞻（新硬件新介质）/ Hamming 法则（常备 10-20 个重要问题）。
3. **能力×生命周期匹配**（2.1，执行约束）：六类 idea × 学生画像（工时/技能/算力/理论vs应用偏好），匹配不上 = 能执行也赶不上 lifecycle。

### B. idea-evaluator skill 的工程化（最成熟部分）

8 步流程，**次序不能换**：
1. **致命缺陷审计（早期闸门）**：10 个致命缺陷 F1-F10，每个带"检测规则 + 红旗信号 + 防御策略"，按 CRITICAL/MAJOR/MINOR 分级。**CRITICAL 短路规则：直接跳过打分输出 Reject。**
   - F1 无新意 / F2 venue 不匹配 / F3 baseline 非真实 / F4 无动机 / F5 能力不匹配 / F6 不可验证 / F7 伦理数据阻塞 / F8 scope 过载 / **F9 solution hunting（拿方法找问题）** / F10 不考虑失败 case
2. 生命周期×能力匹配
3. 五维打分（1-10，每维带证据，强 idea 一维 8+ 主导 + 另一维 6+ 支撑）
4. 范式跃迁探针（4 问，非门控）
- **Integrity gate（7 条 inspection）**：打分必须引具体证据（禁 gut feeling）、novelty 声称要么引 prior work 要么标 unverified、verdict 与打分必须一致……

### C. 与我们方法论的关键对照（仅记录，不在本轮应用）

| 维度 | 它的做法 | 我们的做法 | 性质 |
|---|---|---|---|
| 找切入点 | 5 维操作 checklist | 四判据定义层（M-C-A） | **互补不竞争**：5 维是操作层，四判据是定义层 |
| 防 solution hunting | F9 致命缺陷 + 可检测红旗 | FR-22 + FR-23 | 方向一致 |

## 结论

技术判断：Supervisor-Skills 在 **"idea 质量评估的工程化"**（致命缺陷表 + 短路 + integrity gate）和 **"找切入点操作层"**（5 维）上比我们成熟。但其方法论是"已有 baseline → 找改进点"的**渐进式导向**，与我们"找空白→转译成 M-C-A 问题"的**诊断失效定位**不同——两者可拼成链路，但"拼成链路"是未来设计，不是现在执行。

## 元层发现（本笔记比技术内容更重要的部分）

本次调研触发了**方法论验证期的第一次外部诱惑压力测试**。关键洞察：

> **5 维框架就是这次的 DPLL**——"看到外部框架看起来更成熟就搬进来补我的洞"，与 thesis-fso 的"看到空白就填"，**是同一根源（对自有方法没有定力）的第二层变体**。第一层（标题联想找空白）好识别，第二层（外部框架看起来更成熟）极难识别，因为技术判断确实是对的，反驳它需要的是元纪律不是技术论证。

这暴露了我们方法论的一个潜在脆弱性：**我们太容易"看到更好的就换"**。建议在 `2026-06-20-problem-driven-redirection` 专题的 decisions.md 或 S001 纪律段补一条不变量（本笔记不代写，留给主对话决定措辞）：

> **方法论验证期免疫原则**（候选措辞）：自创方法论在第一轮完整验证产出结果之前，任何外部"看起来更成熟/更完整"的方法只能进"待激活对照库"（如本 R001），不能进执行路径。违反信号 = 在本轮目标未完成时开始讨论"要不要把外部方法引入 framework"。

本次（Supervisor-Skills）是该原则的第一个测试用例。扛住它 = 方法论多一层韧性；没扛住 = 方法论本身经不起实战。
