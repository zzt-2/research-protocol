## 1.3 坏模式检测清单（25 项）

### 核心理念：逆向评估

不评"好"，只检测"坏"。坏模式比好质量更容易可靠检测。

| 维度 | 评"好"（正向） | 检测"坏"（逆向） |
|------|---------------|-----------------|
| 评分范围 | A+到D，8档，需校准 | 有/无，二值判断 |
| LLM偏差 | 压缩到B-/B（区间窄） | 倾向判"有"（宁可误报） |
| 可解释性 | "综合B-"—无法定位 | "命中6个坏模式"—具体明确 |
| 代码可行性 | 多数需LLM | 大量可正则检测 |

### A 层：结构坏模式（9 项，regex/code 可检测）

| 编号 | 名称 | 描述 | 可靠度 | 本科常见度 |
|------|------|------|--------|-----------|
| A1 | 无独立方法章 | 方法仅在绪论一笔带过 | 高 | 30-40% |
| A2 | 摘要-结论高度重复 | TF-IDF cosine > 0.7 | 高 | 40-50% |
| A3 | 分析章篇幅占比过低 | 核心分析章节字数 < 30% | 高 | 25-35% |
| A4 | 建议章无数据/表格引用 | 建议章节不出现任何数据引用 | 高 | 50-60% |
| A5 | 纯二手数据表 | 所有表格均为公开数据摘录 | 高 | 20-30% |
| A6 | 结论超越正文范围 | 结论中提出正文未讨论的新概念 | 中高 | 15-25% |
| A7 | 无统计关键词 | 全文无基础统计术语 | 高 | 20-30% |
| A8 | 参考文献全为近邻领域 | 所有文献来自同一极窄子领域 | 中高 | 40-50% |
| A9 | 章节标题完全对仗无分析 | 问题章和对策章标题一一映射 | 中 | 30-40% |

### B 层：内容坏模式（8 项）

| 编号 | 名称 | 描述 | 可靠度 | 本科常见度 |
|------|------|------|--------|-----------|

### 对学位论文开题报告的适用性

A层（结构检测）对我们完全适用，可用作自检：
- A1: 确保有独立的研究方法/方案章节
- A2: 避免摘要与结论高度重复
- A3: 确保研究内容章节篇幅充足
- A4: 建议部分引用前文数据
- A6: 结论不超出正文范围
- A7: 包含必要的统计/量化分析
- A9: 避免"问题→对策"机械对仗

B层和C层对学位论文也适用：
- B1: 确保分析性表达多于描述性
- B3: 确保理论框架术语在分析中被使用
- B6: 引用标注密度充足
- C4: 文献综述要有比较归纳而非纯罗列
- C7: 明确提出研究问题或假设

## 1.4 语义评估层（S029）

### 章节分类（6种通用类型）

| 类型 | 典型标题 | 覆盖rubric |
|------|---------|------------|
| intro | 绪论/引言/研究背景 | R1 |
| literature | 文献综述/研究现状/理论基础 | R2 |
| methodology | 研究方法/研究设计/实验设计 | R3 |
| analysis | 现状/问题/实证/数据分析 | R4,R5,R6,R9 |
| recommendation | 对策/建议/改进/优化/策略 | R7,R8,R9 |
| conclusion | 结论/结语/总结 | R10,R12 |

### Layer 1 检测（3项，纯代码，0 API）

A4（建议无数据引用）、A5（纯二手数据表）、A9（对仗标题）

### Layer 2 LLM Rubric（11项）

| # | 子问题 | 适用章节 | 区分力 |
|---|--------|---------|--------|
| R1 | 绪论是否列出3+个具体研究问题？ | intro | 高 |
| R2 | 文献综述是否有比较/归纳/批判？ | literature | 高 |
| R3 | 研究方法是否描述了具体操作步骤？ | methodology | 中高 |
| R4 | 数据呈现后是否有分析性解读句？ | analysis | **高（核心）** |
| R5 | 论据→结论之间是否有明确推理链？ | analysis | **高（核心）** |
| R6 | 分析中是否使用了理论框架术语？ | analysis | 中高 |
| R7 | 对策是否展开到2+层具体措施？ | recommendation | **高** |
| R8 | 对策是否引用前文数据/发现？ | recommendation | 高 |
| R9 | 论证是否针对具体研究对象？ | analysis/recommendation | 中高 |
| R10 | 结论是否未引入新论点？ | conclusion | 中 |
| R11 | 相邻章节是否存在大段内容重复？ | 全文 | **代码n-gram** |
| R12 | 是否有方法论相关的具体研究局限？ | conclusion | 中 |

### 聚合：加权Y率

- 章节权重：analysis=3, recommendation=2, methodology=2, intro/literature/conclusion=1
- 问题权重：R4/R5=2, R7/R8/R9/R6/R3=1.5, 其余=1
- NA排除，不参与分子分母
- 映射：≥0.70合格 / 0.40-0.70需修改 / <0.40不合格

### 关键不变量

1. **regex不能检测"内容浅薄"**：A+B层16项检测器天花板已到
2. **LLM不能做自由评分者**：5种prompt策略全部失败
3. **章节隔离是LLM评估的必要条件**：P3全文输入拿了6/6满分

## 1.5 内容脚手架（S030）

### 5步管线

1. **评估** → soft_metrics.json
2. **DELETE** → 删虚假声称（纯规则，0 API）
3. **分析**（约束提取+缺口映射）→ 1次LLM

## 1.6 十五个质量指标等级标准

| 指标 | A级 | B级 | C级 | D级 |
|------|-----|-----|-----|-----|
| 结构完整性 | 全部要素齐全，位置合理，衔接自然 | 主要要素齐全，个别被合理合并 | 有外形但缺1-2个关键要素 | 缺3个以上核心要素 |
| 引文质量 | 来源多元含核心期刊，深度参与论证 | 基本多元，核心期刊<30%，部分转述 | 来源单一，核心期刊<15% | 数量极少，核心期刊<10% |
| 论据支撑度 | 每个论点充分论据，类型多样，推理链完整 | 大部分论点有支撑，个别单薄 | 多个论点缺乏支撑，类型单一 | 超半数论点无支撑 |
| 研究过程完整性 | 全过程完整呈现，方法独立成章 | 主要环节齐全，个别简略 | 缺1-2个关键环节，过程不透明 | 多个环节严重缺失 |
| 格式合规性 | 全部要素高度一致 | 主体基本一致，个别疏漏 | 格式问题较多 | 3类以上不合规 |
| 结论呼应度 | 每个问题都有明确回应 | 大部分得到回应 | 多个问题未被回应 | 半数问题未回应 |
| 选题新颖性 | 关键词组合稀缺度高，识别研究空白 | 常规领域但场景/数据有变化 | 沿用常见题目，创新点不清晰 | 完全照搬已有课题 |
| 逻辑连贯度 | 章节逻辑递进清晰，段落有过渡 | 整体清晰，个别衔接生硬 | 推进不够清晰，缺少过渡 | 逻辑混乱，衔接缺失 |
| 内容充实度 | 字数达标，信息密度高 | 字数达标，空洞15-25% | 刚达标，空洞>30% | 字数不足，有效<50% |
| 选题范围适当性 | 工作量≥95%，难度适中偏上 | 工作量≥85%，难度适中 | 工作量≥75%，难度偏低 | 工作量<65% |
| 术语使用规范性 | 术语密度适当，有界定，准确统一 | 总体规范，偶有不够精确 | 密度偏低，存在误用 | 几乎不使用专业术语 |
| 文献新近度 | 近3-5年文献占比高，有近两年 | 有部分近几年文献 | 近期占比偏低 | 近5年<20% |
| 文题一致性 | 每个核心概念充分展开 | 大部分围绕标题 | 对应关系较弱 | 2个以上概念未展开 |
| 选题价值 | 紧密结合实际，价值明确 | 能结合实际，有应用价值 | 结合不够紧密 | 脱离实际，缺乏价值 |
| 写作规范性 | 行文顺畅，段落清楚，句长得当 | 大部分清楚，个别堆积 | 不少段落堆叠，句过长 | 缺乏条理，长句>40% |

### 写作自检要点

**选题阶段**：
- [ ] 关键词组合在文献库中是否具有稀缺性？
- [ ] 是否明确了与同类研究的差异化切口？
- [ ] 工作量是否饱满？研究边界是否清晰？

**文献综述阶段**：
- [ ] 参考文献是否覆盖多种来源类型？
- [ ] 是否包含本领域核心期刊和高被引文献？
- [ ] 引用是否深度参与论证而非罗列？

**研究设计阶段**：
- [ ] 是否有独立的方法/方案章节？
- [ ] 是否说明了方法选择的理由？
- [ ] 实施过程描述是否充分透明？

**写作论证阶段**：
- [ ] 关键术语首次出现时是否有明确界定？
- [ ] 句子长度是否控制得当？
- [ ] 每段是否有明确主题句？

**结论阶段**：
- [ ] 每个研究问题是否在结论中都得到了回应？
- [ ] 结论是否超越正文范围？

## 1.7 管线实现概要

### 5步Pipeline

1. **Step 0 分类**（classify.py）：LLM调用，论文类型+学科+参考文献提取
2. **Step 1 硬指标**（hard_metrics.py）：纯Python正则，参考文献数/字数/格式合规率
3. **Step 2 软指标**（soft_metrics.py）：LLM单次调用评估Layer 1+2+3，含token预算管理
4. **Step 3 评分汇总**（scoring.py）：纯Python，Grade→Score→维度加权→TQI
5. **Step 4 报告生成**（report.py）：LLM+Jinja2，综合报告+要素报告

### Token预算

- 总预算：100,000字符
- 固定预算：7,000字符（指令+硬指标+分类）
- 论文预算：60,000字符（按章节边界截断）
- 指标预算：33,000字符（按优先级动态加载）

## 2.3 架构设计哲学

### 薄编排层原则

Prompt模板应该是薄的编排层，而非格式定义层：
- **职责**：角色定义+任务声明+文件命名+写入目录
- **格式来源**：由注入的文档库文档决定
- **document-driven核心**：改文档改行为，不需要改模板

### 首次实跑失败根因链

```
CS域规则不适用通信论文
  → 关键误导条款（benchmark数据集名称、GPU+深度学习框架）
    → Blueprint未规划公式数量
      → Outline缺少"公式与推导规划"
        → Write无目标可循，公式仅7个（vs典型25-45个）
          → Review缺"公式充分性"维度
            → 修订不修公式→循环不收敛
```

### 关键教训

1. **架构vs实现要分清**：经过8轮密集讨论的三层架构没问题，问题在实现
2. **Postmortem建议不能脱离框架**：建独立规则文档与DCW稀疏矩阵冲突
3. **Prompt模板不硬编码格式**：内容按文档库格式产出，模板只编排

### 骨架提取器规则

- 频率阈值：≥60%样本→required: true
- 比例取中位数
- 变异单独记录（频率20-60%）
- 只记结构不记内容

- 只提取可观察的失误，每条必须有具体表现

- 从正例提取，每条必须附实际片段

- 优先提取跨章节的论证链模式

### 约束提取器规则

- 只提取硬性约束，可判定对错
- 标注可检测性
- 区分来源权威性：期刊官方>写作指南>观察推测

## 3.4 文档维护管线（doc-maintain）

### 完整工作流（7步）

```
M1 验收试建产出
  → M2 审查产出（内外双轨）
  → M3 问题归类与映射（4维：类型/阶段/章节/严重度）
  → M4 定位文档与已有规则覆盖
  → M5 修改文档
  → M6 重跑验证
  → M7 回写决策
```

### M2 双轨审查

**内轨**：规则效果检查（合规率、虚假合规、规则冲突、规则缺失）
**外轨**：质量基准检查（AI写作痕迹、缺失写法、领域惯例、读者体验）

### M4 排除性证据要求

判定"没有对应规则"时必须：
1. 列出最相关的1-2条已有条目，说明约束的是X而非本问题的Y
2. 回查DCW extractions确认提取结果中也无对应素材
3. 如果已有条目部分覆盖，重新归为"增强已有规则"

### M5 修改约束

- 每次最多修改5条规则
- 翻转检测：修改前检查方向相反的历史修改
- 已验证规则保护：已通过M6验证的不能删除
- 加一删一：每次添加时寻找可删除或合并的

### 核心教训

- **压测实际产物而非规则文本**：必须通过实际产出验证规则效果
- **闭门造车会进入自证循环**：需要外轨对照真实论文
- **补完不验证是核心陷阱**：不允许只修改文档不验证效果

## 4.1 34篇论文综合分析

### 三种"3章结构"模式

| 模式 | 占比 | 特点 | 对我们的适用性 |
|------|------|------|---------------|
| 问题分解型 | ~40% | 大方向拆成多个独立子问题 | 中 |
| 层次递进型 | ~30% | 前一章结果被后一章使用 | **最优** |
| 场景拓展型 | ~20% | 同一框架在不同约束下求解 | 中 |

### 8条跨论文共性发现

1. 章间衔接：章首递进回顾效果最佳（曹阳典范）
2. 系统模型共享：做到的论文整体感显著更强
3. 方法论统一：统一方法框架是最强"粘合剂"
4. 每章独立性：34篇全部做到独立可发表
5. 绪论结构图是标配（~70%有）
6. "基础模型章"是可选但有效的策略
7. 层次递进型>问题分解型>场景拓展型
8. Top6参考：曹阳、张乐、姬思敬、王鹏、杨竞凯、金骥丰

### 方案A（路由+切换+抗毁）评级

- 获评5星
- 3章形成"正常态→优化态→异常态"递进
- 每章可独立发表
- 共享统一的LEO星座拓扑和ISL模型

### "互相关联"最低标准

共享系统模型+至少一个共享的方法/技术
我们的GNN+DRL统一框架+同一LEO星座模型可达到最高标准

| 中 | provide (theory) | 提供理论分析 | 理论贡献 |
| 中 | investigate/evaluate | 研究/评估 | 实证贡献 |
| 弱 | demonstrate/show | 证明/表明 | 实验结果 |
| 弱 | leverage/incorporate | 利用/融入 | 借用已有方法 |
| 弱 | apply/use | 应用/使用 | 方法迁移 |

### 局限性写作规范

标准结构：**性质→原因→影响→改进方向**

每条局限含四要素：
1. 性质：仿真假设/模型简化/规模限制/方法边界
2. 原因：为什么做这个选择
3. 影响：对结论适用范围有何限制
4. 改进方向：未来可以如何缓解

### 贡献声称降级模板（Before→After）

| 反模式 | 正确写法 |
|--------|---------|
| "本文创新性地提出了基于GNN的路由算法" | "本文针对LEO卫星网络路由场景，设计并验证了基于GNN的路由方案" |
| "本文提出了一种全新的DRL切换框架" | "本文在已有DRL框架基础上，针对LEO切换场景进行了系统性适配和验证" |
| "首次将GNN应用于LEO卫星网络" | "据作者所知，本文首次在[具体条件]下系统评估了GNN在LEO网络中的表现" |
| "本文提出了二部图GNN建模方法" | "本文采用UE-卫星二部图作为GNN输入，利用图消息传递捕获关联关系" |

### 局限性分析示例

- 规模退化："720节点（10.9×跨度）零样本泛化退化，表明跨度过大时需分阶段迁移"
- 方法边界："集中式DRL在超大规模场景下的推理延迟可能成为瓶颈，分布式方案是未来方向"
- 假设局限："M/M/1排队模型假设泊松到达和指数服务时间，与实际流量突发模式存在差距"

## 4.3 三章贡献定位策略

### 第1章（路由）—— 规模不变性

- 贡献类型：场景适配+实证验证
- 适合动词：evaluate, demonstrate, apply
- 不应使用：invent, pioneer
- 定位：基础路由的跨规模部署，正常态，离线规划，监督学习

### 第2章（切换）—— 规模适应性

- 贡献类型：问题建模+架构设计
- 适合动词：formulate, design, investigate
- 不应使用：create, discover
- 定位：用户接入切换的跨规模扩展，接入层，在线DRL，UE数泛化

### 第3章（故障弹性）—— 故障弹性

- 贡献类型：场景拓展+系统评估
- 适合动词：evaluate, show, leverage
- 不应使用：originate, devise
- 定位：故障弹性路由的跨规模在线决策，异常态，在线DRL，故障感知

### 章间过渡句式（参照曹阳模式）

- Ch2开头："上一章验证了GNN在LEO路由场景中的有效性，但路由优化仅覆盖离线规划层面。在线接入决策面临..."
- Ch3开头："前两章分别研究了正常运营下的路由和接入优化。然而，卫星网络固有的故障风险要求路由方案具备弹性能力..."

## 5.3 写作时应避开的反模式

### 来自评估管线的坏模式（选适用于学位论文的）

1. **A2 摘要-结论重复**：开题报告的总结与各章摘要应避免高度重复
2. **A3 核心内容篇幅不足**：研究方案和技术路线应占主体
3. **B1 描述>分析**：应确保分析性表达多于描述性
4. **B3 理论术语消失**：理论框架中引入的术语应在方案中被使用
5. **B6 引用稀疏**：引用标注密度应充足（≥每千字1次）
6. **C4 文献综述纯罗列**：必须有比较/归纳/批判
7. **C7 无研究问题**：必须明确提出可回答的研究问题

### 来自写作管线的反模式

1. **贡献声称过度**：不自夸"创新性""全新""首次"
2. **公式规划缺失**：每章公式数量应提前规划
3. **贡献边界模糊**：各章贡献声明应清晰独立
4. **论证重复**：避免不同章节重复相同的论证

### 来自贡献声称规范的反模式

1. ❌ "本文创新性地提出了..." → ✅ "本文针对X场景，设计并验证了..."
2. ❌ "本文提出了一种全新的..." → ✅ "本文在已有框架基础上，进行了系统性适配..."
3. ❌ "首次将X应用于Y" → ✅ "据作者所知，首次在[具体条件]下系统评估了..."
