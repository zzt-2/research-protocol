# [S017] 开题报告提示词调优日志

> 2026-05-27 ~ 2026-05-28 | Phase 7 续 | 进行中

## 目标

记录开题报告写作提示词（PROMPT-001）从 v1 到 v3 的迭代调优过程，包括每轮发现的问题、改进措施和经验教训。供后续类似写作任务参考。

## 背景

开题报告写作提示词的目标：指导 LLM 逐节撰写硕士学位论文开题报告正文（13000-16000 字），要求学术规范、无 AI 味、引用准确、论述充实。

核心挑战：LLM 默认输出存在系统性问题——AI 推销腔、翻译腔、逐篇罗列文献、技术参数堆砌等，纯靠"不要这样做"的否定规则无法完全消除，需要肯定性示范（few-shot）+ 具体规则 + 自查机制三管齐下。

## 调优时间线

### v1：初始版本（2026-05-27 上午）

**设计思路**：基础规则 + 约束文档引用 + 写作流程

**内容**：
- 引用格式要求（pandoc-crossref `[@citekey]`）
- 术语规范（首现全称+英文+缩写）
- 反 AI 味清单（推销性/绝对化/模糊化/元叙述/自我声称）
- 段落纪律和论证纪律
- 核心叙事线和字数分配
- 逐节写作流程

**测试结果**：完全不合格
- 引用格式错误（用了 `[Author, Year]` 而非 `[@citekey]`）
- 没有写入文件，直接在对话中输出
- AI 味十足，基本规则全未遵守
- 参考文献手搓而非用 .bib 文件

**诊断**：规则太抽象，模型没有具体参照。"不要 AI 味"没有告诉模型"好的学术中文是什么样的"。

### v2：加入写作基底约束（2026-05-27 下午）

**设计思路**：读取写作基底文档（`通用写作基底.md`），将核心约束硬编码进提示词

**新增内容**：
- 文件输出硬要求（写入 `开题报告.md`）
- `.bib` 文件机制说明
- 核心叙事线细化（"探索性分化"框架）
- 贡献定位三档（系统性验证/规模适应性实证/故障弹性实证）

**测试结果**：仍然很差
- AI 推销词大量出现（"关键使能技术""广泛应用""快速增长"）
- 引用位置不对（`[@key]` 紧跟人名而非论断末尾）
- 文献综述变成逐篇罗列
- 方法描述像产品规格书
- 研究意义段引用了未做实验的结果

**诊断**：模型理解了格式要求但缺乏"好写法"的具体参照。需要 few-shot 示范段落。

#### 改进 2：引用格式正误对照

新增引用格式的❌/✅对照，包括：
- 逐篇罗列 vs 按方法归类整合
- "据文献XX所述"（元叙述）vs 直接在论断后标引用
- "广泛应用[@refs]"（引用做装饰）vs 引用支撑具体论断

#### 改进 3：引用位置规则
- 引用放在具体论断之后，不放在段落末尾堆积
- 一句内多个论断各自标引用
- 多篇支撑同一论断合并为 `[@a; @b; @c]`

#### 改进 4：研究意义段特殊规则
- 禁止引用 MVE 实验结果（91.5%、21.2% 等）
- 这些数据属于第七节"研究基础"

#### 改进 5：禁止词自查机制
- 列出所有禁止词，要求每节写完后搜索确认
- 命中即不合格

**测试结果**（第一节）：明显改善，但仍有问题
- 引用格式正确了 ✅
- 文献综述按方向分组了 ✅
- 有具体数据了 ✅
- AI 推销词残留（"关键使能技术""广泛应用"出现 2 次）
- 引用紧跟人名（"Shen 等人[@key]从理论上证明了"）
- 研究意义段引用了 MVE 结果

### v3 第二轮：引用位置 + 节间引导 + 翻译腔（2026-05-28）

**用户反馈**：
1. "参考文献引用有些地方怎么啥也没有"——引用密度不够
2. "不少地方的引用很生硬"——引用位置不对
3. "人名也没分出来"——人名后面直接跟引用
4. "国内外一般是分开的？"——国内外文献组织方式

#### 改进 6：引用密度下限

- 文献综述：每千字至少 5 次引用
- 背景意义：每千字至少 3 次引用
- 每个段落必须有引用，无引用段落视为不合格

#### 改进 7：作者名称与引用位置惯例（关键修正）

**核心修正**：之前提示词示范写的是 `Shen 等人[@key]从理论上证明了...`（引用紧跟人名），导致模型全部照搬。

改为：
- ❌ "Shen 等人[@key]从理论上证明了..." — 引用打断句子节奏
- ✅ "Shen 等人从理论上证明了...的关键机制[@key]" — 引用在完整论断之后

同时明确：
- 中文作者用全名/姓+"等人"
- 英文作者用姓+"等人"
- 禁止"文献[X]"指代

#### 改进 8：国内外文献组织说明

- 12/12 参考论文按技术方向分组，0/12 按地理分组
- 混合中外文献是正确做法
- 节标题用"国内外研究现状"（模板要求）

#### 改进 9：节间引导段规则

- 每个二级/三级标题与第一个子标题之间必须有 1-3 句引导文字
- 概述本节内容、组织结构或分组逻辑

#### 改进 10：翻译腔禁止清单（第一轮）

从子 agent 对比审查中发现 8 种系统性翻译腔模式：

| 翻译腔 | 来源英文 | 替代写法 |
|--------|---------|---------|
| "使...成为..." | "enables it to become" | 拆成两句 |
| "使...能够..." | "enables...to..." | "可以..."或"具备...能力" |
| "被激活" | "is activated" | "得以发挥"或"体现优势" |
| "零篇" | "zero papers" | "尚无论文涉及" |
| 名词+加号堆砌 | "A+B+C+D" | 自然语言连接 |
| 一句话塞太多信息 | 长复合句 | 拆成 2-3 句 |
| 过度精确无源数据 | "82.6 days" | 给整数或注明推导前提 |
| 调试日志式描述 | "CUDA OOM" | "超出 GPU 内存限制" |

### v3 第三轮：标题命名 + 方法描述风格 + 跨节去重（2026-05-28）

**用户反馈**："第二章写了，但感觉有些地方很生硬？比如标题，比如遣词造句"

子 agent 对比审查第二节后发现问题集中在三个层面。

#### 改进 11：章节标题命名规范（E2）

**发现**：当前标题像实验报告（"GNN 跨规模路由的规模不变性验证"），不像学术论文。

**规则**：采用"场景/问题 + 方法/技术 + 研究/算法/设计"结构
- ✅ "基于 XX 的 YY 方法/研究/设计"
- ❌ "XX 的 XX 验证/分析/实证" — 实验属性不在标题中
- ❌ "第X章研究内容：" — 删去说明性前缀

**本报告建议标题**：
- 2.2: 基于图神经网络编码器的 LEO 卫星跨规模路由方法
- 2.3: 基于二部图 GNN 的多用户卫星切换决策方法
- 2.4: 面向链路故障的 GNN 弹性路由方法

子标题建议："研究问题与动机""拟采用的技术路线""预期成果与考核指标"

#### 改进 12：方法描述风格规范（E3）

**发现**：方法描述像产品规格书/README，参数罗列缺论述。

**规则**：
- 技术参数融入论述句，不单独括号堆砌
- 每个技术选择交代"为什么"——3 层因为 3 跳感受野，top-K 为压缩动作空间
- 特征维度用概括性语言引出，括号标注维度作补充
- 连续三个以上并列的"N 维（特征列表）"必须改写

**正误对照**：提供了产品规格书写法 vs 论文论述写法的完整对比

#### 改进 13：预期目标与已有结果分离（E4）

**发现**："预期目标"中堆砌了已完成实验的全部数据，开题报告应该是将来时。

**规则**：
- "预期目标"写将来时要验证什么、通过标准
- "初步进展"放已有 MVE 结果，标注"初步仿真结果表明"
- 已有完整实验的章节，目标改为"验证并扩展初步发现的适用范围"

#### 改进 14：跨节去重（E5）

**发现**：第二节"问题定义"重复展开第一节的 gap 分析。

**规则**：
- 简短引用第一节结论（"如第一节所述"）
- "探索性分化"框架在 2.1 完整阐释一次，后续只简短回引
- 篇幅留给方法论述和预期贡献

#### 改进 15：翻译腔补充（7 条新模式）

从第二节审查中发现的额外翻译腔：

| 翻译腔 | 替代 |
|--------|------|
| "成为...的激活条件" | "是...的关键因素"或"发挥关键作用" |
| "转化为实际性能增益" | "体现为显著的性能提升" |
| "体现出结构性优势" | "性能优势逐步显现" |
| "vs flat Q"英文缩写对比 | "相比...减少约19倍" |
| "让模型接触不同分布" | "使模型学习到...特征" |
| "保证排列等变性" | "保持排列等变性" |
| "感知...异质性" | "区分...差异" |

## 经验总结

### 1. 否定规则不够，需要肯定性示范

纯"禁止"清单（不要 AI 味、不要翻译腔）的遵守率约 30-50%。加入 few-shot 示范段落后，遵守率提升到约 70%。关键是示范段落必须来自**同类文档**（学位论文绪论），不能来自通用写作示例。

### 2. 提示词中的示范本身就是错误来源

v3 第一轮在作者名称惯例中写的是 `Shen 等人[@key]从理论上证明了`（引用紧跟人名），模型完全照搬了这种写法。教训：**提示词中每个示范句子本身必须完全正确**，模型会无差别地学习示范中的所有模式，包括错误模式。

### 3. 翻译腔是 LLM 中文学术写作的最顽固问题

LLM 的训练数据以英文论文为主，输出时倾向于"英文句式+中文词汇"的逐词翻译模式。具体表现为：
- "使...成为...""使...能够..."（enables/becomes）
- "被激活"（is activated）
- "转化为...增益"（translates into gains）
- "vs XX"（英文对比缩写）
- 名词加号堆砌（A+B+C+D）

解决方法：在禁止清单中给出具体的❌/✅对照，比抽象规则有效。

### 4. 引用格式的三个层面

LLM 处理引用需要三个层面的规则：
1. **格式层面**：`[@citekey]` vs `[Author, Year]` vs `[1]` — 需要明确指定
2. **位置层面**：引用紧跟人名 vs 放在论断末尾 — 需要正误对照
3. **密度层面**：每段至少有引用 vs 整段无引用 — 需要量化下限

三个层面缺一不可，只给格式规则不够。

### 5. 审查需要参照对比

让子 agent 同时读草稿和参考论文来对比审查，比单纯审查草稿有效得多。具体原因：
- 参照对比可以发现"这个位置参考论文用自然语言，草稿用技术参数堆砌"
- 可以发现"参考论文的标题是X结构，草稿是Y结构"
- 可以提取具体的替代写法

### 6. 子 agent 并行提效

整个调优过程中使用了多轮子 agent 并行：
- 3 个 agent 并行提取 few-shot 示范（6 篇论文）
- 1 个 agent 对比遣词造句（草稿 vs 2 篇参考论文）
- 1 个 agent 最终审查提示词
- 1 个 agent 对比第二节标题和写法

子 agent 的优势：避免主对话上下文被论文全文撑满，返回的是结构化摘要。

### 7. 提示词迭代的有效节奏

有效节奏是：**写提示词 → 测试输出 → 用户反馈 → 派子 agent 诊断 → 改进提示词**

关键：用户反馈是第一手信号（"写的特别烂""有些地方很生硬"），子 agent 诊断是把模糊反馈转化为具体问题的手段。不要试图在用户反馈前预判所有问题。

## v3 第四轮：第三至七节审查与修复（2026-05-28 续）

### 背景

第三至七节由 LLM 基于 v3 提示词生成后，用户直觉"感觉不太对劲"。派子 agent 从两个角度审查：（1）开题报告各节标准写法调研；（2）第三至七节写作质量审查。

### 发现的系统性问题（20 项）

#### 问题类型 1：结构缺失

开题报告标准结构要求七节，但 LLM 输出在 3.5 之后直接结束，缺少第四至七节。原因是提示词只覆盖了前三节的写作流程，未明确要求补全后续节。

**教训**：提示词必须覆盖**完整的文档结构**，不能只写"核心章节"的流程而假设模型会自动补全。

#### 问题类型 2：时态错位（最严重）

第五六节大量使用完成时态："揭示了""设计并验证了""系统性验证了""建立了"。这是论文 contribution section 的写法，不是开题报告的写法。开题报告应该用"拟""初步观察到""计划验证"。

**根本原因**：提示词中第二节"研究内容"的"初步进展"子节已包含完整实验数据，模型在写第五六节时自然地从中提取并使用完成时态。

**修复**：
- 第五节"预期成果"：从问句改为成果陈述句式（"明确.../确定.../标定..."）
- 第六节"创新之处"：全部改为"拟设计""初步实验观察到"，并补充"与现有...不同"的对比
- 已有实验数据统一移到第七节"研究基础"

#### 问题类型 3：数据三重重复

91.5% 时延保留率在第二、六、七节各出现一次，89.4% 阻塞率在第二、七节重复。同一份文档中核心数据逐字重复三次，给人凑字数的印象。

**原则**：每项核心数据在全文中只出现一次完整版，其他位置用概括性表述（"超过 90%""显著提升"）或回引。

#### 问题类型 4：括号堆砌

第七节 7.1 一段内出现 4 处括号：`（10.9 倍）`、`（跨规模时延 65.92 ms，同规模 Dijkstra 60.77 ms）`、`（移除后 GNN 退化为近纯 Dijkstra）`、`（$p=0.007$，Cohen's $d$=5.03）`。读起来像实验日志而非学术文本。

**修复**：

#### 8. 多角度审查的必要性

#### 10. 核心数据重复是开题报告特有的结构问题

在正式论文中，实验数据在 Results 节完整呈现，Discussion 节引用，不会重复。但开题报告的七节结构中，"研究内容"需要展示初步结果支撑可行性，"创新之处"需要数据佐证创新点，"研究基础"需要详列已有积累——三节都指向同一组数据。这需要在写作前就规划好数据分布策略。

#### 经验总结

##### 16. "检索报告体"是 LLM 文献综述的系统性缺陷

LLM 倾向于用量化方式证明自己的文献调研完整性（"我搜了N篇"），但学位论文的读者关心的是技术分析结论，不是检索过程统计。正确做法：通过技术机制分析（"现有方法的X局限导致Y问题"）自然引出空白，让读者自己得出"确实没人做"的结论。

##### 17. 段落衔接是 LLM 长文写作的薄弱环节

LLM 生成的段落内部通常质量尚可，但段落之间缺乏过渡——每段都是独立的信息块，不像人类作者会精心设计"前段末尾→后段开头"的衔接。这需要在提示词中明确要求"每两段之间必须有一句过渡"。

##### 18. "清单体"文献综述源于逐篇处理习惯

LLM 处理文献列表时天然地逐篇展开，导致"X做了Y但Z"的重复句式。参考论文的做法是先分组归纳再选择性展开。提示词需要加入"文献综述按技术路线分组，每组总结共性后只展开最相关的2-3篇"的明确规则。
