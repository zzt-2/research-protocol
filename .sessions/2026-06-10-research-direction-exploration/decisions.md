### 背景

R002 已产出 22 个候选方向，但卡在"用户选方向"这一步。根因**不是候选不够，是评判尺度未锁定**——"什么方向值得发力"没有显式标准。在尺度未定前继续挑候选是发散的（失败模式 M6 范围偏离的前置症状）。

用户最怕两类坑：**做不出来**（难度过高烂尾）和**做完了是空的**（常识拼凑，答辩被问"贡献在哪"）。本框架以避这两类坑为核心组织。

### 决策：四轴 + 筛选标准

**四轴状态**：

| 轴 | 状态 | 强度 |
|----|------|------|
| **E 含金量** | 三检验（反例/非平凡/可比较）。**过≥2条=真工作，过2条=勉强，过1条=常识重做** | DECIDED |
| **D 实现难度** | 资源门槛取消（GPU ✅ RTX4070 / FPGA ✅ 用户熟练多项目）。只剩工程门槛 + 硬上限=排除"工程完全不可实现"（见 5 类排除列） | DECIDED |
| **C 风险** | C1 扩展高引已有工作（砍所有空白方向，符合 TL-04 陷阱空白教训） | DECIDED |
| **B 验证深度** | B3 可达（FPGA 可做时序闭环级，不必降综述级） | DECIDED |

**E 含金量三检验**（全过才算真工作）：
1. **反例检验**：做出来会不会被反驳"这不就是教科书 X 章 + 套个湍流参数"？能被反驳 → 不过
2. **非平凡性检验**：核心有没有 ≥1 个不显然的设计决策（湍流约束下取舍/推导/组合，非直接代公式）？没有 → 不过
3. **可比较检验**：有没有明确 baseline + 非平凡指标差异？没有 → 不过

**D"工程完全不可实现"排除列（5 类）**：
1. 需实测星地激光链路数据（无采集条件）
2. 需专用/非通用硬件（特定 ASIC / 光电硬件 / 非手上 FPGA 板）
3. 需超 RTX4070 单卡 + 不可接受时长训练（超算级）
4. 需实时物理闭环（实际光路 + 大气湍流模拟箱等硬件在环）
5. 需数月级长周期实测/采集

不在排除列：通用 FPGA 板上的综合实现 / 时序闭环 / 资源评估（用户熟练，算工程量不算不可实现）。

**ML 放行 + 优先**（TENTATIVE）：ML 不是 D 排除项，是用户偏好点（同分时 ML 类优先）。落点分寸 = **扩展已有 ML 方法到湍流场景**（如 ML 辅助同步/估计），非从零设计全新 ML 架构。与宽壳创新点(2)"湍流下载波同步"结合顺，新对话读 R002 重点看 A 组有无 ML-based 同步。

**最终筛选标准（4 条 AND）**——R002 22 方向逐个过：
1. E 过 ≥2 条
2. D 在上限内（不在 5 类排除列）
3. C1（扩展高引已有工作）
4. 优先 ML 相关（同分时 ML 类优先）
