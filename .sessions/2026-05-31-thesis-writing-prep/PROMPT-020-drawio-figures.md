## 统一设计语言

所有图必须遵守以下规则：

| 元素 | 规则 |
|------|------|
| 比例 | 16:9，适配 PPT |
| 框样式 | 微圆角（arcSize=6），外框淡色容器，内框白底独立模块 |
| 箭头类型 | 实线=数据/信号流，虚线(dashed)=反馈/迭代，点线(dotted)=探索/未来 |
| 颜色系统 | Ch3=蓝色系，Ch4=绿色系，Ch5=橙色系，框架/Ch2=中性灰+点缀色 |
| 禁词 | 图中不出现：自适应/优化/增强/首次/填补空白/鲁棒/oracle CSI |
| 图例 | 每张图底部或右上角标注 3 种箭头类型含义 |
| 字体 | 框内 11-13pt，标题 20-24pt |
| 创新点措辞 | 用"拟"字 |
| 不放公式 | 不放具体数字 |

### 必须实现的"花哨"元素（现有图全部缺失）

参考PPT使用了以下高级视觉元素，我们的图必须加入：

1. **闭环反馈箭头** — DPLL 的 NCO→鉴相反馈、实验→设计准则的验证闭环
2. **诊断面板/外挂面板** — 从主体图向外延伸的小型附属区域，放 BER/NMSE 小曲线、参数表
3. **嵌套结构** — 外框内嵌白框，不是单层平铺
4. **竖向接口条** — 模块之间的接口用竖向窄条表示（参考图1的中间接口）
5. **分段序列条** — 时间/步骤的分段显示（不是一串独立框）
6. **斜向叠放** — 多层信息可以斜着叠放，制造深度感
7. **排线/总线** — 多条信号汇聚时用总线风格（一条粗线+分支），不是每条单独画
8. **颜色分区底色** — 大面积淡色底色区分不同功能区
9. **虚线边界** — 区分研究范围（虚线框=拟探索，实线框=确定交付）
10. **图例区** — 右上角或底部的箭头类型说明

## 参考 PPT 图形语法（用户已提取）

### 图1：研究目标框架图
- **类型**：技术总览 + 模块架构 + 局部闭环机制图
- **可迁移结构**："两大任务区 + 中间接口 + 局部闭环 + 外挂诊断面板"
- **视觉元素**：竖向接口条、横向分段条、小矩阵/表格、曲线小图、散点/误差小图、圆形运算节点
- **排版**：宽画布；低饱和分区；黑色主箭头；蓝色强调算法模块；虚线边界区分研究子域
- **我们要学的**：复制"建模/构造区 → 统一接口 → 算法闭环区 → 结果诊断"的结构
- **要避免的**：不要照搬符号和过密折线

### 图2：载波同步算法全流程框图
- **类型**：复杂算法全流程图；"先验构造 + 接收接口 + 闭环估计 + 诊断输出"
- **可迁移结构**："构造链 + 接口条 + 闭环处理 + 右侧诊断"
- **视觉元素**：分段序列条、竖向序列栈、矩阵小块、折线小图、误差向量示意、圆形融合节点
- **排版**：超宽画布；信息密度高；分区靠淡底色与虚线边界；模块边框细，处理框可用圆角
- **我们要学的**：表达"外部辅助信息如何进入闭环同步/估计系统"
- **要避免的**：不要让虚线同时表示边界、数据流和反馈；每种线型只承担一种语义

### 图3：测距算法全流程框图
- **类型**：时间轴驱动的流程管线图
- **可迁移结构**："时间轴 → 局部展开 → 重复估计 → 集合汇聚 → 拟合输出"
- **视觉元素**：长条时间轴、灰色分段块、高亮窗口、重复局部块、叠放估计卡片、小坐标曲线
- **我们要学的**：用时间轴统领复杂算法，而不是把模块排成普通流水线
- **要避免的**：不要画过多重复窗口；保留 2-3 个代表单元即可

### 图4：FPGA 硬件实现架构图
- **类型**：硬件系统架构 + 信号处理链联合图
- **可迁移结构**："三链并置"——发射链、接收链、算法链分区表达
- **视觉元素**：硬件功能块、器件图标、竖向关键模块、并联支路、淡色算法容器、多输出箭头
- **排版**：白底宽幅；硬件链偏器件图标，算法链用淡色大容器收纳；主箭头较粗
- **我们要学的**：复制"物理链路在上/右，算法处理在下，输出显式并列"的层级
- **要避免的**：不要把硬件图标当装饰；图标必须对应真实接口或器件角色

### 图5：文献方法对比汇总表
- **类型**：三栏对比表 + 论证链路图
- **可迁移结构**："三栏因果链"——为什么需要、问题在哪、如何切入
- **视觉元素**：三色泳道、顶部粗线、圆角观点块、行对齐、跨列箭头、浅色背景
- **我们要学的**：复制"三列泳道 + 多行对应 + 水平推导箭头"的表格语法
- **要避免的**：不要变成普通罗列表；每一行必须能读成一条完整论证链

### 每张图的具体问题

**结构图 (1).drawio（P7）**：
- 优点：5层+3列结构合理，红字标注有价值，左侧导航列概念好
- 缺点：纯单向瀑布流无反馈；框内信息密度低；没有诊断面板；箭头用shape=singleArrow（不支持曲线）
- 改进：L3理论层加闭环反馈；L4技术层改为复合框；箭头改edge元素；加右侧诊断面板

**信道估计路线.drawio（P10）**：
- 优点：上窄下宽漏斗结构好；3行方法对齐便于对比
- 缺点：无圆角矩形(rounded=0)显生硬；写了"反馈回路"但没画箭头；缺"精度设计准则IP1"输出块；缺"接收性能影响分析"展开区；无诊断面板
- 改进：加展开分析区+IP1输出+诊断面板(NMSE小图)+反馈箭头

**载波同步路线.drawio（P11）**：
- 优点：DPLL闭环反馈是亮点（唯一真正的闭环）
- 缺点：缺3层递进结构(分析→准则→探索)；无虚线框区分确定交付vs拟探索；无VV/BPS展示；与P10视觉同质化
- 改进：补3层递进+VV/BPS/DPLL三方法+实线框+虚线框+诊断面板(BER小图)

**FPGA验证路线.drawio（P12）**：
- 优点：FOE+DPLL级联验证流程清晰
- 缺点：与P10/P11完全同模板；无硬件视觉元素(芯片图标/总线/时钟)；无资源对照表
- 改进：硬件风格元素+深色调+寄存器级抽象+资源表面板；必须和P10/P11视觉差异化

## 每张图的详细设计要求

### 图0a：P3 接收端信号处理时间轴（从零新建）

**内容来源**：ppt-content-decisions.md P3 段

**设计方向**：三阶段单轴时间线，分色底色，现代学术风格

**核心信息**（40s 内传达）：
- 接收端信号处理经数十年发展，方法框架已趋成熟
- 三个阶段：奠基期(70s-01)→成熟期(02-18)→扩展期(19-现在)
- 每阶段 3 个标志性节点（共 9 个）
- 底部总结："方法积累丰富，但 FSO 湍流场景覆盖仍有待拓展"

**三阶段内容**：

| 阶段 | 标题 | 节点 | 底色建议 |
|------|------|------|---------|
| 奠基期 70s-01 | 分析框架与统计基础建立 | PLL同步理论(1979) / VV前馈估计(1983) / GG湍流模型(2001) | 淡蓝 |
| 成熟期 02-18 | 方法体系在传统场景中完善 | BPS盲相位搜索·高阶调制(2009) / 经典CE·FSO验证(2010s) / FSO理论综述(2014) | 淡绿 |
| 扩展期 19-现在 | 向新场景和新维度初步扩展 | 数据驱动探索·DL入局CE(2020s) / 湍流场景迁移·解析框架(2019-) / 联合补偿初探(2023-) | 淡橙 |

**结构要求**：
- 单条水平时间轴贯穿三阶段
- 每阶段用不同淡色底色的大圆角矩形包裹
- 节点用小圆点/菱形标注在时间轴上，上方写方法名，下方写年份
- 阶段标题+总结语写在底色区域顶部
- 底部一行总结句（跨全宽）
- 不要写作者名（作者名在口述稿中）

**视觉元素建议**：
- 时间轴用渐变线条（从左到右颜色渐变，暗示时代演进）
- 节点可以加小图标（如 PLL 用齿轮、VV 用波形、GG 用大气符号）——非必须，看效果
- 扩展期的节点可用虚线边框（暗示趋势尚未定型）
- 底部总结句用醒目但不突兀的标注（如小旗帜/括号标注）

**避坑**：
- 不要画成双轨（旧版方案，已否决）
- 节点不要挂作者名（会在 slide 上显得拥挤且增加被追问风险）
- 不要太密——9 个节点要一眼能看清

### 图0b：P5 研究空白（从零新建）

**内容来源**：ppt-content-decisions.md P5 段

**设计方向**：双栏对比 / 双路径图，借鉴参考图5"三栏因果链"的视觉语法

**核心信息**（50s 内传达）：
- 两个空白：①估计精度与下游需求脱节 ②载波同步缺乏湍流系统性研究
- 每个空白有 2-3 个具体表现
- 每个空白有→后果（设计者面临的核心问题）

**两个空白的内容**：

**空白① 估计精度与下游需求脱节**：
- CE 以 NMSE 为核心指标，精度与下游同步模块需求缺乏定量关联
- 不同调制格式对估计误差灵敏度差异大
- → 设计者无法确定精度做到多少才够用

**空白② 载波同步缺乏湍流场景系统性研究**：
- 分析框架：未将 CE 误差纳入，多以白噪声假设为前提
- 参数设计：经典公式多以白噪声为前提，湍流下设计准则不完善
- 方法探索：编码辅助等方向在 FSO 湍流下适配性研究有限
- → 缺乏分湍流条件的方法选择和参数配置指导

**结构要求**：
- 左右双栏或上下双区块，每栏一个空白
- 每栏内部：标题 → 2-3 条具体表现 → 箭头 → 后果（醒目标注）
- 可加 DSP 链示意：在顶部画一条简化的接收链（估计→同步→…），用颜色/叉号标注两个空白对应的位置
- 两个空白之间可以有虚线箭头体现关联（空白①的精度问题加剧了空白②的分析困难）

**视觉元素建议**：
- 参考图5的"三色泳道"语法，但改为双色（如蓝+绿，分别对应 Ch3/Ch4 的颜色）
- 后果行用红色/橙色强调（"设计者无法确定…"/"缺乏…指导"）
- 如果加顶部 DSP 链，用竖向接口条风格（参考图1）
- 空白之间的虚线关联箭头用点线（dotted）

**避坑**：
- 不要变成纯文字列表——必须有视觉元素（箭头、路径、颜色分区）
- 不要太密——50s 页面，信息密度要适中
- E[1/h] 等公式不放 slide 上
