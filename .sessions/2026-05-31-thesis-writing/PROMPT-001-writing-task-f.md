## 二、质量约束（全文适用）

### 防御性写作（R003）

- 不写"首次"/"填补空白"/"oracle CSI"
- 不承诺解决方法，只承诺研究分析
- Ch4 不绑定具体算法（系统性分析路线，不声称新方法）
- 完整禁忌清单见**附录C**（写作前必读）

### 物理约束

- h 是实值归一化辐照度（不是复信道系数）
- ω_n 单位 rad/s（不是 MHz）
- 禁止出现旧方向内容（GNN/路由/切换/故障弹性/DRL）

### 质量维度（已验证有效）

- **D4 问题前置**：每节/每段先陈述问题或动机，再给方法/分析
- **D2 递进评价**：文献/方法评价层层递进，不平行罗列

### 动词强度控制（来自 S004 实战教训）

过强动词是学术论文最常见的审查问题（S004 中占 50%）。必须按内容性质选词：

| 内容性质 | 禁用动词 | 应使用 | 原因 |
|---------|---------|--------|------|
| 引用现有模型 | 建立/提出 | 介绍/分析 | GG等模型非本文原创 |
| 引用现有推导 | 推导 | 介绍 | 公式非本文首次推导 |
| 仿真对比结果 | 揭示/确定 | 分析/给出 | 仿真不是发现/确定 |
| 性能对比 | 最优/最佳 | 较为稳健/较好 | 不提前宣称最优 |
| Ch5 FPGA（未开发） | 完成/实现 | 进行/设计分析 | FPGA尚未开发 |
| 未验证指标 | 实现/验证 | 预期/规划 | 不能承诺未验证内容 |

### 缩写规则

- 所有缩写（FPGA/VV/BPS/DPLL/LS/MMSE/SNR等）首次出现时必须给出中文全称+英文全称
- 后续使用统一缩写，不混用

### 语言约束

- 正式学术中文，不出现口语化表达
- 段落结构不雷同、句式不单调、过渡不公式化
- 公式引入/推导衔接从句式库取，不自编

### Step 3: 派审查子agent（7个并行）

写完后立即并行派出 8 个审查子agent（规格见§七）。每个返回问题清单（位置+问题+建议），不打分。如无问题返回"无问题"。

- 汇总所有审查结果
- 逐条修正，确认每条问题已解决
- 修完后将正文追加到产出文件

### Step 5: 下一节

按§五中的顺序推进到下一节，重复 Step 1-5。

## 七、审查子agent规格

7 个审查子agent，每次写完一节后并行派出。每个子agent接收刚写完的§X.Y正文作为输入。

### R1 语言质量审查

- **检查内容**: 段落结构是否雷同、句式是否单调、过渡是否公式化、是否有口语化表达、是否有翻译腔
- **参考**: 仅凭学术中文语感判断，不需读取外部文件
- **返回**: 问题清单（位置 + 问题 + 建议）

### R2 论断依据审查

- **检查内容**: 每个判断/承诺是否有文献/公式/数据支撑；是否符合防御性写作（不承诺解决方法）；是否存在无依据的"优于"/"显著改善"等断言；数据引用是否可溯源
- **参考**: §二 质量约束
- **返回**: 问题清单

### R3 技术常识审查

- **检查内容**: 物理量纲是否正确（ω_n=rad/s、h无量纲实值）；公式变量含义是否前后一致；是否有物理错误（如辐照度当成功率、SNR搞反、自由空间损耗公式符号错误等）；数值是否在合理范围；公式描述是否准确（"解析表达式"vs"解析关系"vs"工程设计选择"；"推导"vs"引用"）；所有缩写首次出现是否给出中文全称+英文全称
- **参考**: §二 物理约束 + 符号约定 + 缩写规则
- **返回**: 问题清单

### R4 术语合规审查

- **检查内容**: 逐句对照 TERMS.md，检查全文用词是否符合规范（如同义词混用、术语不一致）
- **参考**: 读取 `毕设/TERMS.md`
- **返回**: 术语偏差清单（原文用词 → 应改为）

### R5 符号一致审查

- **检查内容**: 数学符号是否与 symbol-conventions.md 一致；同一变量全文是否使用相同符号；上下标是否规范；希腊字母是否正确
- **参考**: 读取 `毕设/symbol-conventions.md`
- **返回**: 符号偏差清单

### R6 禁忌内容审查

- **检查内容**: 是否出现 GNN/路由/切换/故障弹性/DRL 等旧方向内容；是否出现"首次"/"填补空白"/"oracle CSI"；Ch4 是否绑定了具体算法声称新方法
- **参考**: §二 防御性写作 + 物理约束
- **返回**: 违规清单

### R7 图表公式审查

- **检查内容**: 公式编号是否与 section-outline.md 一致；图表编号是否与 figure-table-plan.md 一致；LaTeX 是否正确（括号匹配、上下标、分数格式）；正文引用公式时"由式(X.Y)可知"编号是否正确
- **参考**: 读取 `section-outline.md` + `figure-table-plan.md` 的对应节
- **返回**: 编号/格式问题清单

### R8 动词强度审查

- **检查内容**: 逐句扫描动词，对照 §二 动词强度控制表。重点抓：引用现有模型用"建立/提出"（应为"介绍"）；引用现有推导用"推导"（应为"介绍"）；仿真结果用"揭示/确定"（应为"分析/给出"）；性能对比用"最优/最佳"（应为"较为稳健"）；Ch5 用"完成/实现"（应为"进行/设计分析"）；承诺未验证指标
- **参考**: §二 动词强度控制表
- **返回**: 动词降级清单（原文 → 应改为 → 原因）

## 八、章级操作

### 写作顺序

1. 先写正文各节（跳过 §X.1 章引言和 §X.N 章小结）
2. 所有正文节写完后，写章引言（需概括本章内容、与上一章衔接）
3. 最后写章小结（总结关键结论、引出下一章）
4. 章引言和章小结同样经过 Step 3 审查（8个审查子agent）

### 全章写完后的额外步骤

#### 跨章一致性审查（必做）

全章各节+引言+小结写完后，派出 3 个子agent并行审查本章与已写部分的跨章一致性：

1. **动词一致性审查**：检查本章动词强度是否与 §1.1-§1.4 已降级的动词一致（如§1.3说"介绍系统模型"，本章不能说"建立系统模型"）
2. **术语+符号一致性审查**：读取 `cross-chapter-notes.md` + `毕设/TERMS.md`，检查本章用词/符号是否与已写章节冲突
3. **章节描述对齐审查**：检查本章引言/小结中对其他章的描述，是否与§1.3中该章的描述一致

发现不一致则立即修正，并更新 `cross-chapter-notes.md`。

#### DeepSeek 外部评审（必做，Phase 7-8）

§1.1 用 DeepSeek 外部评审获得 92 分，验证了该方法有效。每章写完后：

2. 评审维度参考 §1.1 的评分标准：结构完整性、论证严谨性、语言质量、公式正确性

## 附录C：绝对禁忌清单（写作前必读）

> 来源：S002/S003/S004 三轮审查 + Ch2-reviews 12子agent深度文风审查 + 范文验证
> 每章写作开始前，主对话必须完整阅读本附录。

### 范文验证铁律（不可违反）

以下4条经董凡/张思齐/吴志航/闫佳欣4篇范文交叉验证，确认不存在：

**铁律1：节首第一句直接切入新内容，禁止"上节/前节/前文+动词"回指**
- 反面："上节建立了接收信号模型""前文分别介绍了""如§1.2.2所述"
- 正确：直接切入（下定义/引框图/说动机），用"接下来""下面""在此基础上"递进
- 段内指代可用"上述"（如"上述非理想因素"），跨节回指不行

**铁律2：已定义符号直接使用，禁止"（定义见§X.X）"格式**
- 反面："（定义见§2.2.3）""即前文定义的""注意此处与§X.X不同"
- 正确：符号定义过一次后全文直接使用，不加括号注释来源
- 符号冲突通过上下文区分；高风险冲突（如γ同时表示衰减系数和SNR）改用不同符号

**铁律3：参数解释统一"式中/其中，A为...，B为..."格式**
- 不创造变体，连续出现时第二处改"其中"，第三处改"进一步"
- 禁止连续三处以"式中"开头

**铁律4：符号重用通过上下文区分，不显式声明**
- α/β在不同章节有不同含义时直接使用，不需要"注意此处α与§2.3中含义不同"

### 动词强度禁忌

| 禁止 | 应使用 | 条件 |
|------|--------|------|
| 建立/提出 | 介绍/给出 | 非原创模型（GG/QPSK/相干检测等） |
| 推导 | 介绍 | 非本文首次推导的公式 |
| 揭示 | 分析/验证/表明 | 仿真/实验结果 |
| 确定 | 推导/分析 | 参数计算 |
| 最优/最佳 | 较为稳健/较好 | 性能对比 |
| 完成/实现 | 进行/设计分析 | Ch5 FPGA（未开发） |
| 实现了 | 能够实现 | 描述已有模型的能力 |
| 显著提高/下降 | 提高/下降 | 无定量数据支撑时 |

### 措辞禁忌

| 禁止 | 正确做法 |
|------|---------|
| "首次""填补空白""oracle CSI" | 删除或改为审慎表述 |
| "显著鸿沟""目前唯一""最系统的""标杆方案""仍为空白""均缺乏""无法直接迁移""直接决定""突破了""证明" | 降级为审慎措辞（"仍存在较大差距""为数不多的...之一""较为系统的...之一""具有代表性的方案""有待探索""难以直接迁移""直接影响""有效缓解了""表明/验证了"） |
| "据作者所知""据文献检索" | 直接陈述，保留审慎限定词 |
| 反问句 | 改为陈述句 |
| "如§X.X所述" | 用内容描述替代节号 |
| 括号内章节号 | 删除 |
| 引用放在句中 | 引用必须放在句末句号前 |

### 术语禁忌（TERMS.md + Ch2审查）

| 禁止 | 应使用 | 原因 |
|------|--------|------|
| 信道增益 | 归一化辐照度h | h是实值辐照度，非射频含义 |
| VV平滑窗口 | VV平均窗口长度M | VV做算术平均非平滑 |
| 联合同步 | 级联载波同步链 | FOE→CPR串行非联合 |
| GG（首次出现） | Gamma-Gamma | 首次出现不给缩写 |
| 线性调制 | 线性影响 | "调制"多义 |
| 确定性链路增益 | 确定性链路传输因子 | 避免"增益"歧义 |
| 大尺度分量/小尺度分量 | 大尺度Gamma分量/小尺度Gamma分量 | TERMS规定 |

### 内容禁忌

| 禁止 | 原因 |
|------|------|
| 文献综述中掺入自己的仿真结论 | 综述只引已发表论文 |
| 提前绑定具体方法（开题阶段） | Ch4是系统性分析，不绑定VV/BPS/DPLL |
| 无来源定量数据 | 所有数字必须有引用或标注"本文仿真" |
| 承诺未验证指标（Ch5最高工作频率/端到端时延） | FPGA未开发 |
| 文献引用事实不准确 | 归因必须精确，不可张冠李戴 |

### 反复犯错预防

以下问题在S003/S004中纠正后，Ch2写作中又重复出现。**每次审查修正时必须对照本清单**：

1. **审查agent建议的句式改动，必须先在范文库中验证是否存在先例**，不能凭空创造
2. **括号内章节号**：审查agent可能建议加节号"帮助读者"，但范文没有这个写法
3. **回指句**：深度审查agent可能建议加回指"帮助衔接"，但范文用递进词不用回指
4. **过强动词**：正文内和概述段（§1.3/章引言/章小结）的动词标准必须一致
5. **绝对性措辞**：修改正文后必须同步检查辅助材料（映射表/脚注等）
