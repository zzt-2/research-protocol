# PROMPT: 寻找第二个研究方向

## 背景

我正在准备一篇博士学位论文（通信领域，LEO 卫星网络方向），采用"1 方向 → 3 章"结构。

**已有方向**：ISL（星间链路）调度 + DRL，正在从纯 DRL 转向"监督学习预训练 + 离散 RL 微调"方案。项目在 `projects/leo-isl-scheduling-drl/`。

**论文结构要求**（来自 34 篇博士论文精读分析）：

- 3 个主体章节，每章解决一个独立但有联系的子问题
- 章间需要共享系统模型（如同一 LEO 星座）和方法论（如 GNN/DRL 框架）
- 最优结构是层次递进型（路由→调度→抗毁 等）
- 每章必须能独立发表

**本任务目标**：寻找第二个研究方向，与 ISL 调度方向组合后能形成有内在联系的论文结构。

## 搜索范围

不限 LEO 卫星网络。更广的范围包括但不限于：

- 卫星-地面融合网络（星地协同、边缘计算、计算卸载）
- LEO 星座路由、流量工程、拥塞控制
- 卫星网络抗毁/可靠性/故障恢复
- 频谱共享/干扰管理
- 卫星物联网/大规模接入
- 空天地一体化网络资源管理
- 其他通信领域有 ML/AI 应用的方向

## 筛选标准

每个候选方向需要评估以下维度：

| 维度                | 含义                                                           |
| ------------------- | -------------------------------------------------------------- |
| 与 ISL 调度的共享性 | 能否共享同一 LEO 星座拓扑/系统模型？方法论（GNN/RL）能否复用？ |
| 方向独立性          | 是否是一个独立的优化问题（不是 ISL 调度的微调版）？            |
| 组合叙事线          | 与 ISL 调度组合后，是否有自然的递进/分解/拓展逻辑？            |
| 研究空间            | 是否有足够的文献空白可以切入？是否已有大量 ML 方案（红海）？   |
| 可行性              | 能否用纯 Python + 仿真完成？不依赖真实卫星数据或硬件？         |
| 发表潜力            | 是否容易找到合适的期刊/会议？                                  |

## 任务步骤

### Step 1: 宽泛检索（3-4 个子 agent 并行）

用 `tools/search` 对以下方向做初步检索（每个方向 10-20 篇）：

- 方向 A：LEO 卫星网络路由/流量工程 + ML
- 方向 B：卫星网络抗毁/故障恢复 + ML
- 方向 C：星地融合/边缘计算/计算卸载 + ML
- 方向 D：卫星频谱共享/干扰管理 + ML

每个子 agent 返回：

- 检索到的论文数量和年份分布
- 是否有 ML/AI 方法被应用（蓝海 vs 红海）
- 核心研究问题是什么
- 与 ISL 调度的共享性初步判断

### Step 2: 定向深入（2-3 个子 agent）

根据 Step 1 结果，选择 2-3 个最有潜力的方向，各深入检索 20-30 篇，评估：

- 文献空白的具体位置
- 是否有和 ISL 共享模型/方法的可能性
- 初步的问题建模思路

### Step 3: 输出候选方向评估

输出格式（写入 `.sessions/direction-scouting/LOG-001-candidates.md`）：

```markdown
## 候选方向评估

### 方向 1: {名称}

- 核心问题：一句话
- 文献空间：X 篇相关，其中 Y 篇用 ML，空白在 {具体位置}
- 与 ISL 共享性：{共享什么，不共享什么}
- 组合叙事线：{怎么和 ISL 组合}
- 初步问题建模：{优化目标、约束、可能的 MDP 建模}
- 可行性评估：{高/中/低}
- 风险：{主要风险}

### 方向 2: ...
```

最后给出推荐排序和理由。
