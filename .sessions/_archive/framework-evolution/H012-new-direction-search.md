## 任务

### Part 1: 分析现有 3 个项目的内在关联

先读三个项目的核心文档，分析它们之间是否存在未被发现的逻辑依赖：

- 路由的输出（路径/流量矩阵）→ ISL调度的输入？
- ISL调度的输出（拓扑）→ 路由的约束？
- 切换的输出（用户-卫星映射）→ 路由/ISL的流量变化？
- Size generalization 是否可以成为贯穿三个问题的统一方法论创新？

读以下文件（每个项目读 decision_log 的关键决策行 + feasibility_report 的结论段）：
- `projects/leo-mega-constellation-gnn-routing/decision_log.md`
- `projects/leo-isl-scheduling-drl/decision_log.md`
- `projects/leo-ntn-handover-drl/decision_log.md`

### Part 2: 检索"粘合剂"子问题

用 `tools/search` 检索以下方向，看是否有子问题能天然串联路由/ISL/切换：

1. **联合路由+ISL调度** — 路由层和链路层联合优化
2. **拓扑感知路由** — ISL拓扑变化如何影响路由决策
3. **流量感知切换** — 切换决策考虑全网流量负载（串联切换和路由）
4. **联合切换+资源分配** — 切换时同时优化波束/功率（串联切换和资源层）
5. **跨层优化（路由+调度+切换）** — 三层联合

对每个方向：2-3 组关键词检索，评估论文量和 ML 渗透率。

## 评估标准

每个方向/子问题评估：

```
方向: xxx
论文总量: ~N篇（近3年）
ML/DRL/GNN渗透率: X%
最接近竞品: 1-2篇（标题+年份+方法）
蓝海判断: 真/伪/待定
与现有3个项目的关联:
  - 能串联哪几个？ → 指出具体逻辑依赖
  - 替换哪个？ → 指出替换理由
  - 独立方向？ → 指出能否拆出3个子问题
综合推荐: ★★★/★★/★
```
