## 子 Agent 策略

### 子 Agent A：范文精读 — 可行性论证写法提取

**输入**: 闫佳欣范文 + 曾嘉范文（只读"可行性分析""研究基础""研究条件"等对应章节）
**任务**:
1. 精读两篇范文中论证"本研究可行"的段落
2. 提取以下特征：

   - 每个可行性质粒如何组织（理论 → 方法 → 预实验 等的排列和衔接）
   - 风险分析如何自然收束（是否用"即使最不利……仍可保障"式兜底句）

3. 产出 1 份"可行性论证写法特征表"（≤600 字），含范文行号示例
**时间限制**: 10 分钟

### 子 Agent B：AI trace report 筛选 + 信息点提取

**输入**: `ai-trace-report.md`（P-003 产出）+ kaiti-report.md L624-651
**任务**:

3. 从 L624-651 中提取全部信息点（技术内容，不含句式外壳）：

   - 引用的文献/方法名/参数来源
   - 风险表格中的每条风险及其应对策略

4. 产出：(a) AI 痕迹分析摘要（≤300 字）+ (b) 信息点清单（编号列表，改写时必须全部覆盖）

### 子 Agent C：执行改写

**输入**: 子 Agent A 的写法特征表 + 子 Agent B 的信息点清单 + AI 痕迹分析 + B2 规则
**任务**:

3. **重点改写对象**：
   - L626 总领句：消除"三个层面均具备可行性"式元叙述
   - 各段首尾的套话句：保留技术内容，重写引导/收束方式
   - L640 初步验证段：消除"验证了研究路线的可行性"式空话
   - L651 收束句：**导师直接点名"机器语言"**，必须彻底重写，消除"即使最不利情形发生……底线可得到保障"式模板
4. 不改变 (1)(2)(3)(4) 分点结构，不删除任何技术内容
5. 产出：改写后的可行性分析完整段落 + 逐句改写验证记录（原句 vs 新句，句式结构对比）

### Step 2: 信息点完整性验证 [检查点：信息点不丢失]

### Step 4: B2 逐句改写纪律验证 [检查点：B2 通过]

对 Agent C 的产出逐句验证：

| 验证项 | 标准 | 方法 |
|--------|------|------|
| 句式不相似 | 改写后的句子无法通过句式对比识别为同一来源 | 对比原句和新句的主谓宾结构、从句位置、衔接词 |

| AI 痕迹消除 | 无翻译腔/平行罗列/元叙述/数据堆砌/清单体 | 用 B1 的 5 类标准逐条判定 |

如验证不通过，将问题反馈给 Agent C 迭代，最多 2 轮。

## 不要做什么

1. **不改变可行性分析的整体结构** — (1)(2)(3)(4) 分点不变，风险分析表格不变，只改写表述
2. **不删除任何技术内容** — 引用的文献、方法名、参数来源、风险条目等只能重组，不能丢失
3. **不添加新的技术内容** — 只重写已有信息点，不补充新的论证或新的引用
4. **不用同义词替换式修改** — B2 禁令。改几个词但保留原句式 = 不合格
5. **不在主对话调用 WebSearch / webReader** — 子 agent 消化范文，主对话只接收摘要
6. **不扩展到其他章节** — 本 PROMPT 只动 L624-651（可行性分析）
7. **不保留"即使最不利情形发生……底线可得到保障"式模板收束** — 这是导师直接点名的"机器语言"，必须彻底替换
