### B8 图表设计三规则（P-001 预装）

1. 图必须包含具体信息（坐标轴标注、参数值、对比曲线/模块），**禁止笼统框图**
2. 图前有引导句，图后有分析句
3. 开题报告全文图表类型须覆盖：**系统框图 + 算法流程图 + 仿真结果图**

### 用户决策

- **主要补算法图和系统框图**，仿真结果图留待实际实验后补充
- **从同类论文找现成的图直接借鉴**：找构图类似的，照着重画改标签参数
- 开题阶段不用自己原创图表设计，省事为主

## 子 Agent 策略

### Agent 1：缺图需求分析（主线程直接做）

读取 kaiti-report.md 全文，逐章分析需要什么图。按以下维度判断：

- 该节是否涉及系统/模块结构 → 需要系统框图
- 该节是否涉及算法步骤/流程 → 需要算法流程图
- 该节是否涉及性能分析/对比 → 需要仿真结果图（开题阶段标注"占位"）
- 该节是否涉及信号处理链/数据流 → 需要信号流图

产出：**缺图需求表**

| 章节/小节 | 需要的图类型 | 优先级 | 说明 |
|-----------|-------------|--------|------|

### Agent 2-3：论文图表扫描（并行，各负责一半论文）

每个 agent 扫描分配给它的论文 .md 文件，搜索所有图表引用和图标题。

**搜索方法**：
1. 在 .md 中搜索 `图 X-X`、`图X-X`、`![` 等模式定位所有图表
2. 读取图表前后的上下文（标题 + 引导句 + 图后分析句）
3. 根据上下文判断图表类型（系统框图/算法流程图/仿真曲线/原理示意/其他）

### Agent 4：匹配与参考表生成（依赖 Agent 1-3 结果）

基于 Agent 1 的缺图需求 + Agent 2-3 的论文图表库，逐条匹配：

| 缺图需求 | 推荐参考 | 需要改什么 |
|---------|---------|-----------|
| 章节 / 图类型 | 论文名 + 图编号 + 原图描述 | 标签/参数/模块名修改说明 |

匹配原则：
- 优先选**最接近**的图（同主题 > 同大类 > 通用）
- 如果一张缺图有多个候选参考，列 2-3 个供选择
- 如果某类图在现有论文中找不到，标注"需补搜"并给出检索关键词建议

## 工作步骤

### Step 1：缺图需求分析 [检查点：需求表完成]

主线程读取 kaiti-report.md，按章节结构分析每节需要什么类型的图。

**检查点**：需求表覆盖所有主要章节，每张图有明确类型和优先级。

### Step 2：论文图表扫描（并行）[检查点：图表库完成]

Agent 2 和 Agent 3 并行扫描各自负责的论文，提取所有图表信息。

**注意**：
- .md 文件中的图可能显示为 `![描述](路径)` 或纯文本"图 X-X 标题"
- 部分论文 .md 是分章节的 content_*.md，需遍历目录下所有文件
- 重点关注：系统框图、算法流程图、信号处理链框图、接收机结构图——这些是开题报告最需要的
- 仿真结果曲线图也要记录，但优先级低于结构图/流程图

**检查点**：图表库覆盖全部已下载论文，每张图有标题和类型。

### Step 3：匹配与参考表 [检查点：参考表完成]

Agent 4 将缺图需求与论文图表库匹配，生成可执行的参考表。

**检查点**：
- 每个缺图需求至少有 1 个参考候选
- "需补搜"的图不超过总需求的 30%（如果超过，说明现有论文覆盖不够）
- 每个参考图的修改说明具体到"改哪个标签→改成什么"

### Step 4：B8 合规性验证 [检查点：全部通过]

1. 规划的图表类型是否覆盖 B8 三种（系统框图 + 算法流程图 + 仿真结果图）
2. 每章是否至少有图（Ch7 总结可豁免）
3. 参考图是否有足够的构图信息（不能是"某示意图"这种笼统描述）

## 约束

1. **不画图** — 只产出参考表，画图由后续对话完成
2. **不改 kaiti-report.md** — 图片嵌入由单独的 PROMPT 处理
3. **只规划系统框图和算法流程图** — 仿真结果图标注"占位，待实验数据"
4. **不下载新论文** — 只扫描已有的 .md 文件。如果发现缺口过大，在产出中标注"需补搜"并给出关键词，由用户决定是否补充下载
5. **优先已有 .md** — 没有 .md 的论文（如 .caj/.pdf）暂不处理，除非该方向没有 .md 论文可用
