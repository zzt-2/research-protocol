# Recovery and rotation

Use this reference at startup, after context loss, after a blocker, or when choosing the next action.

## Recover from an existing foundation

1. Read the compact status, adapter, current state, active portfolio/batches, latest synthesis, and harvest summary.
2. Recover the formal goal, current authorization, protected paths, baseline identity, metric contract, supported and blocked axes, available commands, and budgets.
3. Classify inherited evidence as `VALID`, `STALE`, `UNKNOWN`, or `INVALID`; retain pointers and reasons.
4. Reconcile unfinished manifests, receipts, events, and artifacts without mutating protected history.
5. State current mode as planning, preparing, running, synthesizing, blocked, or awaiting strategy.

## Start from zero

Recover user intent and constraints, scan prior assets and literature, map problems and failures, establish a minimal legal baseline, then create a broad candidate portfolio. Do not generate candidates solely from model names.

## Rotate with scientific judgment

When local work blocks or saturates, consider:

- one bounded repair that preserves the scientific contract;
- another ready candidate in the batch;
- a different mechanism family;
- a shared capability with clear leverage across worthwhile candidates;
- representative scope expansion;
- portfolio remapping;
- deeper evidence for a stable, mechanism-consistent signal.

Compare information gain, thesis relevance, evidence gaps, dependency leverage, reversibility, and cost. Record the chosen action, alternatives considered, and why stopping is not yet warranted.

Avoid indefinite micro-tuning, repeated repairs of the same local blocker, and infrastructure work that does not unlock research comparisons. Treat local numeric limits as project heuristics unless an upstream safety rule explicitly owns them.

## Close a context safely

Update canonical state, latest synthesis, harvest, and one-page status. Leave an explicit next action, required inputs, integrity warnings, and strategic escalation condition. Do not move live project state into the Skill or transient conversation notes.
