# 论文场景：全文、批注修订与终稿

> 用于论文正文、摘要、引言、结论，以及导师/审稿批注驱动的全文修订。先执行主 Skill 的 C1--C10；本文件增加论文特有门。

## P1 读者与投稿合同

动笔前记录：目标会议/期刊、模板、确切页数或页数范围、参考文献是否计页、匿名/作者模式、作者顺序、通信作者标记和邮箱。项目要求“正好填满 N 页”时，必须检查最终 PDF 的最后占用行；不能把它改写成“少于等于 N 页”。

具体页数、作者姓名、图号和导师偏好只属于当前项目合同，不写成通用规则。

## P2 引言职责

引言按读者所需完成以下职责，具体段落数由可比论文和篇幅决定：

1. 场景与问题；
2. 相关方法类别及其不足/适用关系；
3. 本文方法、机制和评价范围；
4. 论文组织导航（当模板、导师或可比论文要求时）。

相关工作必须分析“方法类别—解决什么—还缺什么—为何引出本文”，不能用一串引用或“已有研究使用 A/B/C”代替分析。先准确说方法属于哪一类，再讨论互补、优劣或适用区间；不要为了突出动机而改写类别定义。

本文方法与评价若构成一个论证单元，应集中呈现，不拆成多个彼此重复的贡献段。被明确划掉的泛化句不能换一批引用后原样补回。

## P3 公式、符号与解释

- 随机变量首次出现时给出分布、参数和独立性/时间关系中对复现必要的部分。
- 公式后解释它测量或控制什么、为何进入算法；不要逐句复述代数，也不要保留已被明确删除的常识性解释。
- 公式、正文、代码/数据的符号与信息访问必须一致。
- 一个解释句只有在承担复现、机制或读图职责时才保留。

## P4 图、图注与正文协作

按实际阅读顺序检查缩写和定义：图或图注先出现的缩写，不能等到后文才解释。

对一组相关结果图统一检查：

- 图例位于读者能直接对应曲线/标记的位置；优先嵌入图面，若因密度采用其他布局，必须在最终尺寸下同样无歧义；
- legend 顺序、颜色、marker、线型和字体一致；
- 无文字遮挡、裁切、贴边或图注替代图内必要编码；
- 每个突出标记、阈值或交叉点在正文有明确用途和解释；
- 多 panel 是否合并由信息职责和最终可读性决定，不因“省页”机械合并；
- 图、图注、正文互补，不重复转录整条曲线。

## P5 结果叙事

结果采用“现象/代表点—比较对象—解释—边界”的层次。删除重复、防御性和开发过程元话语，但不得删除影响公平性、实现真实性、指标含义或结论有效性的必要边界。

完整扫描放在图里，正文只选承担论证职责的数字。不要逐点报数，也不要用“two qualifications matter”一类元话语包裹本可直接陈述的事实。

## P6 引用质量

每条引用同时检查：是否直接支撑所附声称、来源质量、是否有同职责的更强来源。优先使用原始论文、期刊、IEEE Transactions、JLT/PTL 等高质量直接来源；会议论文在独有、最新或不可替代时可以保留。不要按文献类型机械全删，也不要为填页添加弱引用。

## P7 导师/审稿批注闭环

使用逐条 ledger：原话、标记范围、证据类型、修改位置、同类问题扫描、验证结果。明确区分批注文字、删除线/高亮和自己的推断。

每条局部意见都要问一次“全文是否有同类问题”，但只复用诊断问题，不机械复制同一修改。最终独立 reviewer 必须对照原始 ledger 逐条核销。

## P8 终稿 PDF 门

内容稳定后再做页数与布局：

- 页数/最后一行满足项目合同；
- 标题、作者、通信作者、邮箱、匿名模式正确；
- 图表均在最终尺寸可读；
- 参考文献双栏/末页平衡；
- 无 undefined citation/reference、overfull、异常空栏或强制分页造成的大空白；
- 不用 filler、重复句、弱引用或缩小到不可读来填页。

## 交付记录

交付时给出：反馈总数、逐条 PASS/PARTIAL/BLOCKED 数、同类问题扫描结果、fresh build 身份、页数与最后行状态、逐页视觉 QA、引用质量变化和独立 reviewer 结论。
