# 数字与声称审查（防"未验证数字出门"）

> 本文件是 SKILL.md §2 步骤 4 的详细规则。这是 today 切换 bug 教训的直接产物——三轮简报把未验证的切换增益当真的报，是用户用物理直觉问出来的不是主线主动查的。

## 核心原则

**任何数字和"增益/改善/优于"声称，出门前必须过两关：**
1. **数字溯源**：这个数哪来的？怎么算的？验证过计算口径吗？
2. **声称边界**：这个增益相对什么？对照对象是真实 baseline 吗？来源是我们的方法还是固有性质？

**没过两关的数字 = 禁止写进对外输出。** 宁可写"增益待验证"，不可写一个没查过的具体数字。

## 关 1：数字溯源（每个数字必查）

对外输出里每个具体数字（+1.2 dB / 0.27 / 30 seed / 8.3e-6），写之前必须能回答：

| 溯源问题 | 不合格表现 |
|---|---|
| 这个数从哪个文件/实验来的？ | "我记得是 +1.2"——不知哪来的 |
| 怎么算的？计算公式/口径是什么？ | "切换增益 0.27dB"——不知是 BER 差转 dB 还是 SNR 平移 |
| 这个计算口径验证过吗（代码核查过吗）？| 数字直接从 JSON 读，没查 JSON 怎么生成的 |
| 有没有 bug 可能性？ | 代码没核查就当数字可信 |

**今天的教训（切换 bug）**：
- 简报写"切换增益 +0.27-0.48 dB"
- 数字来自 `_a4_switch_30seed.json` 的 `switch_vs_max_db` 字段
- **但这个字段怎么算的，三轮简报从没核查过**
- 用户质疑后读代码，发现：BER 用混合分母（DA 去导频位/NDA 含导频位）+ 对照是 max(DA,NDA) 事后诸葛亮
- **数字看似精确，实际基于 bug 代码**

**防护**：数字出门前，至少查一次"这个数怎么算的"。查 = 读生成这个数字的代码/脚本，确认计算口径合理。不查 = 不能用。

**溯源标记**：对外输出里重要数字，内部留底标来源（文件路径 + 字段 + 生成脚本）。导师档可不显示，但主线自己要有底。

## 关 2：增益声称边界（每个"优于 X"必查）

任何"增益 / 改善 / 优于 / 超越"声称，必须查三件事：

### 2a 对照对象是真实 baseline 吗？

| 对照对象 | 合格吗 |
|---|---|
| 固定导频 DA / 固定盲 NDA（真实方法）| ✅ 真实 baseline |
| 理想上界 oracle | ⚠️ 当上界参考可以，当"超越"的对象不行（理想不可达）|
| **max(DA, NDA) = 事后选更好的** | ❌ **不是任何真实方法，事后诸葛亮** |
| "传统方法"（不指名）| ❌ 太模糊，必须指名具体方法 |

**今天的教训**：切换增益报的对照是 max(DA,NDA)，等于"如果每块都事后选了更好的"——这不是任何实际方法能做到的。拿切换跟它比，等于让切换"既要判断对又要赢两边"，标准过严且对照不存在。**正确对照 = 固定一种（DA 或 NDA）**。

### 2b 增益来源是我们的方法还是固有性质？

| 来源 | 怎么声称 |
|---|---|
| 我们提出的方法带来的 | "我们方法相对 baseline 增益 +X dB" ✅ |
| 某估计器/模型的固有性质（我们只量化了）| "我们发现 X 相对 Y 有 +X dB 优势（已有性质，我们量化+归因）"——**不可说成"我们方法增益"** |
| 混合（部分固有部分方法）| 拆开报：固有 +X，方法独占 +Y。**不可把固有算进方法声称** |

**今天的教训**：净增益 +1.2dB 是盲估计（NDA-ML）相对导频（DA-ML）的**固有性质**，我们做了量化+归因。不能说成"我们的方法带来 +1.2dB"——除非"我们的方法"定义成"用了盲估计的完整方案"，且诚实标注来源。

### 2c 增益在哪些条件下成立？

| 合格 | 不合格 |
|---|---|
| "强湍流下 +1.2dB（弱湍流仅 +0.1dB 不显著）" | "+1.2dB"（不标条件）|
| "crossover 区（块信噪比 12-14dB）切换赢两边" | "切换赢 +0.27dB"（不标是哪个区，藏着低 SNR 区输）|

**今天的教训**：切换增益只报了 crossover 区的正值（+0.27-0.48），没报低 SNR 区的负值——cherry-picking。完整呈现 = 赢的区和输的区都说。

## 常见陷阱（这些情况数字看似对实际错）

1. **BER 分母不一致**：对比两种方法时，一个 BER 分母含导频位、一个不含——比较不公平。所有对比方法的 BER 必须统一口径。
2. **事后对照**：对照对象用到了结果信息（如 max/min 选优）= oracle 式，不是真实 baseline。
3. **单点 BER 差冒充 SNR 增益**："同 SNR 下 BER 差转 dB" ≠ "达到同 BER 的 SNR 差"。两者物理含义不同，不能混用"dB 增益"一词。
4. **条件性增益当无条件**：某方法只在特定区/条件下赢，报成"全程增益"。
5. **固有性质当方法贡献**：估计器/模型的固有优势，算进"我们提出的方法"名下。

**每报一个增益数字，自查这 5 个陷阱有没有踩。**

## 对外输出的数字标注规范

重要数字对外呈现时，标清三件事（至少内部底稿要有，导师档可精简）：

```
+1.2 dB 净增益
├─ 来源：盲估计（NDA-ML）相对导频（DA-ML），强湍流场景
├─ 计算：达到同 BER 所需 SNR 差，扣 1.25dB 导频开销
├─ 验证：30 seed 主实验，标准 BER 统一分母，代码核查通过
└─ 边界：弱湍流仅 +0.1dB 不显著；盲估计固有性质非我们方法独有
```

不能全标的，至少标"来源 + 验证状态"。验证状态 = "已核查" / "待验证" / "初步"。

## 与 sim-preflight 的关系

本文件管"数字对外怎么呈现"。sim-preflight C1-C8 管"数字本身扎不扎实"。

- 数字扎不扎实 → 先过 sim-preflight
- 数字对外怎么报（标什么/怎么标注/对照对象）→ 过本文件

两者顺序：实验跑完过 sim-preflight → 写对外输出过本 skill。跳 sim-preflight 直接写对外 = 数字可能本身就错（today 切换 bug 是实验代码错，本 skill 的溯源关能发现"没查过怎么算的"）。
