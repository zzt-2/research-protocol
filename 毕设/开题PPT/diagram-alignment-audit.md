#### 核心冲突：v5 "压缩前面展开后面" vs 当前结构

v5 设计理念：
- **上面（估计方法）精简**：只需 "LS / MMSE / KF / DL" 一行，不要每个方法的子步骤
- **下面（影响分析）展开**：E[1/h] 发散、调制差异、仿真验证等多个分析维度

当前结构：
- **上面展开**：3 行 × 4 列的详细方法子步骤（12 个框）
- **下面精简**：只有 "NMSE 评估" + "BER 灵敏度分析" + "精度设计准则"（3 个框）

**这恰恰与 v5 的设计意图相反。**

#### 选项分析

**选项 A：只改文字，不改结构**

- [4] "NMSE 评估" → "接收性能影响分析"
- [5] "BER 灵敏度分析" → "E[1/h] 发散 + 调制差异"
- [6] "精度设计准则" → "面向同步的精度设计准则"
- 3 行方法子步骤保留，口述时"快速过"方法部分

优点：用户不用重新调结构
缺点：图和文字规格不一致，口述节奏可能对不上（30 秒讲不完 12 个方法框）

**选项 B：调结构（压缩方法行，展开分析区）**

- 合并 3 行方法子步骤为 1 行精简块（4 个框 → 1 个框 "LS / MMSE / KF / DL"）
- 扩展分析区域：新增 3-4 个框（E[1/h]、调制差异、仿真验证等）

优点：与 v5 规格完全一致
缺点：需要重新调结构（用户说结构调了很久不想动）

**选项 C：折中 — 保持 3 行但隐藏子步骤细节**

- 方法名称行保留（LS / MMSE / KF），子步骤框的文字改为灰色/浅色或缩小
- 分析区在现有 3 个框内用多行文字填充
- 视觉上突出分析区，方法区弱化

优点：不大改结构但视觉上实现"压缩上面展开下面"
缺点：可能拥挤
