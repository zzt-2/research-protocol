## 1 范文验证铁律（铁律级）

> 来源：董凡/张思齐/吴志航/闫佳欣 4 篇范文交叉验证。不存在先例 = 禁止使用。

### 铁律 1：节首第一句直接切入，禁止跨节回指

| 类型 | 示例 | 判定 |
|------|------|------|
| 违反 | "上节建立了接收信号模型""前文分别介绍了""如§1.2.2所述" | ❌ |
| 正确 | 直接切入（下定义/引框图/说动机/陈述问题） | ✅ |
| 例外 | 段内可用"上述"指代同段前文（如"上述非理想因素"） | ✅ |

**允许的递进词**："接下来""下面""在此基础上""为此""据此"。

### 铁律 2：已定义符号直接使用，禁止括号节码注释

| 类型 | 示例 | 判定 |
|------|------|------|
| 违反 | "（定义见§2.2.3）""即前文定义的""注意此处与§X.X不同" | ❌ |
| 正确 | 符号定义过一次后全文直接使用 | ✅ |
| 冲突处理 | 高风险符号冲突（如 γ 同时表示衰减系数和 SNR）通过改用不同符号解决，而非加注释 | |

### 铁律 3：参数解释统一"式中/其中"格式

| 用法 | 正确性 |
|------|--------|
| 首处："式中，A 为...，B 为..." | ✅ |
| 次处："其中，C 为...，D 为..." | ✅ |
| 三处："进一步，E 为..." | ✅ |
| 连续三处以"式中"开头 | ❌ |

**变体**（可穿插使用）："该式表明...""其中各参数含义如下""将上式代入..."

### 铁律 4：符号重用通过上下文区分，不显式声明

| 类型 | 示例 | 判定 |
|------|------|------|
| 违反 | "注意此处 α 与§2.3 中含义不同" | ❌ |
| 正确 | α/β 在不同章节有不同含义时直接使用 | ✅ |
| 前提 | 首次定义必须足够清晰，让上下文能区分 | |

## 2 动词强度控制（规则级）

### 2.1 核心原则

动词强度必须匹配内容性质。过强动词是审查最高频问题（Ch2 中占 50%）。

### 2.2 动词强度对照表

| 内容性质 | 禁用动词 | 应使用 | 原因 |
|---------|---------|--------|------|
| 引用现有模型 | 建立/提出 | 介绍/分析/给出 | GG/QPSK/相干检测等非本文原创 |
| 引用现有推导 | 推导 | 介绍 | 非本文首次推导的公式 |
| 仿真对比结果 | 揭示/确定/发现 | 分析/验证/表明 | 仿真不是发现/确定 |
| 性能对比 | 最优/最佳 | 较为稳健/较好 | 不提前宣称最优 |
| 描述已有模型能力 | 实现了 | 能够实现 | 区分"已完成"和"具备能力" |
| Ch5 FPGA（未开发） | 完成/实现 | 进行/设计分析 | FPGA 尚未开发 |
| 未验证指标 | 实现/验证 | 预期/规划 | 不能承诺未验证内容 |
| 参数计算 | 确定 | 推导/分析 | — |

### 2.3 概述段动词标准

章引言（§X.1）、章小结（§X.N）、§1.3 章节描述中的动词标准与正文一致。"§2.3 建立了...模型" → "§2.3 介绍了...模型"。

### 2.4 程度词控制

| 条件 | 规则 |
|------|------|
| 有定量数据支撑 | 允许"提高 X dB""下降 Y %" |
| 无定量数据 | 禁止"显著提高""大幅下降""远高于"，改用"提高""下降""高于" |
| 仿真结果 | "表明""验证"而非"证明""确定" |

### 2.5 AI 痕迹判定标准

> 来源：批注 16/32/34/48 + R011 §7-§8

以下 5 类 AI 痕迹，出现即判定为机器语言，必须改写：

| 类型 | 判定特征 | 典型示例 |
|------|---------|---------|
| 翻译腔 | "使/被"高频（≥3次/段）、"通过...实现...的目的"、被动语态堆叠 | "上述风险分析表明，即使最不利情形发生..." |
| 清单体 | 逐篇罗列无分析、每段结构相同（"A提出了X，B提出了Y"） | 综述段逐篇平铺，无递进/对比/分组 |
| 元叙述 | "本节将""下面从...分析""以下按...梳理" | "以下按方法演进的脉络，依次分析..." |
| 数据堆砌 | "经系统调研""通过深入分析"等无实质信息套话 | 散布全文的空泛修饰语 |
| 平行罗列 | 三个以上并列项结构完全相同，缺乏递进/对比关系 | 三个方向逐条平铺，无分析递进 |

**判定方法**：全文搜索"使""被""本节将""以下按""经系统"，命中处逐个检查是否属于上述类型。每段"使/被"各≤3次。

### 2.6 防御性补丁句控制（规则级）

> 来源：2026-09-05 用户原话"不要有过多防御性句子……写论文不是让你写不能 xxx、不表示 xxx……没必要这打下补丁那打下补丁，没人会这么写"+ 范文量化对照（夏兆宇全文约 0.4 处/万字，本稿曾达 6—21 处/万字）。

否定句三分法，逐处判定后处置：

| 类型 | 特征 | 示例 | 处置 |
|------|------|------|------|
| A 技术否定句 | 陈述物理/数学事实或建模约束，承载实质信息 | "功率增益不能直接作为场幅系数使用" | 保留，但一句说完，不追加免责 |
| B 防御补丁句 | 紧跟自己结论后的免责/自我设限 | "不能据此确定普遍最优的导频长度""不表示理论最优阈值""不能据此宣称…" | 禁止散布。改写为直接陈述确定了什么、是什么；普遍性限制交给 C 的集中边界句 |
| C 边界声明句 | 限定结论适用范围 | "方法结论限于当前调制格式与三档湍流场景" | 合法，但每章至多 1—2 处，只落在该章边界段（如 3.6.3、4.7）或小结末句；引言、正文段中不出现，同一边界全稿不重复声明 |

**检查方法**：grep "不能据此｜不表示｜不外推｜不宜概括｜不能据此宣称｜不意味着"，逐处判 A/B/C；再数每章 C 类落点是否超出配额。**同一边界在引言、正文、小结多处重申 = 违规，保留一处即可。**

### 2.7 连接词密度控制（规则级）

> 来源：2026-09-05 用户原话"有没有使用致死量的连接词……希望靠句间语义自然地链接"+ 范文量化对照（夏兆宇全文约 13 处/万字，本稿方法章曾达 23—27 处/万字）。

- **密度上限：16 处/万字**（词表：然而/为此/因此/在此基础上/随后/进而/由此可见/同时/此外/然后/与此同时/值得注意的是/进一步/首先/其次/最后）。范文基准约 13。
- **超标主源**：①分节预告链"首先—随后—在此基础上—最后"连排；②段间"为此/因此/由此可见"粘合；③句内逻辑已在语义里、连接词只是复读。
- **减量原则**：删掉后句序语义仍自明 → 删；顺序靠内容表达（步骤时序、因果内嵌在句义中）；分节预告链最多保留首尾两个路标。拿不准读出声判定。
- **检查方法**：固定词表 grep 计数 ÷ 全文字符 ×10000，逐章报告。

## 3 措辞禁忌清单（规则级）

### 3.1 绝对禁止

| 禁止 | 处理方式 |
|------|---------|
| "首次""填补空白""oracle CSI" | 删除或改为审慎表述 |
| "尚未建立""尚未研究""尚属空白""尚缺乏讨论""缺乏系统研究""缺乏系统性研究" | 改为"尚不完善""仍不充分""研究仍有限"等非绝对表述 |
| 反问句 | 改为陈述句 |
| 括号内章节号 | 删除 |
| 引用放在句中 | 引用必须放在句末句号前 |
| 破折号（——） | 用冒号、逗号或拆句替代 |
| 正文加粗（`**text**`） | 全文正文不使用加粗；四级以下标题用序号（`（1）（2）（3）`）+ 换行，不用加粗 |
| `---` 分隔符（pandoc 误读为 setext 标题） | 不使用 `---` 作段落间分隔；章节标题已提供视觉分隔 |
| 泛话套语（"协同推进""推动发展""具有重要意义"） | 删除，替换为具体动作或数据 |
| 空洞递进（"不断深入""积极探索""持续优化""全面提升"） | 删除，替换为具体进展描述 |
| 泛化趋势（"日益增长""日趋完善""广泛认可"） | 删除，替换为定量事实或具体引用 |

### 3.2 降级映射

| 禁止 | 应使用 |
|------|--------|
| 显著鸿沟 | 仍存在较大差距 |
| 目前唯一 | 为数不多的...之一 |
| 最系统的 | 较为系统的...之一 |
| 标杆方案 | 具有代表性的方案 |
| 仍为空白 | 有待探索 |
| 均缺乏 | 尚不充分 |
| 尚未建立/尚未研究（已有初步工作的领域） | 尚不完善/研究仍有限 |
| 尚属空白 | 仍不完善/有待发展 |
| 尚缺乏讨论 | 讨论较少/仍较为有限 |
| 缺乏系统性研究 | 系统性研究仍不充分 |
| 无法直接迁移 | 难以直接迁移 |
| 直接决定 | 直接影响 |
| 突破了 | 有效缓解了 |
| 证明 | 表明/验证了 |
| 据作者所知/据文献检索 | 直接陈述，保留审慎限定词 |
| 如§X.X所述 | 用内容描述替代节号 |

### 3.3 文献综述自洽规则

总结段（"综合以上分析""上述研究表明"）中的缺口描述**不得与前文引用的文献贡献矛盾**。若前文已引用某方向的系统性工作，总结段不能对该方向使用绝对否定表述，应使用限定语缩小断言范围。

| 违反模式 | 正确做法 |
|---------|---------|
| 前文引了 Petković 的系统性框架，总结说"缺乏系统研究" | "未将信道估计误差纳入性能模型" |
| 前文引了 Han 的定量映射，总结说"尚未建立" | "尚不完善"或加限定"在信号处理模块级" |
| 前文引了 FPGA 验证文献，总结说"尚缺乏讨论" | "讨论仍较为有限" |

**判定方法**：写完总结段后，逐句检查其中每个否定断言是否与前文引用的论文贡献冲突。

### 3.4 缩写规则

- 所有缩写（FPGA/VV/BPS/DPLL/LS/MMSE/SNR/PDF 等）首次出现必须给出**中文全称+英文全称**
- 后续使用统一缩写，不混用
- 例："概率密度函数（Probability Density Function, PDF）"

## 4 术语规范（规则级）

> 完整术语表见 `TERMS.md`。以下是反复出错的易混淆术语。

| 禁止 | 应使用 | 原因 |
|------|--------|------|
| 信道增益 | 归一化辐照度 h | h 是实值辐照度，非射频含义 |
| VV 平滑窗口 | VV 平均窗口长度 M | VV 做算术平均非平滑 |
| 联合同步 | 级联载波同步链 | FOE→CPR 串行非联合 |
| GG（首次出现） | Gamma-Gamma | 首次出现不给缩写 |
| 线性调制 | 线性影响 | "调制"多义 |
| 确定性链路增益 | 确定性链路传输因子 | 避免"增益"歧义 |
| 大尺度分量/小尺度分量 | 大尺度 Gamma 分量/小尺度 Gamma 分量 | TERMS 规定 |
| 自适应（描述方法时） | 分析框架/设计方法 | 除非确实有自适应机制，否则不暗示适应性 |
| 揭示 | 分析/表明/验证 | 仿真不揭示机制 |
| 级联（描述本文分析框架时） | 影响分析/误差传播/对接收性能的影响 | "级联"仅用于描述已有方案的 FOE→CPR 串行架构，不用于本文贡献 |

## 5 结构规则（规则级）

### 5.1 质量维度

| 维度 | 含义 | 适用位置 |
|------|------|---------|
| D4 问题前置 | 每节/每段先陈述问题或动机，再给方法/分析 | 所有节 |
| D2 递进评价 | 文献/方法评价层层递进，不平行罗列 | 综述/文献评价段 |
| D1 落脚句 | 段末一句话落脚到具体结果/数据 | 辅助维度，不强求 |

### 5.2 段落结构

- 每段 3-8 句，控制节奏
- 公式密集段：每段不超过 2 个公式（范文同类推导拆为多段）
- 子节（§X.Y.Z）篇幅一般 3-5 段，主节（§X.Y）一般 5-8 段
- 段落结构不雷同：连续两段不能同为"定义→公式→参数解释"模式

### 5.3 节首写法

1. **直接切入**：下定义/引框图/说动机/陈述问题
2. **允许的过渡**："在此基础上""下面""为此"
3. **禁止的过渡**："上节...""前文...""如§X.X所述..."

### 5.4 节尾写法

- **本节总结**：概括本节给出了什么（"给出了...的闭合表达式"）
- **预告下一节**：只预告紧邻下一节，不跨章预告
- **禁止**：同时预告两个不同方向（如同时预告§2.3和第四章）
- **范式**："前节总结 → 剩余问题 → 预告后节"三段式

### 5.5 段内过渡句

段尾纯指路句删除。读者通过节标题和小标题即可导航，无需段末预告。

**禁止模式**（删除后半句或整句）：

| 模式 | 示例 | 处理 |
|------|------|------|
| "这正是…" | "这正是下一节要分析的核心问题" | 删整句 |
| "需要在后续…探讨" | "这一问题需要在后续分析中进一步探讨" | 删后半句 |
| "见下一节/下章" | "其数学推导和实验验证见下一节" | 删整句 |
| "下一节将…" | "下一节对选定方案进行 FPGA 设计分析" | 删整句或后半句 |
| "共同构成后续…的输入" | "共同构成后续载波同步方法分析的设计输入" | 删整句 |

**保留的过渡**：节首/章首的总领句（如"本节分析…"）属于结构必需，不在此列。

### 5.5 章引言（§X.1）写法

- 概述本章内容和目标
- 与上一章衔接（一句话递进，不回指）
- 分节预告："§X.2 介绍...§X.3 分析...§X.4 讨论..."

### 5.6 章小结（§X.N）写法

- **两段式**：第一段总结关键结论（含公式编号和定量锚点），第二段引出下一章
- **禁止**：(1)(2)(3) 机械列举式
- **递进信号**：用"首先...在此基础上...进而..."代替平铺

### 5.7 标题用词规范

> 来源：批注 7 "概况→现状"

| 上下文 | 推荐用词 | 禁止用词 |
|--------|---------|---------|
| 综述节标题 | "现状" | "概况""简介""概述""综述" |
| 方法节标题 | "分析"（除非含新方法） | "研究"（过度承诺） |
| 实验节标题 | "实验设计" | "实验验证"（暗示已完成） |
| 编号子节小标题 | 小标题后用冒号，如"（1）系统建模与分析：介绍…" | 小标题后用句号 |

## 6 物理约束（铁律级）

| 约束 | 正确 | 常见错误 |
|------|------|---------|
| h 含义 | 实值归一化辐照度，E[h]=1 | 复信道系数 |
| SNR 与 h 关系 | γ = γ̄·h（线性，非 h²） | γ ∝ h²（那是 IM/DD） |
| ω_n 单位 | rad/s | MHz |
| 旧方向内容 | 禁止出现 GNN/路由/切换/故障弹性/DRL | — |
| FPGA 状态 | 未开发，不承诺实现指标 | 声称"完成了 FPGA 实现" |

## 7 审查维度（规则级）

> 每节写完后按 R1-R8 全维度审查。以下为各维度核心检查项。

### R1 语言质量

- 段落结构是否雷同（连续两段同模式 = 问题）
- 句式是否单调（连续两句同结构 = 问题）
- 过渡是否公式化（机械衔接 = 问题）
- 是否有口语化表达（"这些""需要指出"→"上述""值得注意的是"）
- 是否有翻译腔（"占据支配地位"→"起主导作用"）

### R2 论断依据

- 每个判断是否有文献/公式/数据支撑
- 是否符合防御性写作（不承诺解决方法）
- "优于"/"显著改善"等断言是否有定量数据
- 所有数字是否有来源（引用或标注"本文仿真"）

### R3 技术常识

- 物理量纲是否正确（ω_n=rad/s、h 无量纲实值）
- 公式变量含义是否前后一致
- 数值是否在合理范围
- 公式描述是否准确（"解析表达式"vs"解析关系"vs"工程设计选择"；"推导"vs"引用"）
- 所有缩写首次出现是否给中文全称+英文全称

### R4 术语合规

- 逐句对照 TERMS.md
- 同义词混用（如"信道增益"vs"归一化辐照度"）

### R5 符号一致

- 数学符号是否与 symbol-conventions.md 一致
- 同一变量全文是否使用相同符号
- 上下标是否规范

### R6 禁忌内容

- 是否出现旧方向内容（GNN/路由/切换/故障弹性/DRL）
- 是否出现绝对禁止词（"首次""填补空白"）
- Ch4 是否绑定了具体算法声称新方法

### R7 图表公式

- 公式编号是否连续、是否与 section-outline.md 一致
- 图表编号是否与 figure-table-plan.md 一致
- LaTeX 是否正确（括号匹配、上下标、分数格式）
- 正文引用公式时编号是否正确
- 图题是否为简洁名词短语（≤15字），不含括号条件（如"SNR=20dB"），不含关系描述（如"XX对YY的影响"）；条件放图注或正文

### R8 动词强度

- 逐句扫描动词，对照 §2 动词强度表
- 重点：引用现有模型用"建立/提出"、仿真结果用"揭示"、性能用"最优"

## 8 反复犯错预防（铁律级）

> 以下问题在 S003/S004 纠正后，Ch2 写作中又重复出现。**每次审查修正时必须逐条对照**。

### 8.1 五条预防规则

1. **审查 agent 建议的句式改动，必须先在范文库中验证是否存在先例**，不能凭空创造
2. **括号内章节号**：审查 agent 可能建议加节号"帮助读者"，但范文没有这个写法
3. **回指句**：深度审查 agent 可能建议加回指"帮助衔接"，但范文用递进词不用回指
4. **过强动词**：正文内和概述段（§1.3/章引言/章小结）的动词标准必须一致
5. **绝对性措辞**：修改正文后必须同步检查辅助材料（映射表/脚注等）

### 8.2 根因模式

| 根因 | 表现 | 预防 |
|------|------|------|
| 不查范文就采纳 agent 建议 | "加过渡让读者更清楚" → 引入违规 | 建议 → grep 范文 → 命中才采纳 |
| 修一处顺手加括号节码 | "（见§X.Y）" | 改完后全文搜"（§"和"（见" |
| 修衔接时加回指 | "上节建立了..." | 改完后全文搜"上节""前文""前节" |
| 概述段动词标准与正文脱节 | §1.3"建立模型" + 正文"介绍模型" | 写完概述段单独做动词扫描 |
| 声称"已同步"但未实际验证 | "formulas 已更新" | 必须用 grep 验证，不能信任声称 |

### 8.3 文档同步验证纪律

修改符号/公式后，涉及同步的文件必须用 **grep 验证**，不能用"已执行"声称替代：

| 修改类型 | 需同步验证的文件 |
|---------|----------------|
| 正文公式 | formulas-master.md、formulas-index.md、对应 formulas-ch*.md、section-outline.md |
| 符号 | symbol-conventions.md、TERMS.md |
| 术语 | TERMS.md、cross-chapter-notes.md |
| 图表编号 | figure-table-plan.md |

**验证命令**：`grep "旧符号" 文件列表`，返回空才算完成。

### 8.4 不顺句识别规则

> 来源：批注 34 "请人工逐句理顺"

导师指出全文存在语句不通顺的问题。处理方式：
- 逐句扫描，**标记所有读起来不顺的句子**，列出原文 + 不顺原因
- 标记后交给用户逐句确认和修改，agent **不得自行改写**
- 判定"不顺"的标准：语序别扭、搭配不当、逻辑跳跃、冗余累赘

**重点关注：节首句和节尾句。** 这两个位置是读者注意力的关键锚点，必须经过大量打磨。给出修改建议时：
- 必须从**高层次**检查——结合本节目标、上下文逻辑、范文范式去推理该怎么写
- 必须结合写作质量规范的其他规则（动词强度、过渡方式、落脚句要求等）综合判断
- 不得只看单句语法就建议修改，必须理解该句在段落和章节中的功能

## 9 子 agent 建议验证流程（规则级）

> LLM 写作建议天然倾向"加过渡、加引用、加结构标记"，这些恰好是范文验证出的禁忌。

### 9.1 判定流程

```
子 agent 建议"加 X 让读者更清楚"
  ↓
在范文库中 grep 搜索该模式
  ↓
命中 → 可以采纳（注意不要照搬，理解意图后用自己的话）
未命中 → 拒绝该建议
```

### 9.2 常见误导建议

| agent 建议模式 | 实际判定 | 正确做法 |
|---------------|---------|---------|
| "加'（见§X.Y）'帮助读者定位" | 范文无此写法 | 拒绝 |
| "加'如前所述'帮助衔接" | 范文用递进词 | 改用"在此基础上" |
| "用'建立'显得学术性更强" | 过强动词 | 改用"介绍" |
| "加一段过渡段让结构更清晰" | 范文无多余过渡段 | 用一句递进词 |
| "加引用'据文献检索'增强说服力" | 范文不使用 | 直接陈述 |

## 12 开题报告特有规则（规则级）

### 12.1 动词时态一致性

创新之处（六）和预期成果（五）中，未完成研究统一使用"拟"前缀：

| 用法 | 正确性 |
|------|--------|
| "拟建立""拟分析""拟给出" | ✅ |
| "建立了""分析了""给出了" | ❌（暗示已完成，开题阶段研究未开展） |

**与正文 §1.4 的关系**：正文 §1.4 创新点使用完成时态（"给出了""分析了"）是描述创新点性质的声明式写法，可保留。开题报告的创新之处是承诺性写法，应统一用"拟"。

### 12.2 表格编号

表格标题必须包含编号，与正文引用一致：

| 类型 | 正确 | 错误 |
|------|------|------|
| 有编号 | `表 3-1 仿真参数体系` | `表 仿真参数体系` |
| 正文引用 | "如表 3-1 所示" | — |

### 12.3 对比句式引用例外

"与 A[@X]和 B[@Y]相比"句式中，引用跟随被引述对象是语义唯一合理的位置，不强制移至句末。

| 类型 | 判定 |
|------|------|
| "与 Han 等人...[@han2022jlt]和 Safi 等人...[@safi2019]相比" | ✅ 保留 |
| "VV 算法[@viterbi1983]利用..." | ❌ 引用移至句末 |

**判定标准**：当引用与人名/方案名紧密关联且在同一分句内无其他谓语时，允许句中引用。其余情况一律句末。

### 12.4 教学与科研区分标准

> 来源：批注 45 "3.6.3 和 3.6.4 属于学习教学，不属于科学研究"

实验方案必须满足以下全部核心判据：
- (1) **可证伪性**：每个实验必须有至少一个可证伪的假设——即存在某种可能的仿真结果能推翻该假设（Popper 划界标准）
- (2) **结果不确定性**：实验前结果必须不确定——如果完全可预测，就是演示不是研究

且至少满足以下之一：
- (3) 提出新的科学假设
- (4) 探索新的条件边界
- (5) 引入新的对比维度

以下类型属于"教学验证"，**删除不留**：
- 把前面的仿真结果再跑一遍确认（综合验证）
- 只有框架描述没有具体假设的"探索"（空壳探索）
- 重复已有方法的已知结果

> 补充依据：R001 调研（3 子 agent 并行，Popper 可证伪性 + Agent 1 八条自检 + Agent 3 写作技巧）

**实验方案改写纪律**（R001 PR-1~PR-6）：
- PR-1：定位为"条件-性能映射与工程决策指南"，不是"方法对比复现"
- PR-2：按研究问题分组，不按方法类型分组
- PR-3：每组开头三段式——研究问题 → 已知缺口（引用文献）→ 本组实验目标
- PR-4：每个实验用"条件-预测-判据"三要素写假设，禁止只写"对比X和Y"
- PR-5：级联效应分析是核心，在总述和分组中突出其地位
- PR-6：开题阶段给参数范围和理由，不给实现细节

### 12.5 表格学术性标准

> 来源：批注 42 "类似此表不属于学术论文范畴"

学术论文中的表格必须满足：
- 参数汇总表/规格表需附分析列（"对比分析""适用条件""本文选择"）
- 纯罗列无分析的对比表不属于学术论文范畴
- 不符合标准的表格 → 替换为**分点叙述**（保留信息量，去掉表格外壳）

### 12.6 研究方案写法（6 篇范文共识）

> 来源：P-003 AI 痕迹扫描 + 6 篇范文精读（夏兆宇/闫佳欣/曾嘉/管路阳/惠嘉欣/百佳骏）

**禁止**：编号列表罗列研究内容（"1. 建立... 2. 分析... 3. 研究... 4. 实现..."）

**应使用**：连续叙述，用逻辑递进连接（"本文针对X问题，先A，再B，最后C"）

| 写法 | 正确性 | 示例 |
|------|--------|------|
| 连续叙述，单段或两段 | ✅ | 管路阳：单段约390字，先问题再逐章说明 |
| 技术参数嵌入叙述流 | ✅ | 管路阳：研究方案中嵌入"[-B/8,+B/8]"等参数 |
| 编号列表逐条罗列 | ❌ | kaiti-report §3：四个层次"1...2...3...4..." |
| "首先...其次...进而...最后"四段式预告 | ❌ | 与编号列表同构 |

### 12.7 创新点写法（6 篇范文共识）

> 来源：同上

**禁止**：独立"创新之处"小节 + 平行编号罗列（"（1）...（2）...（3）..."），每条结构高度同质

**应使用**：

| 场景 | 写法 |
|------|------|
| 格式不要求列创新点 | 创新贡献嵌入总结/展望段落的自然陈述（"提出了...""推导了..."） |
| 开题报告格式要求列创新点 | 每条写成**含完整论证链的独立段落**（问题→方法→效果），差异化各条表述结构 |

| 写法 | 正确性 |
|------|--------|
| 每条含独立论证链，表述结构各异 | ✅ |
| "针对X，拟Y。与A和B相比，本文将Z"模板复制多条 | ❌ |
| "为...提供...依据"在多条中重复出现 | ❌ |

## 15 不顺句模式库（规则级）

> 来源：§3.6 实验方案 opus 逐句扫描（35 处），后续每轮审查补充。按模式分类，写完每节逐项检查。

### 15.1 搭配不当

| 禁止 | 应使用 | 原因 |
|------|--------|------|
| 经过…分析 | 分析… / 在…的基础上分析 | "经过"搭配过程不搭配名词短语 |
| 绘制…率 | 绘制…曲线并统计…率 | "绘制"搭配"曲线"，"率"需"统计" |
| 以导频为架构 | 采用导频方案 | 导频是信号结构，不是架构 |
| 分X的（如"分湍流条件的"） | 按X划分的 | "分X的"口语化 |
| 解耦…贡献 | 分离…各自的贡献 | "解耦"搭配系统/模块，不搭配"贡献" |
| 依次关闭噪声源 | 逐一排除噪声源 | "关闭"口语化，"排除"更学术 |
| 替换注入误差 | 代替注入误差 | "替换"暗示移除，"代替"暗示方案切换 |

### 15.2 语义断裂

| 模式 | 判定标准 | 处理方式 |
|------|---------|---------|
| 超长主语（>15字） | 主语到谓语之间超过 15 字 | 拆句，用"该X"重引主语 |
| 隐含主语切换 | 同句前后半句主语不同但未显式切换 | 补充主语或拆句 |
| 介词短语叠加 | 一句内两个以上"在…下""以…为" | 用逗号断句或拆为两句 |
| 名词四级堆叠 | 如"面向同步的估计精度设计准则" | 拆解为"适用于载波同步的估计精度设计准则"或更短 |

### 15.3 元语言/抽象化

| 禁止 | 应使用 | 原因 |
|------|--------|------|
| 将分析维度扩展到X | 将X纳入对比 / 引入X | "维度扩展"是元描述，不是实验内容 |
| 成为…独立维度 | 是影响…的独立因素 | "维度"是元概念 |
| 建立…设计准则 | 建立…设计准则（限三级嵌套） | 超过三级名词嵌套需拆解 |

### 15.4 数值与范围描述

| 禁止 | 应使用 | 原因 |
|------|--------|------|
| 0 至 -20 dB | -20 至 0 dB | 中文习惯从小到大 |
| 从无交织到 10 倍块衰落周期 | 范围为无交织至 10 倍块衰落周期 | "从状态到数值"不匹配 |
| 恢复至接近 AWGN 水平 | 恢复到接近 AWGN 时的水平 | "恢复至接近"双目标连用语意不清 |
| 统计稳定的性能估计 | 统计可靠的性能估计 | "统计稳定"非标准搭配 |

### 15.5 术语与句式规范

| 禁止 | 应使用 | 原因 |
|------|--------|------|
| 错误突发 | 突发错误 | burst error 是固定术语，不可倒装 |
| 越X越Y（口语） | Y随X增大而… | 学术写作不用"越…越…"句式 |
| 交叉点随湍流强度迁移 | 交叉点随湍流强度偏移/移动 | "迁移"用于大规模位移 |
| 进行迭代（施动者不清） | 形成迭代环路 | 明确迭代是环路行为 |
| 增加调制格式 | 引入调制格式 | "增加"像往集合加元素 |

### 15.6 体例一致性

| 检查项 | 标准 |
|--------|------|
| 并列项动作体例 | "标定/探索/验证/验证"→统一为不同动词 |
| 三段式对比句 | "在A已有…在B得到…但在C仍有限"→不超过两个"在…" |
| 实验标题体例 | 同组实验标题保持"方法+对象+目的"式命名 |
| 判据确定性 | 同组判据要么都有数值阈值，要么都用定性表述，不混用 |

## 16 公式排版规范（规则级）

> 来源：pandoc 管线实践，适用于所有含 display math（`$$...$$`）的 markdown 正文。

### 16.1 长公式必须用 `aligned` 防溢出

单行公式源码超过约 60 字符（含下标/上标/分数等 LaTeX 命令）时，可能在 15.4cm 文本宽度内溢出。必须用 `\begin{aligned}...\end{aligned}` 包裹。

**判定标准**（满足任一即用 `aligned`）：
- 含 `\frac{}{}` 且分子或分母超过 3 项
- 含 4 个以上 `\cdot` 连乘
- 含 `\sum`/`\int` + 复杂上下限 + 较长被积/被加表达式
- 两段式公式用 `\quad` 连接

### 16.2 `aligned` 对齐锚点规则

| 规则 | 正确 | 错误 |
|------|------|------|
| 对齐锚点 | `&=` — 在等号处对齐 | 不加 `&` |
| 续行运算符 | `&+` / `&\times` — 运算符紧跟 `&` | `&\quad +`（`\quad` 导致续行偏离等号） |
| 续行起首 | `\\` 换行后、`&` 前不留空格缩进 | `\\ \quad &+`（多余空白破坏对齐） |

**正确示例**：
```latex
$$
\begin{aligned}
\epsilon[n] &= \text{Re}\{...\} \cdot (...) \\
  &+ \text{Im}\{...\} \cdot (...)
\end{aligned}
$$
```

**错误示例**：
```latex
$$\epsilon[n] = \text{Re}\{...\} + \text{Im}\{...\}$$
```
（溢出，未拆行）

```latex
&\quad + \text{Im}\{...\}
```
（`\quad` 使 `+` 偏离 `=` 对齐位置）

### 16.3 断行位置选择

优先在以下位置断行（按优先级）：

1. **`=` 号处**：第二行用 `&=` 起首
2. **`+` / `-` 号处**：运算符留在第二行行首（`&+` / `&-`）
3. **`\times` 处**：同上
4. **避免在括号/分数内部断行**

### 16.4 两段式公式拆分

用 `\quad` 连接的两个独立表达式（如定义+分布），应拆为两行：

| 模式 | 正确 |
|------|------|
| `A = B, \quad C \sim D` | `\begin{aligned} A &= B, \\ C &\sim D \end{aligned}` |

### 16.5 不需要 `aligned` 的情况

以下情况保持单行 `$$...$$`，不包裹 `aligned`：
- 公式源码 ≤ 60 字符且无双行分数/长连乘
- 简单的赋值/定义（如 `h = X \cdot Y`）
- 单个分数且分子分母各 ≤ 2 项

### 16.6 编号规则

公式编号由后处理自动生成（`w:ptab` 绝对定位），markdown 中不写编号。`aligned` 多行公式的编号标在整体右侧，不逐行编号。
