# 增量方向扫描规则（4 种适配）

> 防止"锁死一个方法，在方法内部找增量，结果同族持平"的死循环。
> 触发证据：thesis-fso NDA-ML 方向 D-009，~9 个对话证算法层无增量（加权/segmented/高线宽/上行全堵死），根因是锁死 NDA-ML 内部找增量。

## 何时用

**跑 MVE / Contract 实验 / Execute 实验前**，如果目标是"找方法的增量优势"，必须先过一遍 4 种适配扫描。

不需要用的场景：
- 纯复现别人方法（不找增量）
- 纯参数调优（已知方法在已知场景的最优参数）
- 方向已选定且增量已验证（进 Execute 跑正式实验）

## 核心问题

> 在我们的场景下，任意参数条件下，某个方法是否存在优于另一个明确有力的 baseline 的区间，且能给出明确理由？

这是找增量的指导思想。**不要求方法全面更好，只要存在优势区间 + 有明确理由即可。**

## 4 种适配类型

每种适配有"扫描问题 + 信号判据 + 失败信号"。4 个维度全扫一遍，哪个出信号就追哪个。

### A1. 参数适配

**扫描问题**：方法的关键参数在新场景下，最优值是否随条件变化？

| 项 | 内容 |
|---|---|
| 信号判据 | 参数 X 的最优值在条件 C1 vs C2 下不同（如块长/窗长/环路带宽随湍流强度变）|
| 创新形态 | 自适应参数策略（根据可测量条件切换参数）|
| baseline | 固定参数版（最优单一参数但不适配）|
| 失败信号 | 最优值不随条件变 → 无自适应空间，跳过 |
| 典型例子 | VV 窗长 Nw：低线宽 Nw=64 好，高线宽 Nw=16 好 → 自适应 Nw |

### A2. 结构适配

**扫描问题**：方法从原场景搬到新场景，哪个结构组件需要调整？

| 项 | 内容 |
|---|---|
| 信号判据 | 原场景的结构假设在新场景下不成立（如频域→时域、块常数→逐符号跟踪）|
| 创新形态 | 结构调整 + 适配论证 |
| baseline | 原结构版（不做调整直接搬）|
| 失败信号 | 原结构在新场景直接适用 → 无调整空间，跳过 |
| 典型例子 | B11 频域 R(k)^M₀ → 时域 r(n)^M₀（D002 已做，不能重复卖）|

### A3. 组合适配

**扫描问题**：场景里不同族方法能不能组合？互补性在哪？

| 项 | 内容 |
|---|---|
| 信号判据 | 方法 A 的弱项 = 方法 B 的强项（互补）|
| 创新形态 | 混合方法（A 粗估 + B 精跟 / A 主 + B 辅）|
| baseline | 单一方法 A、单一方法 B（证明联合 > 分开）|
| 失败信号 | 两方法强项重叠（冗余非互补）→ 组合无增量，跳过 |
| 典型例子 | NDA 前馈无失锁 + DPLL 闭环高精度 → 混合 |

### A4. 条件适配

**扫描问题**：不同条件下方法间优势关系是否切换？切换判据可测量吗？

| 项 | 内容 |
|---|---|
| 信号判据 | 存在 crossover 点（条件 C 下 A 赢 B，条件 D 下 B 赢 A）|
| 创新形态 | 基于条件检测的方法/参数切换策略 |
| baseline | 单一方法全条件（不切换）|
| 失败信号 | 无 crossover（一个方法全条件赢）→ 无切换空间，跳过 |
| 典型例子 | 低 SNR DA 赢（pilot 可靠），高 SNR/强湍流 NDA 赢（pilot 崩溃）→ 切换 |

## 扫描流程

```
1. 列出场景里的所有可用方法（含我们的 + baseline + fellow）
2. 对每个方法列关键参数（A1）/ 结构假设（A2）/ 互补关系（A3）/ 优势关系（A4）
3. 逐维度扫描：
   - A1：参数最优值是否随条件变？（需扫描数据）
   - A2：结构假设在新场景成立吗？
   - A3：方法间有互补性吗？
   - A4：方法间有 crossover 吗？（需 BER vs 条件数据）
4. 出信号的维度 → 评估创新形态 + baseline 结构
5. 无信号的维度 → 标"跳过"继续
6. 全维度无信号 → 方法层无增量，考虑换方法或换场景
```

## baseline 结构规则（适配策略下）

**关键原则**：如果创新是"适配策略"（参数/方法切换），baseline 不是"另一个方法"，是**"不做适配的版本"**。

| 角色 | 是什么 | 为什么是 baseline |
|---|---|---|
| 我们的方法 | 自适应策略（参数/方法随条件切换）| 创新在策略 |
| **主 baseline** | 固定策略（最优单一参数/方法但不适配）| "不做适配"是最自然对照 |
| 参照线 | 不同族方法（架构对立）| 标尺 |
| fellow | 同族方法 | 定位 + 防御 |
| 上界 | oracle | 天花板 |

**老师"不找接近方法当 baseline"的满足**：比的是"有没有策略"，不是"方法谁强"。主 baseline 跟方法同族不同族无关——因为对照维度是策略，不是方法本身。

## 与 FR 规则的关系

- **FR-23（增量改进非填补空白）**：适配策略是"现有方法在条件 C 下优于 baseline"→ 转译成 M-C-A = "方法 M 在条件 C 下因策略 A 优于固定 baseline"✓
- **FR-25（Go/Kill 标准分离）**：Go 标准 = 适配策略 > 固定策略（赢 baseline）；Kill 标准 = 全条件无优势区间
- **FR-22（GW 门控）**：适配扫描在 Step 4a 维度 D / Contract 阶段做，不跳框架

## 防坑清单

- [ ] 没有锁死单一方法内部找增量（锁死 = 4 种适配只扫 A1 且只扫自己方法的参数）
- [ ] A1 扫描覆盖了**所有可用方法**的参数（不只自己的）
- [ ] A3 组合验证了**互补性**（不是冗余叠加）
- [ ] A4 crossover 确认是**物理因果**（不是噪声/seed 假阳性，TL-29 多 seed 验证）
- [ ] baseline 是"不做适配的版本"，不是弱方法
- [ ] 优势区间有**明确理由**（物理因果，不是"调参碰巧赢"）
