# 能力探测提示词（用户贴给 dot 的第一条消息，探测完再让它进长跑）

> 用法：整段复制给 dot。目的：在开跑前摸清它的真实能力边界（重点是文献检索），要求实测举证，不要口头自称。

---

探测任务：我打算让你在我的研究仓库上长时间自主跑探索性实验。你能拿到的资源是这台云服务器 + 一个 git 仓库。开始前我需要你的真实能力清单。**逐项实测举证**：每项给一个真实执行的小验证（命令/请求 + 实际输出摘录）；做不到就明确写"做不到"，这同样是有效答案。禁止口头宣称"应该可以"。

**1. 文献检索（重点，我怀疑你这块受限）**
- a) 能否访问公网？能否请求 arXiv API（export.arxiv.org/api/query）？
- b) 能否请求 Semantic Scholar API（api.semanticscholar.org）和 Crossref API（api.crossref.org/works/<DOI>）？
- c) 能否用通用搜索引擎检索？能否打开并读取任意网页？
- d) 能否下载 PDF 并读全文（试一篇 arXiv 论文）？能否读 HTML 版论文？
- e) IEEE / Springer 付费墙后的全文拿得到吗？
- f) 如果 a-e 大部分做不到：能否离线利用仓库内的文献库（`papers/` 目录，约 2 万篇带全文或摘要，索引在 `search-archive/_index/all-papers.jsonl`）做检索和占位判断？试一次：在索引里搜 "LDPC early termination"，报告命中数。

**2. 工程环境**
- python 版本？pip 能装包吗（装一个当前没有的包再卸载，贴输出）？
- numpy / scipy / torch / sionna==2.0.1 装得上吗？有没有 GPU（nvidia-smi 或等效）？内存/磁盘多大？

**3. git**
- 对我给你的仓库做一次真实 `git status` 和 `git pull`，贴输出。能 commit/push 吗？

**4. 长跑能力**
- 单次任务能连续执行多久？会话/进程中断后怎么恢复？
- 你能自主循环推进吗（比如每完成一轮自动开始下一轮），还是每轮都需要我手动触发？
- 有没有 token/时间/调用次数预算限制？一天大概能自主推进多少轮工作？

**5. 文件与记忆**
- 能持久写文件吗（写一个测试文件再读回，贴内容）？
- 跨会话的记忆机制是什么（靠文件？靠仓库？还是每次从头）？

**产出要求**：把结论整理成《能力清单》，格式：`能力项 | 实测结果 | 证据摘录 | 对长跑任务的影响`。如果仓库里有 `dot-lab/` 目录，把清单写到 `dot-lab/CAPABILITY.md` 并 commit；不能访问仓库就输出在对话里。最后用三句话总结：你最擅长干的三种活、最缺的三种活、建议我怎么用你。
